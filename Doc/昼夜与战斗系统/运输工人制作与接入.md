# 运输工人制作与接入

运输工人 `transport_worker` 表现现有资源供给连接。施工建筑的本期材料在工人生成时从正常库存预扣，送达后首次卸货显示材料飘字；若回合结束仍未送达，结算时确认这笔费用，工人继续完成送货。维修、维护和生产仍由回合结算支付。工人属于平民，不注册为士兵或敌军。

## 游戏行为

1. 白天黎明过渡结束后，系统检查需要物资的建筑及其资源提供点，例如皇宫、市场到生产或施工建筑。每个连接中的需求建筑至多对应一个工人，男女模型交替，数量不超过现有人口。
2. 工人在提供点的可行走出口出现，手中已有灰盒物资，沿现有地表导航前往需求建筑外围。
3. 到达后播放卸货动作，隐藏灰盒，空手返回原出口；每回合只派送一次，抵达起点后休息。
4. 入夜准备开始时停止新任务。尚未送达的施工工人在结算确认材料消耗后继续走到目的地、卸货，再返回原出口；其他工人从当前位置返回原出口。只有抵达起点后才隐藏。
5. 归途仍可被普通敌军发现和攻击。生命耗尽时播放死亡动作；送达前且尚未确认扣费的施工材料掉落地图，可点击拾取。阶段结束确认扣费后死亡不再掉落该批材料。人口只减少一次，不计作士兵死亡或敌军击杀奖励。狼继续遵守只追击士兵的既定规则。
6. 暂停会冻结移动与装卸。工人的身份、模型、位置、路线、装卸状态和死亡记录随白天／入夜节点保存；读档和入夜结算重建会话时保留这些信息。

每个工人代表现有居民的运输活动，不另收招募费用、不重复占用建筑岗位。居民伤亡后沿用既有岗位协调规则，人口不足时释放普通岗位。安全回家不扣人口；同一天死亡不会立即补出另一个工人。

资源点失效或目的建筑被拆除、荒废时，当前工人结束任务并回家；下一天重新根据当前连接安排。路线不可达时等待导航恢复，不穿越障碍或瞬移回家。该工人不会阻塞士兵归营及下一天流程。

工人出发后若新建筑挡住原交付点，会从当前位置重新选择可到达的需求建筑外围格；返程出口被挡时也会重选。同一地表的新建筑若直接覆盖工人所在格，先将工人移到附近可通行格，再清除旧路径重新寻路。跨阶段继续送达的施工材料不会因此重复扣费。

## 固定资源与首次创建

已接入正式世界模板，正常游戏无需手动在地图放置工人。首次制作入口为 **Landsong → 内容制作 → 创建运输工人**。重复执行保留已有预制体、动作与材质，补齐世界模板引用，不重置手工修改。

使用的原始模型：

- `Assets/polyperfect/Low Poly Ultimate Pack/_M/Prefabs_M/People_M/Rigs_M/使用/Man_Empire_Rig.prefab`
- `Assets/polyperfect/Low Poly Ultimate Pack/_M/Prefabs_M/People_M/Rigs_M/使用/Woman_Empire_Rig.prefab`

抱物、拿起和放下动作来自 `Assets/Landsong/Art/Animations/Kevin Iglesias/Human Animations/Animations/Female/Work/Carry/`；行走、普通待机、受击、死亡来自同套 Female 动作。两种模型通过各自 Humanoid Avatar 使用同一个控制器。

正式产物固定在：

```text
Assets/Landsong/ECSContent/
└─ Units/Worker/transport_worker/
   ├─ transport_worker_male.prefab
   ├─ transport_worker_female.prefab
   ├─ transport_worker_maleView.prefab
   ├─ transport_worker_femaleView.prefab
   ├─ Controllers/transport_worker.controller
   ├─ Clips/                      Idle、Walk、Carry、PickUp、Drop、Death、Hit
   ├─ Masks/CarryArms.mask
   ├─ Materials/                  男女蒙皮材质与 CargoGrey.mat
   └─ Preview/                    双模型动画预览场景
```

逻辑根只有动画 View 引用，出生时由 ECS 补齐平民身份、生命、导航和路线。View 的 `Model` 内保留 Animator、Rukhanka Rig 和蒙皮；`RightHand/CargoMount/CargoGreybox` 是物资挂点与灰盒。男女 View 是唯一正式外观编辑入口，创建器不再生成不会自动同步的模型副本。

## 后续修改步骤

### 调整工人数值

1. 打开 `Assets/Landsong/ECSContent/World/GameWorldTemplate.prefab`。
2. 找到 `TransportWorkerSettingsAuthoring`。
3. 修改生命值、行走速度、装货时间和卸货时间。当前初始值为生命 30、速度 1.6、装货约 1.13 秒、卸货约 1.33 秒。
4. 执行 **Landsong → 内容制作 → 同步运输工人到地图**。现有地图实体场景保存的是世界模板快照，同步只更新运输工人组件，不重新烘焙地形；新地图在生成时自动复制此配置。

### 修改模型或灰盒

1. 打开对应的 `transport_worker_maleView.prefab` 或 `transport_worker_femaleView.prefab`。
2. 替换 `Model` 时保留有效人形 Avatar，并配置 Rig：CPU、关闭 Root Motion、保留骨骼实体、关闭动画事件。
3. 在实际抱物姿势中调整 `CargoMount` 的局部位置和角度。修改 `CargoGreybox` 的尺寸或网格；挂点根保持单位缩放，显隐由运行时控制。
4. 确认 `TransportCargoAuthoring.Mount` 指向新挂点，`SoldierAnimationVisualAuthoring.Animator` 指向新 Animator。
5. 运行 **Landsong → 动画 → 预览运输工人**，检查男女模型的抱物、空手行走、装卸及倒地。

### 修改动画

直接编辑固定 Controller 和 Clips。Base 层播放行走、装卸、受击和死亡；Carry Arms 层只覆盖双臂，抱物时由运行时设置权重，腿部继续行走。`Handling` 为 0／1／2，分别表示普通动作／装货／卸货；通用的 `Speed`、`LocomotionRate`、`Dead`、`Hit` 等参数仍由单位动画系统驱动。

装卸时间由世界模板配置控制，灰盒在装卸过程的中点切换可见性。动画事件不结算库存、人口或伤害。调整动作时同步校准装卸时间。

## 验证入口

运行 **Landsong → ECS → Verification → Transport workers** 检查正式地图的资源连接、真实导航往返、暂停、存档恢复、敌军攻击和人口损失。全项目回归包含该套验证。

该验证还覆盖“先有外侧施工建筑与工人路线，再在旧交付格建内侧建筑，进入下一阶段”的交付点重选、返程点重选和工人所在格被新建筑覆盖后的恢复。

实际 Play 验证通过 `EcsEditorAutomation` 的 `VerifyTransportWorkerAnimationPlay` 执行。报告和六组双模型画面输出至 `Library/LandsongEcs/transport-worker-play.txt` 与 `worker-*.png`。该预览没有游戏会话，不修改王朝库存或人口，退出后恢复之前打开的场景。

2026-09-21 验收结果：工人玩法验证 37 项通过；实际 Play 动画验证 36 项通过，并检查了双模型六种动作画面；全项目回归 54 套、14,942 项断言，零失败（14:26 完成）。
