# 启动、加载与场景

场景承载世界资源，UI 承载应用与当前会话的展示。四个正式场景都通过 `ApplicationSceneEntry` 显式引用同一 `Assets/Landsong/UI/Prefabs/Bootstrap/UI_Root.prefab`。首次入口安装根，后续场景复用已登记的根；`UIManager.Initialize()` 校验 Canvas、分层容器、输入和注册表并调用 DontDestroyOnLoad。

## 场景职责

| 场景 | 职责 |
| --- | --- |
| `Assets/Landsong/Scenes/Boot.unity` | 注册 Boot 入口；应用流程打开 `UI_BootPanel`，等待其 SplashSeconds 后进菜单，默认 2 秒 |
| `Assets/Landsong/Scenes/Start.unity` | 注册 Menu 入口；应用流程打开 `UI_StartPanel` |
| `Assets/Landsong/Scenes/LoadingTransition.unity` | 卸载上一场景与承载切换期间的场景空壳；进度由常驻根上的 `UI_LoadingPanel` 显示 |
| `Assets/Landsong/Scenes/Game.unity` | 保存 `EcsGameHost`、世界相机、光源与各地图 SubScene 引用；不保存 UI 副本 |

Build Settings 启用以上四场景并按表中顺序排列。SubScene 通过 Game 的显式引用进入构建，不作为菜单入口。正常返回为 Game → LoadingTransition → Start，不重复开幕。从 Start 直接 Play 跳过开幕；直接运行 Game 或 LoadingTransition 会路由回菜单，不凭场景中残留状态自动创建一局。

唯一 Canvas、UIManager、EventSystem/InputSystemUIInputModule 来自常驻 UI 根，音频 `AudioRuntime` 与本地化 `LocalizationRuntime` 由根分别显式提供。AudioListener 由当前场景相机持有，随相机启停；Game 相机在地图准备完成前关闭，避免加载过程出现重复监听器。`EcsGameHost.SetVisible` 控制世界相机和光源。UI 根在地图未加载时已经能显示菜单、设置与错误信息。

## 应用层与展示层边界

`Scripts/Application/` 的 `ApplicationUiRoot`、`GameApplicationFlow`、`ApplicationSceneEntry` 和 `EcsGameHost` 属于 `Landsong.Application`。`GameApplicationFlow` 是场景/会话事务的唯一所有者，处理进行中标志、取消、阶段超时、释放与回退。

UI 位于 `Scripts/UI/` 的 `Landsong.UI`。菜单、存档和暂停视图通过共享契约 `IApplicationUi`、打开上下文及 `EcsSceneFlow` 提交意图，不自己加载场景。契约与路由门面在 `Scripts/Presentation/` 的 `Landsong.ECS.Presentation`，由应用层绑定实际流程，避免 UI 与 Application 循环引用。玩法模拟、恢复协议和费用/权限核验继续在核心层。

内容资产与烘焙位于 `Landsong.ECS.Authoring`，行为树接入位于 `Landsong.ECS.AI`，两者均单向引用共同的模拟/存档 Core。建筑视觉用途与槽位数据契约位于 Core 的 `Simulation/Contracts/`；GameObject 槽位与共享选择器位于 Content.Runtime，烘焙适配留在 Authoring。感知之后先执行 TacticalSlotSystem 分配接战位，再执行行为树，AI 程序集的排序边界再允许 Core 的 `CombatResolutionGroup` 更新；战斗、导航、弹道与伤害保留组内原有先后约束。核心不反向引用插件类型来排序。

固定引用必须提前配置：入口的 RootTemplate、Game 入口的 GameHost，以及宿主的 Catalog、Maps、Camera、Sun。缺失、重复或不一致直接报配置错误，不扫描当前场景寻找替代对象。ECS 数据查询用于判断地图与模拟状态，不用于修补 Unity 引用。

## 进入与结束游戏会话

新建或读取请求携带确定的地图 ID 与对应新局/存档数据。正式流程如下：

1. 打开共享 `UI_LoadingPanel`，保存取消回调并读取阶段超时配置。
2. 关闭 Confirm、Setting、Save，清除共享视图的会话上下文；解绑视听与世界表现、暂停和 Game UI。结束上一局 `UIScope`，取消其未完成 UI 操作并释放根/子视图。
3. 以 Single 加载 LoadingTransition，等待上一场景卸载，并确认 ECS 中不再有 `Session` 或 `SimulationOwner`。返回菜单请求到此即可加载 Start。
4. 以 Additive 加载 Game，取得该场景明确注册的 EcsGameHost。根据目录加载唯一选中的 SubScene，等待 SceneSystem 已加载、模拟根与 `SimulationReady`，再核对地图 ID。
5. 创建新王朝或恢复存档，等待一帧完成后续同步，并将相机定位到核心建筑。
6. 创建新游戏 `UIScope` 并加载 `UI_GamePanel`。显式绑定 EntityManager、会话根、相机、共享 Scaler/EventSystem，以及视听、世界表现和暂停服务。
7. 将 Game 设为活动场景，卸载 LoadingTransition；启用世界相机和光源，关闭加载面板，然后发布已进入游戏状态。

根面板的 Game 作用域不能省略；Start、Loading、Setting、Save、Confirm、Boot 使用应用作用域。返回菜单时会话 UI、Entity 引用、行缓存、拖动与放置状态均先清理，应用根和可缓存的共享面板继续存在。再次进入会建立新的游戏实例和绑定，不复用上一局的模拟对象。Game 的 GamePanelId 导航历史、GameUiRefreshScheduler 展示版本和条目交互状态也按会话重置；GameUiInputPolicy 读取显式绑定控制器的当前状态，不把旧模态开关复制到下一局。

## 请求与退出所有权

EcsSceneFlow.BeginAsync 返回当前切换 Task；CurrentTransition 可跟踪流程完成，TryBegin 在忙碌时返回 false。Task 正常完成也可能表示已取消或已恢复到菜单，是否进入游戏应读取 GameReady。已恢复的加载失败通过菜单说明和结构化日志报告；未被流程恢复的异步异常由路由统一清除 Busy / Pending 并记录 LastFailure。void UI 入口统一观察异常，不让请求静默丢失；同步拒绝不抹掉正在显示的游戏状态。ApplicationSceneCatalog 是四场景路径唯一来源，构建预处理校验 GUID 和启用顺序。

正常退出由 ApplicationUiRoot 先等待流程结束，再等待 UIManager.ShutdownAsync；UIManager.OnDestroy 只做同步取消和 lease 释放兜底。退出任务先让出执行权，确保 `Application.wantsToQuit` 回调已返回后再调用 `Application.Quit`，避免同步清理完成时的递归退出被 Unity 忽略。需要保留非零进程退出码的开发验证使用 `ApplicationUiRoot.Quit(int exitCode)`。

## 进度、取消与失败回退

进度值表示真实阶段已经推进，不伪造实体加载字节进度；等待 Entity Scene 或模拟准备时可停留在当前阶段。超时来自 `UI_LoadingPanel.TimeoutSeconds`，默认 120 秒，应用至少使用 10 秒。并发场景切换请求会被拒绝，不能在尚未结束的事务中启动第二局。

取消先清理当前会话与已加载 Game，再确认模拟所有权释放，随后返回 Start。Unity 原生场景 AsyncOperation 不能直接取消；已经提交的加载需等待完成后安全卸载。流程保留未完成操作清单，超时后的清理仍需先等待它们结束，不能仅清空托管变量就声称地图已释放。

加载异常先在可用的阻断层显示错误并执行同样清理。若加载面板自身创建失败，清理后直接尝试返回菜单；若此时清理失败，应用提供独立的重试入口。清理成功后提供返回菜单操作，用户返回时重新打开带错误说明的 Start。若清理本身超时或失败，`ApplicationCleanupRecovery` 保持新会话锁定，加载页显示具体原因与“重试清理并返回”。每次点击只排队一次重试，先等待未结束的原生操作、释放旧会话，再恢复菜单；重试或返回菜单再次失败时继续保持锁定。`CleanupDiagnostic` 保留完整异常供诊断，只有清理与菜单恢复均成功才解锁。正式存档的写入与备份恢复仍遵循 [运行时与存档](../运行时与存档/README.md) 的独立规则。

## 地图制作与验收

- `Assets/Landsong/GameMaps/`：公共 TWC 模板、公共地形规则和地图菜单目录。
- `GameMaps/<地图名>/<地图名>.unity`：唯一日常制图入口，保存初始建筑、地图规则区域及开局配置；TWC Blueprint Layers 中绘制边缘区。
- `<地图名>Data/Source/`：地图独立的 TWC 绘图源数据，必须保留。
- `<地图名>Data/Generated/`：烘焙配置、逻辑网格、运行 MapAsset 和实体子场景。
- 源场景 MapContentAuthoring 提供“初始化地图 / 校验地图 / 烘焙地图”。完整烘焙会实例化公共 `GameWorldTemplate.prefab`，添加当前地图的 `GameWorldMapAuthoring`，并自动同步地形、初始建筑与运行场景；按“加入地图菜单”设置维护菜单和 EcsGameHost.Maps 的同索引关系。
- 地图 ID 保持稳定，实体场景按 GUID 引用；SubScene 关闭 AutoLoadScene，仍由 Game 显式引用进入构建。初始化草稿不进入正式地图集合。

新建地图只需保存源场景、添加 MapContentAuthoring 并初始化；不需要手动创建 MapAsset、实体子场景或执行独立建筑同步。具体操作见 [地图系统](../地图系统/README.md)。

UI 制作改动保存到面板预制体及 Editor 预览配方，不能在四个场景中再放独立 Canvas 或设置/存档副本。引用与生命周期配置见 [UI 与输入](../UI与输入/README.md)，Game 内部所有权见 [Game 场景布局](../UI与输入/Game场景布局.md)。完成静态配置与架构检查后，实际验证 Boot、直接 Start、取消、失败回退、返回菜单和连续新局；各项执行结果以 [当前修复与验收记录](../ECS/问题修复记录20260917.md) 为准，不能用配置检查代替四场景 Play。
