# 表现层统一

状态：单位表现由各自逻辑 Prefab 声明；全局字符串模型目录已移除。

## 资源归属

`内容定义 → ECS 逻辑 Prefab → 该 Prefab 的表现引用` 是唯一入口。文件夹名称和稳定 ID 不参与运行时模型查找。

- 建筑定义引用完整 ECS Prefab，建筑模型与 `BuildingVisualSlot` 随 Prefab 烘焙。
- 正式动画单位在逻辑 Prefab 上配置 `SoldierAnimationAuthoring`，指向独立 Rukhanka View。出勤时创建、归营及死亡展示结束时释放。
- 暂无正式动画的 boss、raider、invader、titan 在逻辑 Prefab 上配置 `ActorVisualPrefabAuthoring`，指向独立的 `PresentationActor` View。该 View 由 `WorldPresentationView` 按实体生命周期创建与释放。invader 有独立逻辑 Prefab。
- `WorldPresentationView` 跳过带 `AnimatedUnitVisual` 的角色，防止重复模型。旧 `WorldVisualCatalog` 与 `LandsongWorldVisuals.asset` 已删除。

## 制作和验证

新增单位先创建内容定义，再制作单独的逻辑 Prefab 和 View Prefab。逻辑根须恰好选择一种表现入口；不得把 Renderer 或 Animator 放回逻辑根。正式骨骼动画使用 `SoldierAnimationAuthoring`；占位外观使用 `ActorVisualPrefabAuthoring`。检查器引用缺失应由制作人员修正，不通过运行时扫描推测。

`Landsong → 内容制作 → 校验正式制作内容` 检查定义、逻辑 Prefab 与 View。表现验证还检查特效目录及引用。出勤、归营、死亡、暂停、存档恢复和场景重载应保持唯一表现与正确释放；外观和粒子不得改变 ECS 权威数据。
