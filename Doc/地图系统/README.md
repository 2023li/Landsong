# 地图制作

地图制作与主项目的后续拆分、跨项目地图包和分阶段迁移计划见 [地图编辑器与主项目拆分执行方案](地图编辑器拆分执行方案.md)。当前暂不支持自定义地图或独立地图编辑器；本页描述主项目内已经启用的轻量场景与本地 Mesh 生成流程。

所有地图资源集中在 `Assets/Landsong/GameMaps/`。日常从每张地图的外层 `.unity` 场景制作，TWC 用于编辑，正式游戏加载生成的 MapAsset / Entity SubScene。

新制图规则见 [Layer 与 Blueprint 地形规则](Layer地形规则.md)：每个 Blueprint 只代表一种逻辑地形，Layer 唯一决定逻辑高度，分层 SO 配置跨层共用的地形映射，覆盖排序 SO 决定同层优先级。地图范围直接读取 TWC Settings 的宽高，边缘宽度在 MapContentAuthoring 配置。

桥梁、阶梯、桥下独立通行及额外导航地表的正式配置与验证，见 [建筑通行连接](建筑通行连接.md)。

## 资源组织

```text
GameMaps/
├── 分层模板_TWC配置.asset
├── 分层地形规则.asset
├── 地形覆盖排序.asset
├── MapMenuCatalog.asset
└── 地图名/
    ├── 地图名.unity
    └── 地图名Data/
        ├── Source/
        │   └── 地图名_TWC配置.asset
        └── Generated/
            ├── 地图名_烘焙配置.asset
            ├── 地图名_逻辑网格.asset
            ├── 地图名_Map.asset
            └── 地图名_Entities.unity

Assets/LandsongGenerated/             # Git 忽略，可完整删除并重建
└── GameMaps/地图ID/Meshes/
    └── Mesh_<稳定键>.asset
```

Source 中的 TWC 配置由工具首次复制，但会保存实际绘图成果，必须随轻量源场景一起提交版本控制。`GameMaps/*/Generated` 中的 MapAsset、逻辑网格、烘焙配置和轻量 Entity Scene 仍提交，用于保持 MapId、SubScene GUID 和现有加载契约；日常不直接编辑。体积最大的地形 Mesh 位于 `Assets/LandsongGenerated`，使用稳定 GUID，由 TWC 输入重建，不提交，也不能作为唯一制图来源。

保存后的地图源场景不包含 TWC 生成表现，Entity Scene 也不内嵌 Mesh。需要在编辑器观察地形时，点击 **生成临时地图预览**；预览对象仅存在于当前编辑会话，不写回场景。点击 **烘焙地图** 会更新逻辑资产和 Entity Scene，并把正式 Mesh 外置到本地生成目录。

分层 TWC 模板提供初始图层、生成参数和美术资源；分层地形规则定义地形枚举及建造、通行权限。模板不会自动覆盖已有地图。地图范围不依赖任何 base Blueprint，超出 Settings 宽高的逻辑格会被拒绝。

## 创建新地图

1. 在 `GameMaps/<地图名>/` 创建并保存 `<地图名>.unity`。
2. 创建一个地图根对象，添加 `MapContentAuthoring`，点击 **初始化地图**。
3. 工具补齐同对象上的 TWC Manager、独立 TWC 配置、Grid、初始建筑/地图规则区域容器、运行地图、实体子场景和输出引用。初始化不要求已有核心建筑；重复点击只补齐内容，不重置地图。
4. 在根检查器填写地图显示信息、开局参数，使用 **编辑 TWC 地形配置** 和 TWC 绘图工具制作地形。
5. 将正式建筑预制体拖入地图根的“初始建筑”下；初始化或校验地图时，会根据预制体的 `BuildingVisualAuthoring.Definition` 自动补齐 `InitialBuildingPreview`，默认初始等级为 1。已有绑定、等级和摆放位置会保留，也可手动配置预览组件。必须恰好有一座在初始等级启用了“是否王国核心”的建筑（例如王宫）；普通展示模型不按名字猜测建筑身份，目录外的模型不会自动加入开局。
6. 在 TWC **Settings** 设置宽和高，在 **MapContentAuthoring** 设置 **边缘（格）**（例如 `5`）。工具沿宽高矩形边界向内生成边缘，整个边缘不可建造，可通行且能到达城市的格子参与刷怪入场。点击 **检查地图范围与边缘** 可提前检查范围，无需手绘边缘图层。需要阻挡弹体时，在“地图规则区域”下添加 `MapProjectileRegionAuthoring`；后面的区域覆盖前面的区域。
7. 点击 **生成临时地图预览** 可从 TWC 输入恢复仅供本次编辑查看的地形表现；点击 **校验地图** 检查当前逻辑格、规则和建筑。修改生成器参数后可重新生成预览，或直接执行完整烘焙。
8. 点击 **烘焙地图**：工具等待 TWC 网格生成完成，烘焙逻辑格、吸附建筑、收集建筑和特殊规则，更新运行地图及实体子场景，把 Mesh 写入被 Git 忽略的 `Assets/LandsongGenerated`，再以不含生成表现的状态保存源场景。失败保留上次有效运行输出。
9. 烘焙成功后点击 **添加到地图菜单**，直接同步菜单条目和 Game 的地图子场景引用并保存，无需再次烘焙。按钮只使用已烘焙地图；重复点击更新名称、说明和缩略图，不重复添加。已移除“加入地图菜单”勾选框，菜单资产中的实际条目是唯一收录状态。后续烘焙保留已收录状态并更新资料；未收录地图不会因烘焙自动加入。需要下架时从 `MapMenuCatalog.asset` 删除条目，再烘焙同步游戏加载引用。初始化草稿不进入运行验收集合。

地图 ID 首次初始化生成后保持稳定。复制已初始化源场景再点击初始化时，工具分配独立 ID 和输出引用，并默认不加入菜单，避免覆盖原图。菜单已有条目顺序保留，新条目追加；修改菜单排序后需烘焙一次以同步 Game 宿主顺序。

## 编辑与验证

### DX12 设备崩溃恢复

2026-09-16，Map_Map01 完整烘焙并保存后，Unity 6000.3.5f2 的渲染线程报 `D3D12Fence::Wait / Device removal / 887a0006`，随后再次启动也出现同类故障。日志明确不是显存不足；这只能确定 DX12 设备失效，不能据此断定具体驱动或网格是根因。

用 DX11 重开后，源地图与已保存 MapAsset 校验通过，并再次完成 619 个初始建筑的完整烘焙。之后可从项目根运行 `powershell -ExecutionPolicy Bypass -File Tools/Open-UnityDX11.ps1`，或在 Unity Hub 为此项目添加 `-force-d3d11` 启动参数。此恢复方式只改变编辑器渲染后端，不修改游戏发行构建的 Graphics APIs。参数说明见 [Unity 官方编辑器命令行文档](https://docs.unity3d.com/cn/6000.0/Manual/EditorCommandLineArguments.html)。

此次日志与重烘焙前备份位于本机 `Library/LandsongEcs/CrashRecovery_20260916_2051/`，DX11 验证日志位于 `Library/LandsongEcs/recovery-dx11.log`。

### 地图美化

`MapContentAuthoring` 的 **地图美化** 折叠组集中配置和操作初始建筑：

- **填充默认树木与资源堆列表**：为尚未填写的列表加入内容目录中的 8 种树和小石堆、小土堆；列表引用建筑定义资产，由定义提供预制体、占地和地形限制。
- **生成树林**：每片独立抽取主树种，默认约占 80%，其他树种按权重混合。半径、片数、密度可调；树林边缘不规则且较疏，零散树与树林保持距离。只有一个树种时全部使用该树种，比例是随机期望值而非每片精确配额。
- **随机放置建筑**：每项指定建筑、数量和初始等级，在合法空格中随机放置。列表靠前的建筑优先占用空间；空间不足时报告实际数量。桥梁等连接建筑仍需手工摆放。
- **预览生成数量**：只在 Console 输出两个工具分别按当前地图规划的数量，不修改场景；它不是先生成树林再生成资源堆的联合预览。
- **清除全部**：移除初始建筑，包括手工王宫、树木、资源堆；不删除 TWC 地形或地图配置。
- **清除自动生成**：只移除本工具标记的内容，保留手工建筑。自动生成对象即使手工移动，仍保留其生成来源标记。

生成种子独立于游戏运行种子；相同种子、配置、地形和其他建筑占用产生相同结果。`限定 Layer=-1` 表示所有逻辑层，其他值只在对应层放置。建筑遵守允许/排除地形、全占地平整、边缘禁建、斜坡和 XZ 占用规则；模型高度不参与逻辑。生成使用当前 TWC 的逻辑格，修改 Blueprint 生成器参数后需先更新 TWC 结果。

重复生成只替换对应类别的旧结果，不叠加，保留另一类别和手工建筑；无有效结果或规划失败时保留旧结果。每次生成/清理都可用一次撤销恢复。生成后仍应 **校验地图 → 烘焙地图**，以检查核心数量和整体入场通路；局部放置合法不保证树林没有封住狭窄通道。仅清空列表并点击生成不会删除旧结果，应使用清理按钮。

网格为等尺寸世界 XZ 平面，原点、格尺寸、高度与地形标签必须一致。建筑占地必须存在、平整、可建、符合地形要求且无重叠。通行、建造与弹体阻挡彼此独立；规则以源场景为准，不再手改生成 MapAsset。

烘焙前关闭目标生成子场景；Game 若有未保存修改，先保存。实体子场景按 GUID 引用，包含唯一 `GameWorldTemplateAuthoring`、`GameContentSetAuthoring` 和 `GameWorldMapAuthoring`；Game 的地图 SubScene 关闭 AutoLoadScene，由会话流程选择加载。

本地生成目录缺失或输入哈希变化时，进入 Play 会先取消本次切换、生成运行 Mesh，再自动继续；Player Build 的预处理也执行相同检查。可用 **Landsong → 地图 → 生成全部运行地图** 主动刷新，或用 **清理并重建全部运行地图** 验证干净重建。后者只删除 `Assets/LandsongGenerated/GameMaps` 与 `Library` 中的生成清单，不删除 TWC 源、MapAsset、逻辑网格或 Entity Scene。正式提交不得包含 `Assets/LandsongGenerated`。

不再创建“出生区域”子对象，也不手工指定怪物出生点；每夜按建筑隐性范围动态选区，规则见 [动态刷怪](动态刷怪方案.md)。当前正式游戏地图为 Map_Map01；Map_NavigationLab、Map_TWCFlowLab 作为专项实验资源。领域回归使用隔离 World，地图制作回归使用临时副本，不修改正式地图来满足测试条件。

运行 `Landsong/ECS/Verification/Map authoring workflow` 检查初始化、复制隔离、首次烘焙、地形网格生成、菜单注册及失败保护；运行 `Runtime map artifacts` 检查 Git 忽略规则、场景体积、无内嵌 Mesh 及外置引用。完整验收使用 `Verification/Run all` 和 `Verify four-scene flow (Play)`，见 [验证工作流](../ECS/验证工作流.md)。

地图目录迁移后的实测结果与既有 UI/音频限制见 [资源迁移验收](资源迁移验收.md)。地图加载定向 Play 入口为 `Landsong/ECS/Verify map loading (Play)`，验证所有当前菜单地图及首张地图重复进入后的释放。
