# 多高度导航最小验证

场景：`Assets/Landsong/GameMaps/Map_NavigationLab/Map_NavigationLab.unity`。

这是独立技术实验，不在正式地图菜单中，不创建 ECS Session，也不走现有单层地图烘焙。它使用项目已具备的 `UnityEngine.AI` 运行时构建接口，无需新增导航包或 Cinemachine。

## 操作

从 Unity 菜单「Landsong → 地图验证 → 打开多高度导航实验」打开，点击 Play。

- 白天：按钮建造或拆除吊桥、阶梯；每次实际重新构建本实验 NavMesh。
- 夜间：禁止建造／拆除，三组 NavMeshAgent 实际沿计算出的路线往返。
- 青色：西高地到东高地，经过吊桥。
- 红色：谷底南北通道，从吊桥下方经过。
- 金色：谷底经过阶梯登上西高地。
- 模拟受损：桥、阶梯保持连通；实验中通行代价变为 3 倍，在结构上的移动速度降为 1/3。该数值是实验参数，不是正式道路配置。
- Q / E：按 90° 切换观察方向；滚轮缩放。

本实验相机只有演示旋转、缩放，没有实现本轮讨论的硬软边界、弹性回弹或边缘雾。

## 几何与来源

地图宽 32、深 28，TWC 单格 0.5；谷底顶部 0.35，东西高地和桥面顶部 5.15。桥长 8、宽 2，桥下独立净空约 4.58。阶梯有 16 级，每级上升 0.30、前进 0.50，连接谷底与西高地。

`Map_NavigationLabData/Source/Map_NavigationLab_TWC配置.asset` 保存实际 BlueprintLayer 绘制数据，包括 Base、软范围占位、谷底、两座高地、桥面、16 个阶梯层。绘制位置与默认浮点高度均持久化；桥面与谷底在 XZ 上实际重叠。

本实验使用专用生成器，将这些填满的矩形蓝图层转换为场景中的 Box 几何；它不是 TWC Tiles Build 的美术验证，也没有接入正式地图的地形覆盖规则。生成器不将高度四舍五入。桥的木板和绳索仅作装饰，不进入导航烘焙；实际桥面由连续碰撞面提供。

正式多高度地图的通行面分类、land／water 覆盖、水上建造与交互拾取尚未实现。这里不添加 MapContentAuthoring，以免误用旧的单层烘焙丢失谷底或桥面。

材料和初始导航快照位于 `Data/Generated`。运行时按照当前结构重新构建导航，不依赖快照残留数据。直接调整场景导航几何后重新 Play 即可验证；蓝图编辑不会自动同步到已经生成的场景对象。

## 校验

Unity 菜单「Landsong → 地图验证 → 校验多高度导航实验」执行真实 NavMesh 查询：

- 同一 XZ 能分别采样谷底、桥面，中间空气不可采样。
- 桥上、桥下路径各自保持正确高度，阶梯连接高低端。
- 拆桥后桥面路径中断、桥下与阶梯保留；桥面无残留导航。
- 拆阶梯后高低地连接中断，桥上和桥下仍连通。
- 重建恢复路线；受损改变代价但不切断连接。

结果输出到 `Library/LandsongEcs/navigation-lab-verification.txt`。它是导航原型的独立校验，不代替项目完整回归。

2026-09-15 实测：17 项导航校验通过；进入 Play 后三组实际 NavMeshAgent 均到达终点，夜间拆除请求被拒绝。人工点击验证了受损、白天切换、拆桥及桥下通道保留。Play 结果记录在 `Library/LandsongEcs/navigation-lab-play-verification.txt`，画面为 `Library/LandsongEcs/navigation-lab-play.png`。

## 后续集成边界

按钮控制的是本场景预设桥和阶梯的实际几何，不是正式建筑系统的自由放置、资源扣除、道路编辑、存档或 ECS 命令。碰撞体由原型直接转为 NavMeshBuildSource，小场景同步重建；性能和生产环境异步更新仍需另行验证。

当前探针使用 NavMeshAgent，正式单位使用 ECS，尚未迁移单位移动、敌人出生可达性、访客路径或建筑服务范围。尚未验证战斗分层、桥面禁止再建造、动态建筑净空与端点校验。导航避让在探针上关闭，避免将人群避让与本次通行面验证混在一起。
