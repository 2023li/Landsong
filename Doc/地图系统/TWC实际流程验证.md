# TWC 实际生成与显式连接验证

验证日期：2026-09-15，Unity 6000.3.5f2。场景：`Assets/Landsong/GameMaps/Map_TWCFlowLab/Map_TWCFlowLab.unity`。

## 结论

实际运行了 TWC 的 Blueprint 和 Tiles Build 流程，并使用官方 Green / GreenRamp 预设生成 Mesh 与 MeshCollider。导航直接消费生成的三角形，没有用方块代替斜坡。

- 生成、保存重开、重新导入配置、全量重新生成后的检查：173 项通过。
- 同一个横向接缝问题在四个阶段复现，记录为 4 项失败。不能宣称“所有 TWC 斜坡情况全部通过”。
- Play 下三个真实 NavMeshAgent 均完成往返：坡道上下、高架面、桥下地面。坡道脚部与真实碰撞面的最大高度误差为 0.0444 世界单位。
- 移除 Ramp override 后，上下地表不连通；添加独立显式连接后双向寻路成功；移除连接后再次断开；错误高度的连接端点被拒绝。

用户确认的方向是：**斜坡放置时建立地表连接，连接的存在不由显示模型的三角形决定。** 直接从模型烘焙斜坡通行只作为对照实验。

## 如何复现

Unity 菜单 `Landsong → 地图验证`：

1. `打开 TWC 实际斜坡验证`：打开场景，Play 后可观察三个探针往返，Q/E 旋转视角。
2. `重新生成当前 TWC 实验场景`：编辑 TWC 配置后执行原生生成并持久化合并 Mesh，然后手动保存场景。
3. `验证 TWC 生成、斜坡与保存重开`：先关闭实验场景，在其他场景执行。自动运行生成、重开、移除 Ramp 与显式连接的对照检查，恢复 Ramp 配置并保存实验结果；保留横向接缝失败报告。
4. `验证 TWC 实际单位上下坡 (Play)`：临时切换 Play 启动场景，自动检查往返和坡道贴地，结束后恢复原编辑场景与 Play 启动设置。

报告位于 `Library/LandsongEcs/twc-flow-verification.txt`、`twc-flow-play.txt`，采样明细为 `twc-flow-geometry.txt`，Play 截图为 `twc-flow-play.png`。Library 内容可重新生成，不作为地图源数据。

## 实际 TWC 输入

32×24、cellSize=1、固定种子714、Dual Grid、合并网格和 MeshCollider。

| Blueprint | 高度 | 用途 |
| --- | --- | --- |
| Base_谷底 | -0.15 | 下层地面 |
| land_坡顶 | 0.85 | 上层平台 |
| ramp_南入口 | 0.85 | 官方 GreenRamp 的 override 掩码 |
| bridge_高架通行面 | 2.85 | 与下层通道重叠的高架面 |

预设网格顶部自带 +0.5 偏移，所以实际表面高度为 0.35、1.35、3.35。不能直接把 Blueprint 高度等同于单位站立高度。

三个 Tiles Build 层生成了18个合并 Mesh。原生生成后的临时 Mesh 保存到场景 Data/Generated/Meshes，并同时用于渲染和碰撞，确保重开场景后引用存在。没有改写共享瓦片模型。

导航参数：radius=0.15、height=1.1、climb=0.15、slope=48°、voxelSize=0.035。结论仅覆盖这些尺寸、预设和布局，不代表任意单位体型或任意瓦片均可通行。

## 横向接缝为何失败

在 z=6.9，单条坡道中央 y≈0.9303；整数 x 接缝处射线落到谷底 y=0.35，相邻倒角法线 y≈0.20。这里存在真实凹槽/陡面，无法视为连续宽坡面。沿各坡道的纵向上下坡仍然可行。

因此不应通过放宽高度吸附距离或增大爬阶能力来掩盖问题，这样可能错误连接悬崖或上下重叠地面。

## 显式连接实验的范围

`TwcLabConnection` 是独立的实验组件，保存入口、出口、通行宽度和双向标记。它不读取 Ramp 模型；端点以严格的小距离确认落在对应高度的已有导航面，再创建 NavMesh Link。

自动检查临时删除 Ramp override，通过 TWC 原生生成无坡道的平台和谷底，然后添加连接、查询双向完整路径、删除连接并确认路径断开。端点错误高度也有负例。检查结束恢复原始 Ramp override，不给正式地图添加连接。

**显式连接当前验证的是寻路连通性；上文 Play 贴地数据来自实际 Ramp 几何方案。尚未实现或验证显式连接的单位过渡动画、宽通道排队避让、批量单位吞吐。**

正式流程需要：

1. 斜坡/阶梯/桥梁定义自己的逻辑端口、所连接的地表身份、方向、宽度、单位通行限制及浮点高度轨迹。
2. TWC 地编或玩家放置时，从放置数据和旋转生成端口与轨迹；模型更换不改变连接存在性。
3. 端口必须连接到指定地表，桥上桥下不能仅凭 XZ 或“大范围就近吸附”互相串接。
4. 单位进入连接后按逻辑轨迹过渡；建造、旋转、拆除维护连接生命周期；损坏按已定规则影响效率。
5. 展示模型与轨迹需要对齐校验，但建模倒角、装饰凸起不应决定逻辑连通性。

后续正式 MapContentAuthoring / ECS 已接入多地表与显式连接，正式建造、存档和单位测试见 [建筑通行连接](建筑通行连接.md)。本页保留的是先前独立 NavMesh 实验的结果；其几何接缝问题和模型对齐仍需分别处理，相机软硬边界不在这些验证范围内。

`Map_NavigationLab` 是先前的独立导航原型，使用自定义生成几何；只有这里的 `Map_TWCFlowLab` 验证了 TWC 实际瓦片生成。
