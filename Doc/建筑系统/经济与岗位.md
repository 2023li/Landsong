# 经济、岗位与来源

## 白天结算

白天进入夜晚时结算，黎明才增加回合号。先协调人口并支付人才工资，再按稳定建筑 ID 逐栋处理维护 → 岗位/补贴 → 生产/收获 → 食谱/居住/税收 → 经验 → 英雄供奉。前栋产出可供后栋本次使用。

施工/修复每次推进一期，刚完成不参加该次生产/吃饭/税收。施工材料在运输工人生成时预扣；回合结束仍未送达时确认消耗，工人继续完成路线，确认后死亡不再掉落该批物资。没有生成运输工人时，沿用结算时直接支付。修复仍在结算时支付。全部建筑后结算市场、自然库存损耗、研究、王朝/远征/任务，再协调岗位与驻军。结算防重；入夜前后容量冲突会完整回滚，不留半次支付。

住宅从正常库存量降序选择食物，同量按物品 ID；跨组不重复，整份不足不部分扣。环境不足可阻止增长，但不返还已满足的食物；满员仍按周期收税。

## 账单与资源预测

建造/库存页的“账单记录”打开账单面板，按回合从早到晚排列五列表格：资源名、产出、消耗、净量、库存。建筑详情可筛选本建筑账单。实际收支从结算记录汇总，不从库存差值猜测：转库排除，税收和奖励计入产出，损耗与已确认入夜清空计入消耗。库存为各回合结算后的已入库数量；待存量另存于数据中。此账单覆盖白天结算及入夜清空，不包含白天手动建造、招募和完整夜战流水。

每次成功实际结算写入 ECS 历史，预测、失败事务不写入。v33 存档保留多回合账单和当时库存；开发期间只读取当前格式，不兼容或补算旧记录。

库存资源行显示当前可用已入库数量和本回合预计净增减；“详情”子面板左右分别列预计产出、预计消耗与来源。白天自动计算，正式状态指纹变化后旧预测失效，按当前条件刷新；预测不扣款、不推进回合、不改变随机数或历史。当前工人作为参考，随机作物收益、稀有产出、远征结果/抚恤和王室事件不计为确定净收入，手动操作与入夜待存区清空也不计入。

## 岗位

岗位改为直接设置每回合补贴预算，每次按箭头增减 1 份支付物品（默认金币），范围 0～岗位容量；按本轮约定左侧 < 增加、右侧 > 减少。预算不随自然吸引力变化自动重新定价。设置不立即招人、扣款或取消已经支付的效果，白天结算按预算整笔支付；资金不足保留预算但不给加成。

稳定人数为 floor(吸引力 × (岗位上限 + 1) / 100)，限制在容量内。每份补贴提供 100 / 岗位上限 吸引力，总值上限 100。白条为自然吸引力，黄色进度立即预览当前补贴预算带来的增量（总值上限 100），文字明确下次结算支付后生效，并另列当前已付补贴对应的实际吸引力；黄块按岗位比例分组，最多 10 个，组内岗位全部入驻时高亮，实际人数始终单独显示。只有实际支付才扩大当前招工额度；下一次岗位结算替换已付状态，荒废清除已付状态。`SetWorkforceTargetRequest` 表达按当前环境折算一次预算的显式操作，`SetWorkforceBudgetRequest` 直接设置预算；两者具有不同字段含义，详情使用后者。

单次招募 1 名工人，费用 ceil(配置招聘基础费 × (1 + (100 - 当前吸引力) / 100))。不使用未付预算或待存放，不复用士兵/英雄人口。价格改变拒绝旧请求。远征在途锁岗位/补贴。资金不足整笔补贴不支付，预算保留；自然招入/离职保持单次最多 1 人的概率与保护规则。

`BuildingWorkforceLevel` 通过 `Capacity/InitialWorkers/InitialSubsidy/BaseAttraction/RecruitmentCost` 明确岗位容量、初始工人、默认补贴、基础吸引力与招聘费；`Currency` 为 `ItemId`，未指定时使用 `CurrencySettings.Gold`。初始人数不是永久稳定人数。默认补贴开启时，创建建筑按配置基础吸引力计算达到满岗的最低预算，之后作为固定预算保存；玩家通过详情调整。

## 供给、修复和空间效果

资源提供点按有效条件、优先级、道路加权路径、稳定 ID 选择。选中建筑在地图显示实际路径；详情不列连接候选，供给受阻归入红色异常提示。提供点决定连接和市场流转归因，付款仍取全城正常库存。

修复确认冻结费用/回合；逐期优先待存放，正常部分才要求连接。缺料或断连整期不扣、不推进。详情显示总额、已付、尚需、下一期、两类来源和缺口；待存放支付不算市场流转，修复费不记入建造投资。

空间效果按完整占地曼哈顿格距判断，包含生产/作物、美观、医疗和治安；叠加值 10 相加、20 同类最高、0 同 Key 最高，同值按稳定 ID。精确目标不符、缺工或未运营不计。维护失败是否关闭效果依配置语义，不一概推断。

共享计算入口：WorkforceOps、BuildingCostOps.QuoteRepair、ResourceNetworkOps.Quote、SpatialOps.Quote。UI 和执行器使用同一结果，避免解释与扣费不一致。

## 工人档位侧栏

鼠标进入种植块，在详情左侧打开可滚动的工人档位说明；移入侧栏可继续滚动，离开后关闭，切换建筑或关闭详情时清除。档位来自建筑“岗位与补贴 → 工作效率档位”的显式人数区间，标记当前人数。配置包含建筑等级、最少和最多工人；不会按容量逐人生成，也不会从模块阈值反推档位。区间必须完整覆盖 0～岗位容量，允许合并效果相同的连续人数。未种植时展示本等级可选作物，种植后只展示当前作物。列出生长门槛、每次结算进度、基础随机收获区间和全周期奖励条件；本季已经失去全周期奖励时明确说明，补人不能补回本季奖励。

同一侧栏应用于岗位总览、基础产出中的工人功能、经验条、生产/稀有产出、空间效果、远征及神殿相关模块。内容覆盖加工周期和产出档位、仓储槽及缺工损耗倍率、空间作用、经验、资源提供点、任务容量、市场邀约冷却及神殿工人门槛。WorkerEfficiencyOps 统一读取烘焙档位及各能力的具名配置，UI 只请求并展示查询结果，不包含分档和效果判定分支。缺少档位时明确提示未配置，不自动补档。只读取当前配置和状态，不执行结算、不抽取随机数；展示的是人数条件下的基础能力，运营、维护、资源、容量和其他加成仍按正式规则结算。

## 结算服务

`DailyEconomySettlement.Settle` 是有序协调器，按上述顺序调用 `ConstructionSettlement`、`BuildingMaintenanceSettlement`、`WorkforceSettlement`、`BuildingProductionSettlement`、`ResidentialSettlement`、`BuildingExperienceSettlement`、`SanctumOffering` 与其它领域服务；没有 EconomyOps 全量入口。收获归 `CropHarvest`，人口与岗位重配归 `WorkforceSettlement`，派生吸引力解释仍由 `WorkforceOps.Quote` 提供。

岗位运行状态在 `BuildingWorkforceState`；住宅增长/税收在 `BuildingHousingState`；配方周期在 `BuildingProductionState`；作物与全周期奖励状态在 `BuildingFarmingState`。研究产出写 `ResearchState.Points`，全局随机状态只通过 `SimulationRandom` 消费，提取领域实现时不得改变随机调用次数或建筑顺序。
