# 远征

## 远征

界面可选择出发建筑、目的地、人数和每种补给。出发前共享 `ExpeditionOps.Quote` 预览当前工人、稳定岗位、可选范围、物资、成功率、奖励、伤亡及抚恤。派遣确认绑定本次人数/补给、库存和建筑状态；过期确认不得支付。

可派人数上限取当前工人、稳定岗位、驻地上限、目的地上限的最小值。每座驻地只允许一支在途队伍；已归来的待领取结果不占在途名额。人员来自驻地工人，不重复占人口。在途锁岗位、补贴、移动和升级。主动放弃或驻地荒废/拆除撤回队伍，物资不返还，不另计伤亡；已经归来的结果保留，不因建筑拆除丢失奖励。

在“功能配置 → 远征补给 → 远征补给”直接选择物品，填写最低数量、额外数量上限、每份额外补给的成功率加成和奖励加成。额外上限为 0 时使用最低量的 50%，非 0 也不得超过 50%。最低补给不计算额外加成，最多 8 个不同补给项。英雄供奉费用单独位于“招募、唤醒与供奉”模块，不与远征补给共用编辑字段。

出发冻结人数、驻地等级/名称、供给、成功率、物品奖励加成、抚恤应付数。满 15 人的陆上远征所仍获得 +25% 物品奖励；额外补给加成相加。补给在出发时整份扣除，库存不足不部分出发。成功率不超过目的地上限，物品奖励向下取整；非物品授权不缩放。成功给驻地 1 经验，奖励手动领取；库存放不下时整份结果保留。

失败伤亡按 `RoundToInt` 比例，正比例至少 1 人，扣驻地工人与王朝实际人口；幸存者仍属驻地工人。抚恤扣抵达时的正常金币库存，能支付多少就支付多少。每缺 10 金币计 1 层（向上取整），默认每层全局岗位吸引力 −5，持续 5 回合，叠层并延长到期。**不再直接扣民意。** 结算状态防止重复扣伤亡、抚恤和经验，结果界面展示已付/应付及惩罚层数。

### 当前两个目的地

| 字段 | 近郊侦察 | 废弃要塞 |
| --- | --- | --- |
| 最低驻地等级 / 回合 / 人数 | 1 / 3 / 10～15 | 2 / 5 / 10～15 |
| 基础 / 每人 / 最高成功率 | 40% / 3% / 90% | 25% / 3.5% / 90% |
| 失败伤亡 / 基础及每人抚恤 | 20% / 5 + 1×人数 | 35% / 10 + 2×人数 |
| 基础物品奖励 | 原木 12、石头 8 | 原木 25、石头 20、泥土 15 |
| 重复 / 补给 | 可重复 / 无 | 可重复 / 无 |

在“解锁与显示条件”模块配置“显示前置”和“完成前置”。当前两个目的地未配置额外条件。可用补给通过隔离配置测试验证，不改变上述基准数值。

不可重复目的地按**每座出发建筑**保存完成历史，成功抵达立即记录，尚未领奖也不能再次派遣；领取、修复不会抹除记录，另一座驻地仍可完成该目的地。失败或主动放弃不算完成。不使用全局奖励授权代替驻地历史。

可指定一名符合条件的王室队长；队长不占工人名额，不能与出访重叠，普通远征失败不按工人伤亡率杀队长。人物规则见 [王室与人才](README.md)。出发冻结值与每驻地完成历史均保存，不以当前 UI 选择回算。

人物的“渴望一次远征”请求在出发时绑定真实队伍 ID，维持“远征中”状态；本人存活归来时才完成（成功或失败均可，领取奖励不影响完成时机）。从请求列表进入远征面板会预选该队长。主动放弃或驻地失效撤回不算完成，恢复待安排；队长死亡则取消请求。状态与队伍链接随快照恢复，重复结算不会再次完成或重复写纪事。
