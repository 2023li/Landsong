# 季节、天气与风：设计草案

状态：规则设计已收敛，已获授权进入接入；逐节进度与验证见[执行记录](季节与天气系统接入执行记录.md)。更新：2026-09-23。

本文记录已确认的玩法规则、首版可调数值、建议的代码接入位置和验证重点。占位美术和具体实现细节在开发时可调整，但不能改变已确认的玩法后果。

## 1. 已提出的需求

| 对象 | 需求 |
| --- | --- |
| 季节长度 | 春、秋各 30 回合；夏、冬各 20 回合。四季共 100 回合。 |
| 季节画面 | 春、夏、秋、冬各有不同的后处理滤镜。 |
| 春季 | 下雨概率更高；作物生长速度提高 20%。 |
| 夏、秋 | 暂无玩法效果设计；仍有各自的画面表现。 |
| 冬季 | 最新澄清：作物不停止生长，而是生长周期翻倍；按正常速度的 50% 积累进度。此规则覆盖最初“减缓 100%”的表述。 |
| 晴天 | 以当前白天的光照作为晴天基准。 |
| 雨天 | 分小雨、中雨、大雨；光照比晴天暗，粒子密度随雨量增加，三档均有雷击风险。雷击可能击中建筑或行人；建筑起火后按消防救援与阶段期限规则处理，逾期进入可修复的荒废状态。 |
| 雪天 | 所有道路移动阻力增加 30%。 |
| 风 | 世界中有风，现有树木随风力大小摇曳。 |

### 本轮已确认的补充规则

- 季节按回合推进；天气每天黎明确定，白天与夜晚保持同一种天气。
- 世界存在温度；新游戏从初始季节的基础温度开始，此后每天在前一天温度上随机升/降 **2～10°C**，幅度 2～10°C 对应抽样权重 **9、8、7、6、5、4、3、2、1**，小幅变化更常见。春秋升温概率各 50%，夏季 65%，冬季 35%；结果限制在当季上下限内。换季保留前一天温度，只裁剪到新季节范围，不重置为基础温度。温度在黎明确定后整回合固定。若当天原本抽中雨天且温度 **低于 0°C**，当天变为雪天；0°C 本身仍为雨天，雪天不打雷。
- 建筑起火后以“进入下一个游戏阶段”为默认截止点；阶段只按玩家可感知的 **白天 ↔ 夜晚** 计数，跳过结算、部署、撤退、战报等过渡 Phase。消防站对加权服务范围内的火灾自动派出消防员，消防员沿现有寻路前往起火建筑，**到达后才灭火**；仅有范围覆盖或已经出发都不算完成扑灭。消防员仍在路上时，火灾可跨阶段继续等待其到达。最后一名任务消防员因死亡、路径失效或原站失效而失败且无人接替时，在**当前白天/夜晚结束的下一次主要阶段切换**判定荒废；例如夜晚死亡则夜晚结束、进入下一白天时荒废。
- 起火期间建筑所有玩法功能暂停，不向邻近建筑蔓延。居民与库存保留但暂不可用，不提前计入损失；灭火后原样恢复，真正荒废时才执行现有居民、工人、库存等损失流程。
- 本轮范围包括消防建筑本身及其建造、覆盖、派员与灭火规则。
- 雷击只在可操作的白天发生。火灾默认在下一次白天/夜晚切换时结算；已派出的消防员仍在路上时，按在途救援规则延期。
- 雪天道路阻力 +30% 同时影响人物寻路和建筑加权服务范围。资源连接依赖后者，因此也会随之变化。
- 消防覆盖沿用现有建筑的加权服务范围，首版行动力预算 **30**，道路阻力越大覆盖越近；雪天道路阻力增加时，覆盖也会缩小。消防站正常运营且现有岗位有工人时自动派出消防员，不消耗水或物资；工人就是“值守”，不另设排班。每名在岗工人可同时负责一处火灾，站内按起火先后派员。消防员到达后灭火，之后返回原站；**返回后**释放对应工人的出勤名额。
- 同一处火灾同一时刻最多只有 1 名在途消防员；该任务失败后，其他合格消防站才可接手。不同火灾可由同站不同在岗工人同时处理。
- 消防站首版可调参数：占地 2×2、施工 2 回合、建造费 20 金币＋10 原木＋10 石头、岗位上限 4、消防员行走速度 1.6、加权行动力预算 30；首版不做建筑升级。原木在讨论中称作“木材”，此处采用项目物品资产的名称。
- 消防站蓝图由现有“建筑学”科技奖励解锁。
- 消防员在白天出勤和跨阶段继续救火时都可被敌对单位攻击；被杀死按岗位工人死亡处理，消防站失去 1 名工人，聚落失去 1 名人口，对应任务失败，可由其他消防站接手。
- 多座消防站都可接手同一火灾时，优先选加权路径代价最低的合格站；并列按稳定建筑 ID 决定。
- 首版可调的降水概率已确认：春/夏/秋/冬分别为 45%/25%/30%/35%；四季基础温度分别为 8/25/8/-5°C。原“每天独立 ±10/±5/±10/±8°C 抽样”已被逐日升降温规则取代。
- 每日晴/雨按当季概率独立抽取，不对连续相同天气设置保护或限制。
- 作物改用“生长值”判断成熟。每种作物有固定生长值门槛；农田每次有效白天结算在春季提供 1.2、夏秋提供 1、冬季提供 0.5 生长值，季节切换不重算或清零已积累值。生长周期 10 的作物在冬季经过 10 次有效结算后为 5/10；春季再按每次 1.2 增长，经过 5 次有效结算成熟。
- 冬季照常允许播种、手动收获和自动收获；换种、铲除、收获等结束旧作物的操作将其生长值归零，新作物从零开始。
- 农田 UI 显示成熟百分比、保留 1 位小数的已积累/所需生长值，以及按当前季节速度估算的剩余回合；说明换季后估算会变化。
- 风向和风力档位每天黎明抽取一次；风向在 0～360° 均匀抽取，无风/微风/中风/强风的首版可调概率为 **10%/45%/35%/10%**。无风时树木静止，其余档位以可调参数控制占位树木摆动；本轮风不增加玩法影响。
- 雨天主光以当前晴天光照为基准，首版小雨／中雨／大雨分别乘 **85%／75%／65%**，昼夜过渡继续生效；春夏秋冬先使用四份不同的占位 URP 后处理配置。
- 雪天主光沿用当前晴天光照；季节滤镜、昼夜过渡与雪粒子仍照常生效。
- 进入雨天回合时等概率抽取当回合落雷最大次数（1、2 或 3 次）。可操作的白天每隔随机 **60～120 秒**尝试打雷，直到回合结束；暂停时计时冻结。每次先判定：70% 只打雷、播放闪屏效果而不落雷；30% 实际落雷。只有实际落雷计入上限；达到落雷上限后仍继续纯闪屏打雷，提前结束回合则取消后续尝试。
- 实际落雷中，50% 击中地面，50% 击中单位或建筑；后者再以 50%/50% 选择建筑或可见友方单位。所选类别在当前画面没有有效目标，就改选另一类；两类都没有则改为落地面。落点限定在**当前游戏相机画面内**，不考虑 UI 遮挡。地面命中只有视觉和音效，不造成地形或周边伤害。
- 雷击行人只命中地图中可见的友方单位，包括运输工人、消防员、已出场士兵与英雄、友方访客；房屋内未实体化的居民不参与。命中后 99% 死亡；1% 存活并掉落“雷神殿蓝图”。幸存者保留身份和岗位，生命降至最低可存活值。本轮仅制作可获得、可建造的雷神殿占位建筑，功能暂不设计。已拥有其蓝图时，重复幸存事件暂给 1000 金币，作为后期可改的占位奖励。
- 雷神殿占位建筑首版为占地 2×2、施工 1 回合、最多 1 座、无岗位/产出/玩法效果、建造费暂为 0；模型使用占位资源。未来设计功能时再修订数值。
- 核心建筑（王宫/皇宫）不参与落雷目标抽取。重复幸存的 1000 金币如果库存放不下，进入现有待存放机制。
- 建筑目标只选当前正常运营、非核心的建筑；若没有有效建筑，就选屏内有效友方单位；若单位也没有，就击中屏内地面。
- 若相机画面没有可落点的地图，本次只播放闪屏，不产生落雷，也不消耗落雷次数。
- 本轮所有新增视觉资源先使用占位资源，之后由用户回填。音频优先复用项目已有资源；缺少的留空，不强行引入新素材。
- 开局为春季第 1 回合；HUD 显示季节日序、当前天气、温度和风力，建筑起火时突出显示剩余救援阶段。

### 火灾与消防员的阶段状态

| 当前状态 | 下一次白天/夜晚切换时 | 显示给玩家 |
| --- | --- | --- |
| 起火，尚无有效消防员接单 | 建筑荒废；此前新建消防站或补足岗位工人并成功派员可以改变结果。 | 距离荒废的阶段期限。 |
| 消防员正在前往火场 | 继续燃烧并暂停建筑功能；不因该次切换荒废，等待消防员抵达。 | 消防员在途，救援期限已延长。 |
| 最后一名消防员任务失败，暂无其他站接手 | 在失败所在的白天或夜晚结束时荒废；若阶段结束前其他站成功接手，则重新进入“在途”。 | 本阶段结束前须有新的救援任务。 |
| 消防员抵达 | 立即灭火、恢复建筑功能；消防员返站后释放该工人出勤名额。 | 火灾解除。 |

消防员在返程中死亡，仍按岗位工人死亡扣除人员；已经扑灭的火不会因此重新点燃。单处火灾同一时刻最多一个有效任务；多座站点选择加权路径代价最低者，并列按稳定建筑 ID 决定。

## 2. 项目现状与接入约束

- `GameClock.Turn` 是现有回合号；完成夜间后进入黎明时自增。当前阶段包括白天、白天结算、部署、夜晚、战报等。初始游戏在白天建立。
- 当前白天只推进 `DawnRemaining`，`GameClock.Time`/`PhaseTime` 在白天不持续计时。随机时刻雷击需要新增独立、可暂停和可保存的白天经过时间及待触发事件，不能直接复用夜晚计时器。
- 农田在白天结算时，工人满足条件后对 `BuildingFarmingState.Progress` 加 **1 个整数**，与作物的 `GrowthTurns` 比较并触发自动收获。春季的 1.2 倍增长不能直接用现有整数进度准确表示。
- 当前太阳与昼夜过渡由 `EcsGameHost` 和 `NightLightingController` 管理，晴天基准可以沿用现有白天主光。季节滤镜与雨天变暗需叠加在昼夜过渡上，避免各控制器互相覆盖。
- 路径图从格子及建筑的 `MovementCost` 派生；A* 图也使用该代价。建筑范围另有基于道路/占用代价的加权计算。雪天对“道路移动阻力”生效的层次会决定是否改变建筑服务范围和资源连接。
- 当前泥路定义的 `MovementCost` 为 5，普通空地导航代价为 1；雪天在现有道路代价上乘 1.3（泥路示例：5→6.5）。这也会缩小消防站的加权覆盖。接入时必须观察实际路线是否绕开道路；本轮先保留现有道路基础数值。
- 建筑已经有荒废、修复、拆除及核心建筑毁坏终局流程。当前未查到消防建筑定义；火灾与消防覆盖属于新增玩法，需要单独确定建筑、范围、时点和存档状态。
- 现有 `CurrencySettings.Gold` 是金币物品引用；1000 金币占位奖励可沿用现有物品奖励体系，库存满时进入待存放。
- 已找到项目内的雨声循环资源；按文件名与表现配置检索，未发现明确的雷击声资源。接入时再核实一次，若仍没有则音频槽留空。所有新增视觉先使用占位资源。
- 现有树木包含多个建筑预制体和实体视觉网格。摇曳方案需以它们的材质/渲染批次实测选择，不能假定每棵树都有独立可旋转的运行时 GameObject。
- 权威玩法状态在 ECS，存档为当前版本快照；季节、天气、起火等状态若影响规则，应能保存/读取与回放，不依赖粒子或灯光组件反推。

## 3. 已确认规则与实现边界

### 时间与抽取

每回合对应一个天气日。第 1 回合是春季第 1 日，随后春 30、夏 20、秋 30、冬 20，再循环。这样一年恰好 100 回合，季节由回合号稳定推导。初始天气与每次黎明的新天气按规则抽取一次；同一回合的白天和夜晚保持一致。雨雪粒子、光照及树木动画仅表现当前权威天气和风力。

存档、白天结算和夜间天气表现共用同一个权威天气状态。天气和雷击的随机数流应独立于经济预览，并保存当前抽取进度，避免读档或预览改变真实结果。

每天先确定世界温度，再按季节降水概率抽晴/雨；若当天温度低于 0°C，把抽中的雨转为雪。第 1 天直接使用春季基础温度，不额外抽每日变化。以后每天先将前一天温度裁剪到当前季节区间（换季时尤其重要），再抽升降方向和幅度并再次裁剪到该区间。天气与风分开：晴天也可能有风；风向与风力每天黎明抽一次，本轮只有视觉影响。

### 玩法效果

| 效果 | 规则 | 接入注意 |
| --- | --- | --- |
| 春季作物 +20% | 作物成熟门槛固定为定义中的生长值；有足够工人时，每次白天结算获得 1.2 生长值。跨季节保留累计值，不按当季重新换算已生长部分。换种、铲除或收获结束旧作物时清零。成熟超过门槛的值不结转到下一作物。 | UI 显示成熟百分比、1 位小数的生长值和按当前季节计算的剩余回合。 |
| 冬季作物周期翻倍 | 有足够工人时，每次白天结算积累 0.5 生长值；已有值不倒退。10 生长值作物在冬季经过 10 次有效结算达到 5，春季再经过 5 次有效结算达到至少 10。冬季照常允许播种和手动/自动收获。 | 换季后剩余回合提示会变化。 |
| 春季雨概率更高 | 按已确认的各季降水概率独立抽晴/雨；春季 45% 最高。低温时将已抽中的雨转成雪。不限制连续同种天气。 | 数值可按玩法平衡再调。 |
| 雨天变暗 | 在现有晴天昼夜太阳强度的结果上，小／中／大雨分别施加 0.85／0.75／0.65 系数，昼夜过渡照常进行；雪天沿用晴天主光亮度。 | 雨雪粒子及夜间表现的具体占位形式。 |
| 雪天道路 +30% | 对所有归类为道路的格子有效移动代价乘 1.3，包括荒废道路；坡道若属于道路类别也受影响。人物寻路与建筑加权服务范围共用该结果，资源连接和消防覆盖可能随之变化。 | 建筑范围跨界时的 UI 提示。 |
| 风吹树木 | 每天黎明均匀抽 0～360° 风向及四档风力，概率 10%/45%/35%/10%；无风时静止，其余档位由可调参数驱动树冠/枝叶摆动，树干保持相对稳定。本轮不影响玩法。 | 是否给所有 8 种树统一效果；静态合批/Entities Graphics 下的材质实现与性能预算。 |

### 雷击、火灾与消防

建议将“打雷事件”“落雷事件”“火灾状态”和“消防员任务”分开设计：候选时点先做 70% / 30% 判定；落雷才消耗当回合上限，随后做地面 50% / 目标 50% 判定，并在玩家当前视野内选落点。命中行人按 99% 死亡 / 1% 幸存与奖励处理；命中建筑则进入可见的起火状态，并记录截止时点。有效消防站按在岗人数生成消防员任务，消防员沿现有寻路到达建筑才灭火。若进入下一阶段时仍在途中，火灾继续等待；途中任务失败可由其他站接手。消防员灭火后返回原站，返回才释放岗位出勤名额。最终到期仍未获救，调用建筑的既有荒废流程。

| 单次打雷尝试的分支 | 条件概率 | 本回合落雷计数 |
| --- | ---: | --- |
| 只有屏幕闪光，无落点 | 70%；达到上限后为 100% | 不增加 |
| 落在当前相机画面内的地面 | 未达上限时 30% × 50% = 15% | +1；只有特效和音效 |
| 进入建筑/单位目标分支 | 未达上限时 30% × 50% = 15% | +1；目标类别各 50%，无目标时回退 |

上述 15% 是单次尝试的概率，不是每回合概率。目标分支若选中行人，才继续做 99% 死亡 / 1% 存活及蓝图奖励判定。

在当前相机内始终有建筑和友方单位、且尚未达到落雷上限的理想情况下，单次打雷尝试触发“行人幸存并得奖励”的概率是 `30% × 50% × 50% × 1% = 0.075%`。相机内没有单位、玩家较快结束白天或当天落雷上限较低时，实际概率更低；雷神殿将是非常稀有的建筑。该稀有度是否符合预期，需在数值验收时确认。

关键结算顺序与边界如下：

1. 雷击只在可操作的白天发生；时限按白天→夜晚→下一白天的主要阶段计数，不把结算、部署、撤退、战报算作新阶段。白天结束时先处理已到达消防员，再检查仍在燃烧的建筑。有在途消防员时允许火灾跨阶段等待其到达；若最后一名任务消防员失败且无人接手，在当前主要阶段结束的下一次切换判定荒废（夜晚失败→下一白天荒废）。无延期资格的火灾先转荒废，再做经济结算，避免同一阶段重复处理。
2. 已确定消防沿用建筑加权服务范围，首版行动力预算 30，雪天也会缩小覆盖；正常运营且有现有岗位工人时自动派出消防员，不另设值守岗位、不消耗水或物资。每名在岗工人同时负责一处火灾，按起火顺序派出；灭火只在消防员到达后发生，返回原站后释放名额。任务因死亡、路径失效或原站失效而失败，可由其他站重新派员；起火后新建消防站或招工时可参与后续派员，建议在条件变化时重查。
3. 行人目标限地图中可见的运输工人、消防员、已出场士兵与英雄、友方访客；未实体化居民不参与。命中后 99% 死亡，1% 存活并掉落雷神殿蓝图。雷神殿仅占位、无玩法功能；重复幸存暂给 1000 金币，库存满时进入待存放。
4. 雨天入回合从 1、2、3 中**等概率**确定当天落雷上限。白天每 60～120 秒随机间隔尝试；未达上限时，每次 70% 只闪屏、30% 落雷；后者再分 50% 地面、50% 单位/建筑，目标分支中建筑和可见友方单位各 50%，缺目标依次回退。核心建筑不会被选中。达到上限后只闪屏打雷；提前结束屏蔽剩余尝试。雪天不打雷。相机画面没有地图时只闪屏、不计数。
5. 建筑未获救后进入可修复的荒废状态。雷击只选正常运营的非核心建筑；没有这类建筑时回退到有效友方单位，再没有则落在地面。

建议用占位闪光、落点和起火特效及建筑警告，并让历史/战报记录损失原因。纯打雷分支只播放闪屏；实际落雷的音效若项目已有则复用，没有则留空。火灾的时限在 UI 中清楚显示。

### 已确认的首版可调天气与温度数值

| 季节 | 降水概率 | 基础温度 | 升温概率 | 季节温度上下限 |
| --- | ---: | ---: | ---: | --- |
| 春 | 45% | 8°C | 50% | -5～20°C |
| 夏 | 25% | 25°C | 65% | 15～35°C |
| 秋 | 30% | 8°C | 50% | -5～20°C |
| 冬 | 35% | -5°C | 35% | -15～5°C |

新游戏从初始季节的基础温度开始；以后每日按季节升/降概率，在前一天温度上变化 2～10°C，幅度 2～10°C 的权重依次为 9～1。换季不重置基础温度，先将前一天温度裁剪到新季节范围，再施加当天变化，结果再次裁剪。原草案“每日独立 ±10/±5/±10/±8°C 抽样”已废弃。春季的**降水概率**最高，但低温春日会把雨转为雪。

小／中／大雨主光 85%／75%／65%、雪天主光 100% 和每日风力四档概率 10%/45%/35%/10% 作为首版可调数值。风摆动画细节可以在当前档位内连续变化，但不能改变当天的权威风力档位。

## 4. 表现层建议

- 四季各用独立的 URP Volume 配置作为调色基准，在季节切换时平滑混合。雨、雪作为天气层叠加；昼夜仍控制太阳角度和亮度。效果应在晴天的现有白天画面上制作，避免改变基准曝光后误调所有季节。
- 雨雪粒子跟随相机的有效视野布置，并保留世界落点感；进入菜单、切换地图、暂停/读档时应正确恢复。实际粒子范围、密度和性能等级需要在 Game 场景验证。
- 雪天目前只要求道路阻力，地面积雪、屋顶覆雪、人物脚印等不纳入本轮默认实现。
- 风动画需要先用一种现有树型做技术样例，验证实体渲染、阴影与批处理，再扩展其余树型。风的视觉强度应与权威风力一致，但高频摆动可以只在表现层计算。
- 季节后处理、雨雪粒子、风摆、火焰、雷击视觉和雷神殿模型都先接占位资源；已有音效优先复用，缺少的音效引用留空，由用户后续回填正式美术和音频。

## 5. 接入方案

### 状态与结算边界

| 环节 | 执行方案草案 |
| --- | --- |
| 新游戏初始化 | 用当前回合号确定季节日序；第 1 天采用春季基础温度 8°C，再抽天气与风力。天气只在一个明确入口生成，防止重复抽取。 |
| 每次黎明 | 先让 `GameClock.Turn` 自增，再计算新季节；将前一天温度裁剪到新季节区间，抽本季升/降方向与 2～10°C 的幅度，再次裁剪到区间；随后判定天气，重建雨天落雷上限与下一尝试时点。日期 UI、滤镜、粒子和道路代价随后读取新状态。 |
| 白天经过时间 | 新增专用计时状态，只有可操作且未暂停的白天推进；每隔随机 60～120 秒处理一次。雨天上限 1、2、3 等概率抽取；未达落雷上限时，先做 70% 纯闪屏 / 30% 落雷判定，实际落雷才计数；达到上限后继续纯闪屏。保存下一尝试时点、已落雷次数及随机状态，读档不能重抽。 |
| 白天提前结束 | 未到时点的落雷候选全部作废；先结算正在燃烧的建筑，再继续原有白天经济结算和入夜流程。若经济预览复用候选世界，不得消耗真实世界随机序列。 |
| 消防判定 | 消防站使用现有建筑加权服务范围与道路代价，首版行动力预算 30，雪天覆盖会缩小。起火时和消防覆盖条件变化时检查可出勤消防站；按每名在岗工人最多一处火灾、先起火先派员。消防员沿现有寻路，到达后灭火，返回站点后释放名额。在途任务允许火灾跨阶段等待；最后一名任务消防员因死亡、路径或站点失效而失败且无人接手时，在当前白天/夜晚结束的切换判定荒废。死亡扣除 1 名岗位工人和 1 名人口。 |
| 雪天切换 | 对道路有效代价应用 1.3 倍；更新人物路径图、建筑加权范围及其依赖的资源连接，并使相关缓存失效。非雪天恢复基础代价，不改写建筑定义资产。 |
| 表现层 | ECS 状态决定季节、天气、温度、风和火灾；场景控制器统一混合昼夜太阳、天气暗度和季节 Volume。雨雪粒子、风摆、闪电与火焰是可重建的表现，不作为规则来源。 |
| 存读档 | 保存天气、温度、风、白天计时、落雷候选/随机状态、在燃建筑、消防员任务及必要的消防结果；读档恢复同一回合后不会重复落雷、重复奖励或跳过火灾截止。 |

当前白天的 `GameClock.Time` 不增加，不能用它来安排随机雷击。道路基础代价同时被多个系统读取，也不能只改 A* 图惩罚而遗漏建筑范围。接入时按当前快照开发版本更新存档结构；新旧版本兼容范围依照项目现行存档基准。

1. 以本文已确认规则和首版可调数值为准，准备消防站、雷神殿、消防员与天气表现的占位配置。
2. 增加权威季节/天气/风/火灾状态及配置，确定初始化、黎明切换、白天结算、阶段结束、存档和读档的先后顺序。
3. 将作物成熟度改为固定门槛的生长值，接入春季每回合 1.2、冬季 0.5、其他季节 1 的积累规则；更新种植说明、成熟度显示、经济预览和存档验证。
4. 接入雪天道路代价；分别验证行人路线和建筑范围/资源连接，按最终规则保持一致。
5. 接入季节后处理、雨雪粒子、天气光照与树木风动画，验证昼夜过渡和暂停/读档后的恢复。
6. 接入打雷、落雷、消防、火灾到期、雷神殿占位建筑、建筑后果与 UI/日志；最后用完整回合、跨季节、存读档及极端情况验收。

## 6. 接入时的验证重点

1. **跨季节作物**：10 生长值作物冬季 10 次有效结算得到 5.0，进入春季后 5 次结算成熟；工人不足不增长，播种/收获/换种清零旧值；经济预览不修改真实进度或随机状态。
2. **天气与存档**：春 30、夏 20、秋 30、冬 20 的边界准确；每日温度、晴雨、低温转雪、风与雷击上限在暂停/读档后不重抽；提前结束白天取消尚未发生的打雷尝试。
3. **道路与消防**：雪天所有道路类别代价增加 30%，人物导航、建筑服务范围、资源连接和消防站预算 30 的覆盖一致；现有泥路代价 5、普通空地代价 1，须实际观察路线是否违背道路设计预期。
4. **火灾与人员**：起火期间暂停功能且居民/库存保留；每处火灾同一时刻仅一名消防员在途，同站工人最多各负责一处；到达灭火、返回释放名额，死亡扣岗位工人与人口。跨白天/夜晚、夜晚死亡、任务改派、路径失效、站点失效、读档恢复都按同一时限规则结算。
5. **落雷分支**：70% 纯闪屏不计数；30% 落雷，在相机画面内按 50% 地面、50% 建筑/友方单位选点；无地图只闪屏；核心和非正常运营建筑不被命中；99% 人员死亡与 1% 濒死幸存、蓝图或 1000 金币待存放都能正确触发。
6. **占位表现**：四季滤镜不同，晴天与雪天沿用现有主光亮度，小／中／大雨分别为 85%／75%／65%；雨雪粒子、风摆、闪屏、火焰、消防员与雷神殿使用占位资源，后续能直接替换素材。

最终美术样式、占位动画摆幅和性能档位在接入时调节配置；本草案不要求现在制作正式资源。

## 7. 2026-09-23 雨量分级补充

原有“雨天”作为**中雨**保留存档枚举值，新增小雨与大雨。每日先按当季降水概率确定是否降水；气温低于 0°C 时仍转雪，否则小／中／大雨首版等概率抽取。三档雨均沿用已定的白天雷鸣、落雷、火灾和消防规则，雨量不改变雷击概率或次数上限。

占位粒子发射率依次为每秒 **180／450／900**，中雨保留原有密度；雨滴尺寸随档位略增。主光比例依次为 **85%／75%／65%**，由 Game 场景宿主参数调节。HUD 与天气调试页显示具体雨量。

天气调试页新增“小雨”“中雨”“大雨”“雷鸣”“落雷”按钮。“雷鸣”只播放闪屏和现有雷声提示；“落雷”强制按相机内地面／建筑／单位的既有目标规则执行一次落雷，画面没有地图时仅闪屏。两项调试动作可在任何天气下使用，不消耗当天自然落雷上限，也不改变天气随机流；自然打雷依旧只发生在雨天可操作的白天。

雷鸣的占位闪屏使用明确的全屏白色画面并短暂保持，然后淡出。落雷的占位表现为一束从屏幕上方向落点逐段下劈的电弧，配合移动轨迹粒子、落点火花与短暂光照；这些表现不改变既定的命中和伤害判定。
