# ECS 架构

## 唯一权威状态

默认 ECS World 中的实体、组件和 Buffer 保存全部玩法状态。Session 是阶段根；建筑、士兵、英雄、任务、远征、人才和王室成员使用持久身份。SO 只编辑模板，不在运行时保存王朝状态。

```text
GameDefinitionAsset / GameCatalogAsset / MapAsset / Authoring Prefab
                              ↓ Baking
             ContentBlob / Entity Prefab / 初始组件
                              ↓
UI 输入 → Command → ECS Systems → ECS 状态 → UGUI / TMP / 外观
                              ↓
                     白天保存 / 白天与黄昏节点
```

三个 ECS 程序集分别是模拟与配置、Presentation、Editor；地图和美术适配器在 Scripts 内单独组织。不要为了“全 ECS”把 Canvas、Camera、AudioSource 等展示接口强行变成玩法数据。

## 时序与职责

- GameLoopSystem 初始化、验证并消费命令；白天结算调用无状态领域操作。
- 经济按稳定建筑 ID 逐栋提交，前一栋产出可以用于后一栋当次加工。不能因为合批方便改变资源竞争顺序。
- 夜间感知、战术选择、攻击生成、飞行物、伤害和导航由 ECS 系统配合执行；部分重计算使用 Burst / Jobs，事务与接战位等仍有主线程工作。
- DBP 编辑源烘焙为 Entity Task，选择休眠、撤退、玩家命令、攻击或巡逻意图。它不直接扣库存、扣生命、发奖励或保存。
- CheckpointSystem 消费存取请求；SimulationLifetimeSystem 清理失去根所有者的运行实体。

## 表现与制作

Entities Graphics 负责烘焙的静态模型。WorldPresentationView 可以按资源绑定接管单个实体的外观，驱动纯表现 Prefab、Animator、粒子和灯光；没有绑定时保持 ECS 模型。ExternalVisual 只管理渲染所有权。

PresentationRuntime 管理有界音源与文本缓存，不拥有王朝状态、不创建 AudioListener。模型和特效由 Game 场景所有者清理；应用设置独立保存。动画和 Transform 不反向决定伤害、移动或奖励。

## 身份与恢复

内容使用稳定字符串 ID；个体使用 ulong Identity.Id。Entity 句柄只在当前 World 有效，不能直接持久化。动态实体必须具有 SimulationOwner。

载入先校验全部节点和内容签名，再在同步恢复事务内创建候选实体、恢复稳定 ID 关联并提交。提交前保留原实体，失败恢复原状态。新根字段必须同步扩展捕获、验证和 RestoreTransaction.RootState。

夜晚不能保存逐帧战斗。回退节点表示重新进行该夜，不承诺物理、渲染或多线程逐帧回放一致。
