# ECS 架构

## 唯一权威状态

ECS World 中的实体、组件和 Buffer 保存全部玩法状态。应用入口解析地图根后，将 EntityManager、根实体和会话生命周期显式交给 UI 与表现服务；面板不自行查找默认 World 或推断当前根。Session 是阶段根；建筑、士兵、英雄、任务、远征、人才和王室成员使用持久身份。SO 只编辑模板，不在运行时保存王朝状态。

```text
GameDefinitionAsset / GameCatalogAsset / MapAsset / Authoring Prefab
                              ↓ Baking
             ContentBlob / Entity Prefab / 初始组件
                              ↓
UI 输入 → CommandRequests → Command → ECS Systems → ECS 状态 → UGUI / TMP / 外观
                              ↓
                     白天保存 / 白天与黄昏节点
```

程序集按依赖方向拆分，运行层不反向引用界面或应用入口：

| 程序集 | 脚本目录 | 职责 |
| --- | --- | --- |
| Landsong.ECS | Scripts/ECS/Simulation、Persistence | 运行数据、模拟、事务与存档；不引用 Authoring、UI、Application、Presentation、Moyo 或第三方 AI |
| Landsong.ECS.Authoring | Scripts/ECS/Authoring | 配置资产、校验、Baking 和 Entities Graphics 接入；依赖运行核心 |
| Landsong.ECS.AI | Scripts/ECS/AI | Behavior Designer 决策适配及其与核心战斗组的执行边界；依赖运行核心 |
| Landsong.ECS.Presentation | Scripts/Presentation | UI 使用的接口与数据服务、设置、声音、文本和世界表现；不引用具体面板 |
| Landsong.UI | Scripts/UI | Moyo 根面板和领域子视图；通过接口请求应用行为 |
| Landsong.Application | Scripts/Application | 创建持久根，串行切图、恢复、打开/释放会话面板及显式绑定 |
| Landsong.Verification | Scripts/Verification | 编辑器/Development 完整流程验证；Release 不包含 smoke 行为 |
| Landsong.ECS.Editor | Scripts/ECS/Editor | 原生 ECS 配置与制作入口 |

Moyo.Runtime 独立于项目业务。项目级地图、美术和验证工具保留在 Scripts/Editor 的默认编辑器程序集中；不靠挪入默认运行程序集绕过依赖关系。不要为了“全 ECS”把 Canvas、Camera、AudioSource 等展示接口强行变成玩法数据。

模拟和持久化保留在同一运行核心中：经济预演、入夜确认使用完整候选状态和恢复事务，持久化也需要运行规则进行合法性校验与重建。这是明确保留的事务边界，不声称两者已经单向解耦。建筑视觉槽等只读运行数据归入 Simulation/Contracts；Hybrid、Graphics 和 Opsive 的适配依赖不再进入核心程序集。AI 适配在 DBP 决策之后、核心战斗组之前执行，核心不直接引用第三方组类型。

## 时序与职责

- GameLoopSystem 初始化、验证并消费命令；统一阶段、暂停、情报和许可门禁之后，分别交给 Building、Inventory、Military、Progression、Court 命令处理器，具体扣费与状态变更仍由领域操作完成。CommandRequests 为生产入口提供具名构造，库存移动保存不可变选择来源，任务/远征/肖像载荷在领域边界组装；报价校验使用明确命令种类，不以文案暗示执行协议。
- 经济按稳定建筑 ID 逐栋提交，前一栋产出可以用于后一栋当次加工。不能因为合批方便改变资源竞争顺序。
- 夜间感知、战术选择、攻击生成、飞行物、伤害和导航由 ECS 系统配合执行；部分重计算使用 Burst / Jobs，事务与接战位等仍有主线程工作。
- DBP 编辑源烘焙为 Entity Task，选择休眠、撤退、玩家命令、攻击或巡逻意图。它不直接扣库存、扣生命、发奖励或保存。
- CheckpointSystem 消费存取请求；SimulationLifetimeSystem 清理失去根所有者的运行实体。
- InventoryTransaction 负责库存、待存放及本次追加的经济账本/历史回滚；奖励事务额外覆盖许可、研究行、Session、事件、战报、夜间提交标志和完整历史行，包含消息合并对已有历史行的修改。奖励事务不创建/销毁实体或执行外部 I/O；采集、招募、英雄出场等实体操作仍由各自领域事务保护，不能只恢复资源数值。
- GameEvent 携带 HistoryCategory，手动库存操作携带命令种类。历史筛选不从中文消息内容反推业务类别；名称和文案仅用于展示。

## 许可、奖励与效果

`Entitlement` 继续保存许可和兼容完成投影，但业务通过 `BlueprintOps`、`PermanentBuffOps`、`FeatureOps`、`ProgressionFacts` 读取或写入各自领域含义，底层 `EntitlementStore` 为内部实现。建筑蓝图保存最高许可并覆盖低等级；建造检查一级、升级检查当前等级加一。Buff 许可不等于临时实例或叠层；功能许可仅一级，`limit.*` 是建筑限建组。Authoring、运行发放和导入共用 `EntitlementRules`，恢复导入事实而不重放奖励。

`RewardOps` 先预检整批，再在 `RewardTransaction` 中提交。定义奖励保持物品先、许可后；开局和夜间的批次保留原有配置顺序。普通完整奖励不能放入即整批拒绝，夜间奖励允许进入待存放；人才回合物品保留只存可容纳数量的策略。任务/远征完成标记与对应奖励在同一提交边界内。研究完成次数以 `ResearchEntry` 为权威，旧许可投影在导入时归一化并验证一致性。

`EffectOps` 按显式 `EffectQuery` 汇集永久 Buff、政策、人才/岗位/特性、王室状态，以及对应领域的科技和建筑来源。`Query` 的来源说明与 `Value` 使用同一次匹配规则，记录采用值与排除原因，不保存另一套效果状态或跨会话缓存。物品和建筑两个目标维度分别匹配，固定值与比例值由效果类型确定。建筑范围效果仍由 `SpatialOps` 处理原有叠加算法；当夜军事属性仍在黄昏冻结。支持表同时用于配置校验，不能通过新增可编辑字段宣称已有执行支持。

本次保留 ECS、命令调度、恢复事务和 AI 架构；具体来源约束见 [内容功能配置](ECS/内容功能配置.md)。A–E 实施及 N01–N12 定向编辑器验证已完成，四场景与研究 HUD 实际 Play 检查均通过，完整结果见 [非 UI 重构执行记录](非UI重构执行记录.md)。

## 表现与制作

Entities Graphics 负责烘焙的静态模型。WorldPresentationView 按配置目录中的 PresentationActor 模板接管单个实体的外观；特效使用 PresentationEffect 模板。Animator、Renderers、粒子和灯光均在编辑器显式配置，不在运行时扫描或补组件。没有匹配模型时保持 ECS 模型；ExternalVisual 只管理渲染所有权。

PresentationRuntime 使用持久 UI 根已配置的固定音源池，不拥有王朝状态、不创建 AudioListener。应用流程显式绑定/解除它与 WorldPresentationView 的会话；世界表现根模板实例移入明确的 Game 场景，并在解除会话时清理。应用设置独立保存。动画和 Transform 不反向决定伤害、移动或奖励。

## 身份与恢复

内容使用稳定字符串 ID；个体使用 ulong Identity.Id。Entity 句柄只在当前 World 有效，不能直接持久化。动态实体必须具有 SimulationOwner。

载入先校验全部节点和内容签名，再在同步恢复事务内创建候选实体、恢复稳定 ID 关联并提交。提交前保留原实体，失败恢复原状态。新可变根组件或 Buffer 必须登记 RestoreTransaction.RootState；未登记的 Landsong 根类型在候选构建前拒绝恢复，只读配置使用明确白名单，不能借白名单掩盖可变状态。

所有权清理与应用释放审计包含 Disabled 运行实体，仍存活的 Disabled Session 在同步恢复期间是合法 owner。入夜前的失效任务容器协调在候选事务中执行，扣罚和任务销毁不先写入正式白天；取消或失败只保留必要的确认信息。

新快照 v24 由 SnapshotBinaryV24 显式逐字段编码，并以字段覆盖检查阻止新增字段静默遗漏。旧 v22/v23 读取器固定历史布局，不随当前运行结构体变动；王朝封装保持 v3。新签名包含完整 GameSettings、网格几何、出生区域、开局状态及玩法规则，排除名称、默认皮肤、建筑菜单顺序等纯显示设置。旧签名没有记录的信息不能追溯补验，读取时保留原契约；详细兼容边界与金样本见 [运行与存档](运行时与存档/README.md)。

夜晚不能保存逐帧战斗。回退节点表示重新进行该夜，不承诺物理、渲染或多线程逐帧回放一致。

建筑配置由 ContentSource.Modules 保存；其它功能由 ContentSource.Configuration 中的任务目标、奖励、费用、作物、库存、远征、人物和属性效果模块保存。每个模块有独立的配置类和中文具名字段。开局发放、夜间条件也使用专门的数据类。

ContentCompilation 创建内容引用解析器，将注册资产引用转换为索引。建筑编译器及各模块编译器直接输出运行 Rule；所有内容校验和 Blob 写入共用这次编译结果。紧凑 Rule 只属于运行层，不是可编辑配置。RuleSource、EffectiveRules、ConvertRule、原始 Rules 字段和一次性反向迁移器已删除，无旧配置回退路径。

非建筑条目保存显式执行顺序，以保持跨模块奖励顺序与随机数消费顺序。任务进度仍使用稳定 Key，而不依赖数组位置。配置编译验证保留全部 185 个定义及开局奖励的数值、索引和顺序对照；它与快照协议验证分开，不能把内容编译通过当作跨版本存档兼容证明。
