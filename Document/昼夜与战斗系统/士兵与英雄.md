# 士兵与英雄

## 玩家管理

普通士兵自动巡逻和攻击，不提供直接小队集火。士兵拥有稳定 ID、姓名、个人经验与等级，独立占人口。白天可以改名、多资源批量招募、调动及立刻遣散；遣散直接释放人口/槽位，不退款。

皇宫当前 LV1 提供 3 个通用驻兵槽（Garrison.Amount = 3），新游戏默认向第 1、2 号槽位各分配 1 名民兵，剩余 1 个空槽；出勤沿用每批 1 人的配置。初始士兵占用人口，不扣资源、不消耗本回合募兵额度。

军事页左侧按驻地显示已驻扎和空槽，右侧待分配；点击“募兵”确认费用后，新士兵先进入待分配池，点击右侧士兵再点击左侧目标空槽才完成分配。费用、人口和驻地本回合招募额度在募兵时结算，待分配模式不要求该募兵建筑有空槽；无距离、无调动费用，任何兵种通用槽。溢出或失去驻地进入待分配，重复操作不重置期限；下一夜前仍未安排则解散。

驻地召回打断交战，途中可受击、可取消；归营隐藏且本夜不再出勤。无路可回、途中驻地荒废或路径失效有提示。警铃按当前位置影响士兵，近战不强拉、召回优先、不覆盖已选英雄；新铃替换旧铃，再点取消，集结至可达建筑边缘。

英雄不是人才。以泰坦为例，神殿需持续 30 工人才能供奉/唤醒，招募需 1000 金币；持续供奉每次白天结算付 10 金币，平安夜也消耗，金币不足自动中断提示。英雄人口由定义配置。

所有夜晚都可额外付资源手动唤醒，撤退/收尾不可新唤醒；没有合法出口不扣费。未实际参战也消耗出场费。卡片/数字选择已出场英雄，右键移动、H 驻守，未选中按自动单位处理，不另配白天出战阵容。

神殿荒废/拆除等同英雄死亡；仅缺工不杀英雄。倒地即死亡，黎明释放人口并开始完整冷却，默认 10 回合后可重新全价招募、经验清零；重建建筑不能绕过身份冷却。

## 编辑数据与占位数值

入口仍为 `Assets/Landsong/ECSContent/Definitions`，一个定义一个 SO。当前占位兵种为 `Soldier/militia.asset`。

| 配置 | 语义 / 默认 |
| --- | --- |
| 士兵 `Cost` | 未配置任何 `RecruitCost` 时的单人金币费用，沿用原有数值 |
| 士兵 `RecruitCost` | 配置任意此规则后，整份替代 Cost；Target 为物品，Amount 为单人成本，同物品相加，Level 只允许 0/1。多资源总量先检查再整批提交，不使用待存放池 |
| 建筑 `Modules.Garrison.RecruitmentLimitPerTurn` | 每驻地每回合所有兵种共享招募人数上限；0 使用当前槽数。移动、升级、调动和解散不清除已招计数；重新建造是新建筑身份 |
| `SoldierGrowth.MaxLevel` | 10 |
| `FirstLevelExperience / ExperienceStep` | 20 / 10；从等级 L 到 L+1 需要 `20 + (L-1)×10` 经验，保存累计经验，等级由曲线派生 |
| `BattleExperience` | 10；战斗夜有实际有效伤害交互且存活者获得，不按最后一击抢经验；未交战/平安巡逻不给经验，满级封顶 |
| `HealthPerLevel / DamagePerLevel` | 每级分别增加基础计算结果的 5%；与人才/科技/王室加成之后的夜晚准备值相乘。不在白天换槽或招募后重算本夜入侵预算 |

成长数值为可编辑基准。Baking 拒绝负成本、无效资源、非法等级规则、非有限成长值、零升级门槛和超出存储范围的累计曲线。Inspector 内补配置提示。

## 运行状态与时序

- `Soldier.Slot` 为 **1 起算**，0 表示未驻扎；不能把 UI 排序当槽号。容量缩减只保留仍处于合法槽号的士兵，高号槽溢出，即使该士兵创建得更早也一样。
- 分批出勤顺序使用真实槽号；空槽不会引起其他士兵自动换槽。荒废和拆除同时清掉驻地 ID 与槽号，修复/扩容不自动召回待分配士兵。
- 重复移出或刷新界面不重置待分配起始回合；期限依旧为下次入夜前，无距离限制、不收调动费、所有兵种通用槽。
- 筛选/排序只改变展示，不重排真实槽位；一键填充按稳定 ID 从全部待分配士兵中选取，不替换任何已有驻军。需要指定个体时先选择，再点目标空槽；驻军面板不再显示选中/对比详情；详情用卡片右侧按钮打开。
- 已阵亡士兵在当夜继续占人口/名册/槽位，到黎明才删除，不可在夜间改名、调动或主动解散。存活士兵恢复满状态。
- `Building.SoldierRecruitTurn/SoldiersRecruited` 保存驻地招募账；`Soldier.Experience/LastExperienceTurn` 保存累计经验及防重回合。
- 召回状态 0 正常、1 途中、2 已归营；夜晚准备和黎明清除。它属于 ECS 状态，DBP 只执行命令，不另存一份士兵状态机。
- 经验在收尾时只写战报预览，黎明确认后才增加个人经验。核心失守重开仍从节点恢复，不保留未结算经验。
- 命令全部经过 `GameLoopSystem` 的阶段、暂停、节点门禁。UI 只用共享 Quote 显示与提交，不自行扣费、改槽或计算升级。

## 成长和制作字段

在英雄 `GameDefinitionAsset.Data.HeroGrowth` 编辑：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| MaxLevel / FirstLevelExperience / ExperienceStep | 10 / 20 / 10 | 首次升级需 20，此后每级增加 10；使用累计经验阈值 |
| HealthPerLevel / DamagePerLevel | 0.05 / 0.05 | 每级相对基础值增加 5% 生命/攻击，与士兵个人成长独立 |
| OfferingExperience | 1 | 一次供奉成功后获得；未支付不增加，平安夜也照常供奉 |
| ContactSeconds | 3 | 每次实际生效后延续的有效参战窗口；多个效果取时间并集，不按命中数叠加 |
| ExperiencePerSecond | 1 | 每有效模拟秒的基础经验 |
| ThreatReference / MaximumThreatMultiplier | 100 / 3 | 威胁倍率为 sqrt(BaseThreat / 参考值)，限制在 1～上限 |

战斗经验 = 向上取整（有效秒数 × 每秒经验 × 威胁倍率），再限制在最高等级剩余经验内。数值是可调占位，不代表正式平衡。暂停、平安夜、未生效攻击/支援、纯待命不计时；实际伤害的施加者和承受者均可触发参战。收尾预览、黎明防重提交；英雄死后清零且不授予战斗经验。升级后的生命上限在黎明更新，夜间基础属性仍来自黄昏准备值。

`MilitaryOps.RecordHeroContribution` 是有效治疗、护盾吸收、增减益和控制的统一接点。调用方必须先确认效果实际生效，并传正的有效量；过量治疗、空放和仅选中目标不能调用。目前接入真实对敌伤害，没有为占位英雄伪造支援技能。`HeroCombat` 是 Entity 上的临时计时组件，不是第二套存档状态。

英雄招募时生成持久肖像，HUD 接入统一肖像缓存；再次招募/唤醒保留原 DNA。仍使用普通 UGUI，不在 UI 保存英雄权威状态。英雄没有新增寿命/亲属玩法，当前模块化占位使用成年男性外观，也可配置整图覆盖。

## 生命周期、事务与存档

- 神殿持续需要足额工人才能供奉/唤醒；缺工本身不杀英雄。建筑荒废/拆除与英雄共命；夜间死亡到黎明才释放人口和启动完整冷却。
- 重招继续复用该英雄定义的稳定身份，重新检查人口/建筑/费用，全额支付，经验为零；重建神殿不能绕过旧冷却。
- 唤醒费用立即消耗，即使没有实际参战也不退；战报显示“英雄出场消耗”。招募扣款后、唤醒扣款后/出场准备后异常同时回滚库存、待存放、账本、历史、战报和会话；英雄出场准备还恢复导航、战术、命令与临时战斗组件的值及原先是否存在。
- 持久身份、经验、冷却与神殿关联参与快照校验，HeroGrowth 进入内容签名。恢复白天/黄昏节点时重建空的临时参战计时，当前写入快照 v24 / 王朝封装 v3，旧版读取契约见 [运行与存档](../运行时与存档/README.md)。

## 士兵个人生命周期

首次招募生成性别、年龄（默认 18～30）、寿命（默认 65～85）、姓名和肖像。每次黎明按回合结算一次年龄；自然死亡原实体补充新人，仅刷新姓名、年龄、性别、寿命、肖像及个人标记，保留兵员 ID、驻军槽位、人口、经验和战斗属性。随后仍执行原有黎明经验/治疗规则，不因换人另行重算成长。战死依旧在黎明减员，不能通过换人复活。

士兵卡片的“特别关注”Toggle 提交 SetSoldierAttention 命令并保存到 SoldierPerson.SpecialAttention。仅被关注的个体在自然死亡或战死时发送一次遗言/遗愿并冻结历史姓名，是否改名不再影响事件。取消关注后不触发；自然换人后的新兵默认不关注。遣散不算死亡，不触发遗言。经济预演不产生年龄或纪念消息；关注状态随存档和重试回滚。

## 建筑驻军与士兵详情（2026-09-10）

建筑详情提供独立驻军模块和“调整驻军”入口。已有槽位打开可关闭的士兵详情，空槽打开管理页。详情显示可编辑姓名、持久年龄、真实血量、敏捷（读取现有速度值）及现有攻击/等级能力；力量与知识暂显示“—”，头盔、铠甲、武器为未开放占位，不将攻击值冒充力量。士兵详情暂使用白色肖像占位；建筑驻军槽复用军事列表的真实肖像绑定，保持宽高比，死亡置灰，重新打开或人物数据变化时刷新。

待分配招募使用 Garrison/Slot = 0，PendingSince 为当前回合；直接入驻命令仍保留合法性检查。池中选择更新当前选中者，空槽通过具名分配请求提交真实建筑 ID 与 1 起算槽号。占用目标仍拒绝替换，未安排士兵沿用下次入夜前解散规则。招募异常同时撤销费用、库存历史、人口、募兵次数、创建实体及会话状态。快照写入 v24；v22 读取仍将旧命名标记转换为未关注，v23 的特别关注值原样保留。

## 配置开局驻军

打开 b王宫.asset，在“驻军”模块填写容量 3、每批出勤 1；“开局驻军”添加民兵 ×2，适用等级 1。可添加多个兵种条目，总人数不得超过容量。每回合募兵上限 0 表示跟随容量。保存后新开王朝，后续建造、升级和读档不会重复赠兵。完整步骤见 [建筑模块配置](../ECS/建筑模块配置.md)。


## 驻军卡片与排序

每座建筑的标题、实际槽位和募兵/召回操作共同位于 `UI_GamePanel_GarrisonGroup` 父对象下。右侧标题为“待分配军队”，只显示 Garrison=0 的士兵，不再附带已分配士兵的选中/对比摘要或英雄列表。兵种筛选影响待分配列表及募兵选项，左侧实际槽位保持完整。

`UI_GamePanel_SoldierItem` 分为身份、属性/能力占位、操作栏：姓名、兵种、等级、力量/知识占位、实际敏捷和当前/上限血量；特殊能力图标暂为占位，不赋予技能效果。卡片右侧“详情”打开详情弹窗。点击待分配卡片选中，再点击指定建筑空槽分配；已占用卡片本体不打开详情。每张卡片带特别关注 Toggle；已分配士兵带“移出驻地”，白天存活士兵带“立刻遣散”，后者不额外弹确认。夜间保留召回及关注，禁止调动和遣散。

待分配列表支持按等级、按总属性值降序，同值按稳定 ID 排序。总属性暂为生命上限＋敏捷，不计当前受伤造成的血量下降；力量、知识待策划定义后接入同一口径。
