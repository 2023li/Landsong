# 狼敌人制作与接入

`wolf` 是普通战斗夜中的快速近战敌人。出场后持续寻找最近的存活、已出战、未处于保护期的敌对士兵，靠近后扑咬；目标死亡、归营或距离变化时重新选择。英雄和建筑不是狼的攻击目标，没有合格士兵时原地等待。夜晚结束后按统一流程撤退。

## 正式资产

每个单位固定一个 Animator Controller；没有单位配方资产。下图是创建器的默认输出约定，现有资源包可在 Unity 中改名或移动，功能连接以 GUID 引用为准。

```text
Assets/Landsong/ECSContent/
├── Definitions/Enemy/wolf.asset                         身份、数值、奖励、战术配置
└── Units/Enemy/wolf/
    ├── wolf.prefab                                     逻辑与 AI、View 引用
    ├── wolfView.prefab                                 Animator、Rig、蒙皮表现
    ├── Controllers/wolf.controller                    唯一控制器
    ├── Clips/{Idle,Walk,Run,Attack,Death}.anim           五种动作
    ├── Materials/Material0.mat                         Rukhanka 蒙皮材质
    └── Preview/
        ├── WolfAnimationPreview.unity                  独立动画预览
        └── WolfAnimationEntities.unity                 预览 SubScene
```

原始素材位于 `Assets/polyperfect/Low Poly Animated Animals/`：模型使用 `Meshes/Animals/Wolf/SKM_Wolf_Rig.fbx`，动作使用同目录的 `SKM_Wolf_Animations.fbx`，材质和纹理使用 `Materials/Animals/Wolf.mat` 与 `Textures/Animals/Wolf_COL_2k.png`。创建器把清理后的模型层级直接写入 `wolfView.prefab`，并保存项目拥有的动作副本和材质；不再生成另一个模型快照。供应商 Prefab 的游荡、音效、CharacterController 等脚本没有接入玩法。

正式连接顺序为：当前内容集中的 `wolf` Definition → `Prefab` → `SoldierAnimationAuthoring.VisualPrefab` → View Animator 的 Controller。编辑器重复创建、动画预览和验证都沿这组引用定位，不读取 `Units/Enemy/wolf` 字符串。

## 初始配置与调整

| 字段 | 初始值 | 修改位置 |
| --- | --- | --- |
| 最大生命 | 60 | wolf.asset → CombatStats |
| 基础伤害 | 8 | 同上；实际伤害仍计算护甲和减伤 |
| 攻击距离 | 1.1 | 同上；沿用战斗系统的目标体积与命中容差 |
| 攻击间隔 | 1.5 秒 | 同上 |
| 移动速度 | 3.2 | 同上 |
| 弹体速度 | 0 | 0 表示近战直接命中，不创建弹体 |
| 碰撞半径 | 0.4 | CombatStats → Profile → BodyRadius |
| 战术特性 | NearestSoldier | CombatStats → Profile → Traits |
| 威胁值 | 8 | wolf.asset → ThreatValue，用于夜晚预算 |
| 击杀奖励 | 2 金币 | wolf.asset → KillRewards，沿用普通敌军模板 |
| 普通夜抽取权重 | 1 | NightEventCatalog.asset → night.raid → Enemies |

`night.raid` 中狼与现有两种普通敌军权重相同。编成按波次抽取，某一夜不保证一定出现狼；和平夜、首领夜和首领返回事件未加入狼。

上述生命和伤害是定义基础值，实际出场仍沿用普通夜预算的 `PowerScale` 缩放。

`NearestSoldier` 是可复用的战术特性，没有运行时 `wolf` 字符串判断。它忽略常规索敌半径、追击半径和最长追击时间，按实际距离持续选取士兵；相同距离按稳定身份排序。仍遵循地图寻路、单位避让和近战站位，不穿越障碍。如果最近士兵暂不可达，狼不会改为攻击建筑。

## 动画结构

逻辑和 View 都使用 `GenericCreature`。控制器只有 Base 层，包含 Idle、Walk、Run、Attack、Death，没有人形手臂 Mask、拔剑或火把层。源资源没有专用受击动作，所以保留受伤和生命变化，受击动画时长为 0。没有编造受击或庆祝动作。

跑步由实际移动和警戒状态驱动；攻击由战斗系统产生信号，`AttackSpeed` 根据动作长度与攻击间隔计算。复制出的 Attack 和 Death 均不循环。Generic Rig 使用 UserDefined，Rig 的 Avatar 留空，直接读取保留的 Transform 骨骼层级；Animator 仍保留原始 Generic Avatar。该 FBX 的 Generic Avatar 没有人形 skeleton 数据，不能让 Rukhanka 从人形描述构建骨架。Animator 与 Rukhanka Rig 的 Root Motion 均关闭，位置由导航系统驱动；动作事件不结算伤害。扑咬伤害在战斗攻击时点结算，属于当前统一的即时近战规则。

常用修改流程：

1. 调数值、目标规则或奖励：编辑 `wolf.asset`。
2. 换动作：编辑 `Clips/` 和唯一的 `Controllers/wolf.controller`，保留公共参数契约。
3. 调外观、脚底偏移和包围盒：编辑 `wolfView.prefab`。View 是唯一正式外观编辑入口。
4. 调出现频率：编辑 `NightEventCatalog.asset` 的 `night.raid` 敌军池。
5. 执行 **Landsong → 内容制作 → 校验正式制作内容**，然后执行下面的回归与图形预览。

## 验证入口

- **Landsong → ECS → Verification → Wolf**：正式资产烘焙、最近士兵与稳定同距选择、排除英雄/死者/未出战/保护目标、超视距追击、站位和真实导航、近战伤害与冷却、无目标等待、撤退、动画创建与死亡清理。
- **Landsong → 动画 → 狼 → 运行动画预览**：独立预览，不进入存档会话；停止后恢复原场景。开始前需保存当前场景。
- **Landsong → 动画 → 狼 → 验证动画 (Play)**：真实 Rukhanka 渲染循环检查并输出待机、奔跑、攻击和死亡截图到 `Library/LandsongEcs/wolf-*.png`，完成后自动停止。
- **Landsong → ECS → Verification → Run all**：项目完整回归，包含 Wolf。

测试报告分别写入 `Library/LandsongEcs/wolf-verification.txt`、`wolf-animation-play.txt` 和 `regressions.txt`。运行结果应以报告时间与 PASS/FAIL 为准。

2026-09-21 验收结果：狼专项 28 项通过；13:31 图形 Play 20 项通过并人工检查四张动作截图；13:41 完整回归 53 组、14,884 项断言、0 失败。完整回归还覆盖通过统一窗口输入新建 Generic 动物、拒绝不匹配的人形动作、实际烘焙和 View 生命周期。

其他新单位按 [单位制作流程](单位制作流程.md) 创建。
