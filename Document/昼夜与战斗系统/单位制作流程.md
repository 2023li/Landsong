# 单位创建与制作流程

本页是新增士兵、英雄和敌军的正式制作入口。制作工具统一使用世界模板引用的内容集；新单位均沿“领域定义 → 逻辑 Prefab → 独立 View”接入。

运输工人属于平民，由资源连接调度，使用世界模板中的独立配置；制作和修改见[运输工人制作与接入](运输工人制作与接入.md)。它的男女模型共用一个固定控制器，不需要兵种定义或单位配方。

## 创建步骤

下面以新增一个“演练哨兵”为例，使用基础动作类型。示例只用于说明如何操作，不会自动生成正式兵种。制作英雄或敌人时沿同样流程，选择对应领域的模板。

### 步骤 1：打开创建窗口

退出 Play，等待编译及导入完成。打开 **Landsong → 内容制作 → 创建单位**。

不创建或保存单位配方资产。每个单位固定一个 Controller，后续直接编辑本单位资产。

窗口只临时收集首次创建输入。后续的定义、动画和预制体目录由工具生成，不需要先手工创建空文件夹或空控制器。

### 步骤 2：填写身份和玩法模板

在创建窗口填写：

| 字段 | 本例填写 | 作用 |
| --- | --- | --- |
| 稳定 ID `StableId` | `soldier.sentry_demo` | 新单位在所属领域内的唯一身份 |
| 显示名称 `DisplayName` | 演练哨兵 | 游戏显示名称 |
| 领域定义模板 `DefinitionTemplate` | `Assets/Landsong/ECSContent/Definitions/Soldier/militia.asset` | 复制基础数值、AI 逻辑和领域引用 |
| 动作配置类型 `Profile` | 基础动作（无切换装备） | 生成不要求剑/火把切换的控制器和 View |

模板必须已注册到当前正式内容集。选择 Soldier、Hero 或 Enemy 定义，就生成同领域的新定义；模板本身保持不变。选择英雄模板不会把它转换为普通士兵。创建后再按设计调整新单位数值、费用和奖励。

### 步骤 3：指定模型和动作

准备纯表现模型预制体：有且仅有一个 Animator，使用与动作类型匹配的有效 Avatar，不包含玩法脚本。输入模型可以带 RigDefinitionAuthoring，创建器会按本流程配置生成的 Rig。

第一次演练可复用项目已有模型：

`Assets/polyperfect/Low Poly Ultimate Pack/_M/Prefabs_M/People_M/Rigs_M/使用/Man_Soldier_Roman_Empire_Rig.prefab`

将它拖到“模型预制体”。“Rukhanka 蒙皮着色器”填写下文给出的 `SoldierAnimatedLit.shadergraph`。公共动作可以从正式 `militia` 定义所引用的逻辑 Prefab，继续沿 `SoldierAnimationAuthoring.VisualPrefab → Animator Controller` 找到当前动作；不要通过写死单位文件夹来定位：

| 创建字段 | 本例输入文件 |
| --- | --- |
| 待机 `Clips.Idle` | Idle.anim |
| 行走 `Clips.Walk` | Walk.anim |
| 奔跑 `Clips.Run` | Run.anim |
| 攻击 `Clips.Attack` | MeleeAttack.anim |
| 受击 `Clips.Hit` | Hit.anim |
| 死亡 `Clips.Death` | Death.anim |
| 庆祝 `Clips.Celebrate` | Victory.anim |

基础动作与剑/火把类型需要上述七个 Humanoid Clip。动物选择 GenericCreature：Idle、Walk、Run、Attack、Death 五项必填，Hit 可空，Celebrate 不使用；骨骼路径必须匹配模型，不能把其他骨架的 Generic 动作直接混用。正式制作时换为适合新角色的模型和动作。工具会复制动作与材质，去除动作事件并设置循环；原始 FBX、模型、动作和材质不被修改。输入素材可保留在已有美术/供应商目录，生成的本单位产物放在后文约定的默认目录。

### 步骤 4：选择装备分支并调整模型参数

| 动作类型 | 额外输入 | 生成内容 |
| --- | --- | --- |
| 动物动作（GenericCreature） | 同一骨架的五个必需动作；受击可空 | 一个 Base 层，无装备切换和人形 Mask |
| 基础动作 | 无剑/火把切换输入要求；固定武器可放在模型中 | 公共动作，Base 与 Celebration Arms 两层 |
| 剑与火把切换 | 持火把、拔剑、收剑三个动作；剑和火把模型；左右手挂点位置与角度 | 公共动作与装备动作，四层控制器，武器及火把挂点 |

剑与火把类型要求可访问的左右手 Humanoid 骨骼，模型导入时关闭 Optimize Game Objects。基础类型也可用于弓与射击的表现。CombatStats.ProjectileSpeed 为 0 时直接结算近战命中，大于 0 时生成弹体；伤害、目标选择和冷却由 ECS/AI 决定，更换 Clip 不会改变攻击方式。

设置模型局部位置、统一缩放和蒙皮可见范围 `SkinBounds`。包围盒要覆盖跑动、举手及倒地姿势；它控制渲染裁剪，不是单位伤害或寻路范围。

### 步骤 5：生成并检查独立产物

点击窗口的“创建并注册单位”。成功后自动选中新定义，并生成下文目录树中的全部必需资产。创建器自动建立 Controller、动作副本、Mask、材质、逻辑 Prefab 和 View，不要求复制罗马士兵的旧安装脚本。

本例生成的玩法定义为 `Assets/Landsong/ECSContent/Definitions/Soldier/soldier.sentry_demo.asset`。检查新定义的战斗属性、人口、募兵费用与成长；这些值来自模板，不是工具替新单位设计的平衡值。

打开本单位 View 检查模型比例、脚底、动作及持握位置；逻辑 Prefab 的 `SoldierAnimationAuthoring.VisualPrefab` 应指向它。`Preview/` 只是预留目录，工具不会自动生成该单位的预览场景。控制器与动画生成完成后可以手工调整，须保持后文的参数契约。

### 步骤 6：配置获得或出现途径

| 单位领域 | 配置与验证入口 |
| --- | --- |
| Soldier | 检查新定义的 `RecruitmentCosts` / `FallbackRecruitGold`、人口与成长；在有驻军功能的建筑处募兵并分配空槽。若作为开局驻军，在对应建筑的 `Capabilities.Garrison.InitialUnits` 中填写 Soldier、Count、Level，并检查容量 |
| Hero | 在对应建筑的 `Capabilities.Sanctum.Levels` 中选择新 Hero、适用 Level 与 RequiredWorkers，再检查英雄定义的招募、供奉和人口配置 |
| Enemy | 在当前内容集的夜晚事件/敌军编成中引用新 Enemy，配置出现条件、抽取权重及预算；按实际事件流程验证出生 |

仅注册目录不会产生场上的单位。本例按正常士兵流程验证：募兵 → 进入待分配池 → 分配驻地空槽 → 实际出勤。玩法细节见 [士兵与英雄](士兵与英雄.md) 与 [昼夜与战斗](README.md)。新单位不增加 `WorldVisualCatalog.Models` 行。

### 步骤 7：编译并验收

保存所有修改，依次执行 **Landsong → ECS → Compile domain display catalogs**、**Landsong → ECS → Presentation → Sync language entries (preserve edits)** 和 **Landsong → 内容制作 → 校验正式制作内容**。显示目录用于界面读取新单位，语言同步补充新名称和描述并保留已有译文。

在新测试会话中验证：实际获得/出生、出勤、移动、攻击、受伤、死亡、归营、再次出勤、暂停、读档和切图清理。英雄还需检查唤醒与复活，敌人需检查事件出生条件。工具回归入口为 **Landsong → ECS → Verification → Content authoring workflow**；它不代替本单位素材的实际画面检查。

创建器同时支持 Humanoid 与 GenericCreature。狼是 GenericCreature 的正式样例，见 [狼敌人制作与接入](狼敌人制作与接入.md)。

当前可复用的蒙皮着色器为 `Assets/Landsong/Art/Shared/Shaders/SoldierAnimatedLit.shadergraph`；窗口中的着色器是显式输入，也可指定符合项目 Rukhanka 蒙皮契约的其他 Shader。材质复制后仍需检查纹理与颜色，模型和动作是否适合该单位由作者确认。

## 目录与所有权

`<领域>` 为 Soldier、Hero 或 Enemy。下图是创建器的**默认输出约定**，方便作者定位和避免首次创建重名；它不是单位身份，也不是运行时加载地址。

```text
Assets/Landsong/ECSContent/
├── Definitions/<领域>/<ID>.asset
└── Units/<领域>/<ID>/
    ├── <ID>.prefab              ECS 逻辑根
    ├── <ID>View.prefab          唯一正式模型、骨骼与挂点编辑入口
    ├── Controllers/<ID>.controller  每单位一个
    ├── Clips/             项目拥有的动作副本
    ├── Masks/             Humanoid 手臂混合遮罩；动物没有此目录
    ├── Materials/         本单位材质；纹理可继续引用源资源
    └── Preview/           留给作者保存该单位的预览场景
```

稳定 ID 只保存在 Definition 元数据、编译索引和存档契约中。资产关系通过 Unity 序列化引用连接：内容集引用 Definition，Definition 引用逻辑 Prefab，逻辑 Prefab 引用 View，View 的 Animator 引用 Controller。创建完成后可以通过 Unity `AssetDatabase` 移动或重命名整个单位包，GUID 引用保持有效；运行和验证不得通过字符串路径重新寻找它。

创建器直接把经过清理的模型层级写入 View，不再生成一个不会随 View 同步的 Models 快照。它只在首次创建时使用默认目录；再次执行同 ID 时从正式内容集找到已有 Definition，并沿直接引用验证结构，保留 GUID、控制器编辑、挂点及数值。更新已有单位时直接编辑被引用的产物并验证；创建失败会删除本次新建文件并恢复注册数组，已有文件不会被覆盖。

逻辑根保留所属领域 AI 配置及 `SoldierAnimationAuthoring`，不包含 Renderer 或 Animator。这个历史类名目前承载共享单位动画适配，不限定 Soldier ID；`Profile` 区分装备能力。View 根为 `SoldierAnimationVisualAuthoring`，包含 Animator、Rukhanka Rig、模型及该类型需要的装备。

```text
逻辑 Prefab
└── 领域 AI 配置 + SoldierAnimationAuthoring → 引用独立 View

View Prefab [SoldierAnimationVisualAuthoring]
└── Model
    ├── Animator + RigDefinitionAuthoring
    ├── 模型骨骼与 SkinnedMeshRenderer
    └── 装备挂点（仅相应动作类型需要）
```

## 创建后修改与排查

| 需求或现象 | 操作位置 |
| --- | --- |
| 调整生命、伤害、费用或成长 | 编辑生成的领域定义 |
| 更换模型、装备位置或材质 | 编辑生成的 View 及本单位 Materials；保留动画根与正确引用 |
| 替换动作或调整切换 | 编辑本单位 Clips / Controller，核对参数类型和层索引 |
| 再次创建没有覆盖资产 | 创建窗口只负责首次生成；已有单位直接修改上述产物 |
| 提示模板未注册或 ID 冲突 | 检查模板所属领域与正式内容集；确认新 ID 未被其他资产占用 |
| 提示 Avatar、动作或挂点不匹配 | 检查骨架类型、所需动作以及装备分支的额外输入 |
| 已创建但游戏里没有单位 | 检查步骤 6 的实际获得/出生路径；士兵还要分配驻地并进入出勤阶段 |
| 模型不显示、颜色异常或动作中消失 | 检查逻辑的 View 引用、Rig、蒙皮材质和 SkinBounds，并确认已经出勤 |

## 控制器契约

| 参数 | 类型 | 来源 |
| --- | --- | --- |
| Speed、LocomotionRate | Float | ECS 实际移动与警戒状态 |
| Alerted | Bool | 感知、警铃及释放延迟 |
| Attack、Hit | Trigger | ECS 攻击/有效受伤信号 |
| AttackSpeed | Float | 原动作时长 / 实际攻击间隔 |
| Dead、Celebrate | Bool | 生命与撤退庆祝状态 |
| Equipment | Int | 仅剑与火把类型的装备阶段 |
| DrawWeapon、SheatheWeapon | Trigger | 仅剑与火把类型的拔剑/收剑切换 |

GenericCreature 只有 Base 层，庆祝层和火把层索引为 0，不要求装备或人形骨骼。基础类型生成 Base 和 Celebration Arms 两层；剑与火把类型生成 Base、Torch Arm、Reserved Weapon Arm、Celebration Arms 四层。参数名称和类型必须匹配；庆祝及火把层索引必须指向实际层。Generic Rig 设为 UserDefined 且 Rig.avatar 留空，从保留的 Transform 层级生成骨架；Animator 保留 Generic Avatar。两处 Root Motion 都关闭。控制器和 Clip 可手工编辑，但不能使用动画事件执行伤害、扣费或奖励。

## 生命周期验收

- 未出勤只有逻辑实体；出勤创建一次 View，连续更新不重复创建。
- 归营释放 View，再次出勤创建新实例；未出勤死亡不补建尸体。
- 已出勤死亡保留倒地展示至计时结束；暂停冻结计时和动画。
- 读档替换、单位销毁及会话结束后释放旧 View；表现不进入玩法快照。
- `AnimatedUnitVisual` 阻止旧世界表现系统重复创建模型；导航和战斗继续由 ECS/AI 决定。

具体动作姿态、武器握持、遮挡、蒙皮边界和性能必须在图形 Play 中检查；编辑器工具回归只证明其报告中的创建、编译和状态行为。

| 遗留 ID | 当前路径 | 后续迁移要求 |
| --- | --- | --- |
| boss | Enemy 定义 + 旧模型映射 | 准备匹配动作及独立 View，完成首领出生、战斗、死亡和清理验收后移除旧行 |
| raider | Enemy 定义 + 旧模型映射 | 保留 AI 逻辑与身份，验证出生、攻击、死亡、读档及清理 |
