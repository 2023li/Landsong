# 罗马士兵既有资产说明

新增单位统一按 [单位制作流程](单位制作流程.md) 创建。本页仅维护 militia 的已有资源与专用预览。

当前正式 `militia` 使用 Rukhanka 2.9.1。逻辑与表现是两个独立 Entity Prefab：逻辑根沿用已有士兵与 DBP 配置，出勤时才实例化模型。骨骼计算、混合与变形由插件完成。

## 已接资源

下列资源由正式 `militia` Definition 的直接引用链定位。创建器默认生成在 `Assets/Landsong/ECSContent/Units/Soldier/militia/`，现有资源包可以在 Unity 中改名或移动：

- `militia.prefab`：正式士兵逻辑预制体，定义 `ECSContent/Definitions/Soldier/militia.asset` 已引用；不包含模型、骨骼或渲染器。
- `militiaView.prefab`：独立表现预制体，包含模型、Rukhanka Rig、Animator、右手短剑和左手灰盒火把；由逻辑预制体上的 `SoldierAnimationAuthoring.VisualPrefab` 引用。
- `militia.controller`：可直接在 Unity Animator 窗口编辑。
- `Clips/`：十个独立动作副本（含庆祝）；修改这些副本不影响原始 FBX。
- `Materials/`：身体使用 `Art/Shared/Shaders/SoldierAnimatedLit.shadergraph`，短剑使用普通 URP 材质。
- `Preview/SoldierAnimationPreview.unity`：可重复运行的原生 ECS 动画预览场景。

身体来自用户指定的 `Man_Soldier_Roman_Empire_Rig.prefab`，有效 Humanoid Avatar，1068 顶点、22 根骨骼、5 个材质。右手挂接同包 `Sword_Roman_Empire.prefab`，移除其 Collider，仅负责视觉；挂点名 `RightHandWeaponSocket`。短剑收起时直接隐藏，不创建腰间挂点。火把是无实时灯光和碰撞体的临时灰盒，正式资源可直接替换 `TorchMount` 子物体。

| 动作 | 原始资源 | 当前用途 |
| --- | --- | --- |
| Idle | HumanM@Idle01 | 待机循环 |
| Walk | HumanM@Walk01_Forward | 行走循环 |
| Run | HumanM@Run01_Forward | 奔跑循环 |
| MeleeAttack | Standing Melee Attack Downward | 单次近战挥击 |
| Hit | HumanM@IdleDamage01 | 有效受伤后的短暂反应 |
| Death | HumanM@Death01 | 死亡倒地，默认展示 1.5 秒后释放模型 |
| TorchWalk | 举火把 Standing Torch Walk Forward | 左手举火把巡视循环 |
| DrawSword | 拔剑 Withdrawing Sword | 从火把巡逻切换到持剑 |
| SheatheSword | 收剑 Sheathing Sword | 从持剑返回火把巡逻 |

控制器有 Base、Left Hand、Right Hand、Celebration Arms 四层，并为左右手分别生成 Avatar Mask。Base 负责待机、行走、警戒奔跑、拔剑、收剑、近战、受击和死亡；Left Hand 在火把状态覆盖举火把姿势；Right Hand 保留给武器姿势覆盖；Celebration Arms 使用双臂遮罩，在撤退庆祝时混合 Victory 动作。

Idle、Walk、Run 使用 `Speed`、`Alerted` 和 `LocomotionRate` 驱动。正常巡逻只走路；匹配当前警铃的 Rally 命令或感知到存活敌人时进入警戒奔跑，并有 2 秒释放延迟。敌人进入攻击距离加 1.5 米准备距离后触发拔剑；威胁消失 2 秒后触发收剑。拔剑开始立即隐藏火把，动作中点显示右手短剑；收剑中点隐藏短剑，动画完整结束后恢复火把。攻击信号在拔剑完成前排队，完成后只触发一次。

`Attack` 和 `Hit` 来自核心中瞬时递增的信号，`Dead` 来自生命/死亡状态。`AttackSpeed` 按原动画时长除以单位攻击间隔设置。死亡优先；同帧攻击与受击时优先攻击。攻击、受击、拔剑和收剑暂时使用全身动作。

## 操作入口

1. 从 `militia` Definition 的 `Prefab` 打开逻辑根，再沿 `SoldierAnimationAuthoring.VisualPrefab` 打开 View，最后从 Animator 打开 Controller。死亡展示时长和攻击动画原始时长在逻辑预制体上配置。
2. 菜单 **Landsong → 动画 → 运行动画预览**：进入独立场景。三行依次为待机 / 巡逻走路 / 警戒奔跑、攻击 / 受伤 / 死亡、举火把 / 拔剑 / 收剑。退出 Play 会恢复原场景；若当前场景未保存，先保存再启动预览。
3. 预览运行后，通过 **Landsong → 动画 → 预览数量** 切换 1 / 6 / 9 / 50 / 100 / 200 个单位，或通过 **聚焦动作** 近看举火把、拔剑和收剑。拔剑与收剑聚焦会以 0.25 倍速播放。
4. 菜单 **Landsong → 动画 → 验证罗马士兵接入**：验证正式地图烘焙、正常生成、战斗信号、暂停、死亡与清理。
5. 原“配置罗马士兵 / 拆分士兵逻辑与表现 / 配置士兵双臂庆祝”安装器已退役。日常调姿直接编辑已有引用；新单位使用临时创建窗口输入，不保存单位配方，也不重建 militia。

## 与玩法的边界

导航、避障、目标选择、伤害和奖励继续由已有 ECS / DBP 负责。动画系统在战斗组之后、Rukhanka 之前更新，逻辑根的位置不被动画修改。Animator 和 Rukhanka 均关闭 Root Motion。

`AnimatedUnitVisual` 留在逻辑实体，使 WorldPresentationView 跳过该单位的 GameObject 模型创建，避免重复显示。未接入的其他单位仍沿用已有表现。选择与指令仍指向原逻辑实体。

暂停冻结动画与倒地展示计时；平安夜 2×同步播放。减少动态效果会冻结骨骼动画。从未出勤的死亡单位不创建尸体模型。

正式单位通过创建/销毁表现控制出勤，不再生成后隐藏。独立预览的临时显隐仍使用 `DisableRendering`，保持 `MaterialMeshInfo` 启用。Rukhanka 2.9.1 的新网格注册依赖启用的 `MaterialMeshInfo`，而蒙皮任务仍会处理其余 SkinnedMeshRenderer；禁用前者会在尚未注册时触发 “not properly registered” 和 Burst 断言。

### 持久数据与按需表现

士兵的逻辑实体从招募开始就保存稳定 ID、姓名/肖像、经验、驻军槽位和生命等数据。招募不创建 Rig、骨骼、身体或武器渲染实体；白天管理与存档使用这个轻量逻辑实体。

当 `Combatant.Deployed` 与 `VisualState.Visible` 允许显示时，动画适配系统创建一次 `militiaView`，通过 ECS `Parent` 跟随逻辑根。归营完成后释放整个表现组；召回途中仍出勤，模型继续显示和行走。死亡时保留已有模型至展示时长结束，再释放。再次出勤创建新的表现实例，不重播未出勤期间的攻击/受击信号。当前直接实例化与销毁，尚未使用模型对象池；共享网格、材质和预制体资源仍可驻留内存。

表现实例拥有自己的 `LinkedEntityGroup`，不加入士兵逻辑根的组。`SoldierAnimationState.View` 记录当前实例，表现上的 `SoldierAnimationViewOwner` 指向士兵；删除士兵或读档替换后，动画系统会在 Rukhanka 更新前清理旧表现，即使所有士兵都已删除也会执行。表现根另持有同一会话的 `SimulationOwner`，切图沿用现有会话清理。武器与多材质派生渲染实体均包含在表现组内。

动画进度、信号和实例引用不进入玩法快照。读档成功后依据恢复出的出勤状态重建表现；同步读档事务失败时保留原实体和原模型。动画创建与释放不会改变存档字节或士兵身份、经验和驻军数据。

现阶段使用 **CPU 骨骼动画 + 插件 GPU 变形**，保留 22 根骨骼以支持普通右手挂件，尚未启用动画剔除或 LOD。这是功能基线，后续再按 Profiler 结果优化参数传递、骨骼保留、材质数量、阴影和远处更新。

## 验证与下一步

当前验证报告保存在 `Library/LandsongEcs/`，不提交生成日志：`soldier-animation-verification.txt`、`soldier-animation-preview-1.txt`、`-50.txt`、`-100.txt`、`-200.txt` 以及预览截图 `soldier-animation-preview.png`。测试也已加入 `ProjectVerification` 总入口。

动画接入检查现包含 55 项断言，覆盖真实地图烘焙、零模型驻军、重复出勤、身份保留、读档事务回滚/重建、警铃与敌情状态、拔剑/收剑装备显隐、攻击受击、暂停、死亡和最后一个士兵的清理。完整四场景 Play 验证包含实际 DBP 巡逻、召回、战斗、暂停、存档恢复和卸载清理；另验证原生动画士兵不会生成重复 GameObject 模型。报告为 `scene-flow-verification.txt`。

菜单 **Landsong → 动画 → 验证首次隐藏与显示 (Play)** 在新 Play World 验证 9 / 200 个角色生成后隐藏、显示、再次隐藏和显示，并检查所有蒙皮网格仍能被 Rukhanka 注册查询找到，同时收集实际渲染阶段异常。报告为 `soldier-animation-visibility-play.txt`；结束后自动恢复原场景。

菜单 **Landsong → 动画 → 验证按需创建与释放 (Play)** 使用 200 个轻量输入实体和真实动画适配器，验证 0 → 50 → 200 → 0 → 200 → 0 → 200 个表现的生命周期，以及最终会话清理。逐阶段检查 Rig、蒙皮网格、网格注册与父级位置跟随，同时收集实际 Rukhanka 渲染异常。该场景隔离玩法系统；正式士兵的 DBP、身份和存档由地图烘焙测试及四场景 Play 验证覆盖。报告为 `soldier-animation-lifecycle-play.txt`。

本轮仅在 Unity 编辑器中完成编译、ECS 断言、Play Mode 生命周期和实际 Rukhanka 变形验证，没有执行 Player 构建。

1 / 50 / 100 / 200 数量检查验证实体加载与动画状态播放；编辑器预览不代表 Android 帧率。尚未做 Android 真机、完整战斗场景的 GPU/CPU 预算或独立 Player 性能验收。

本次没有更改 `militia` 的攻击范围 4.5、攻击间隔 0.8 或 Projectile → DamageRequest 结算通路。因此目前是近战挥击表现，仍可能在原攻击距离出手；伤害/飞行物触发也尚未对齐挥刀命中帧。下一阶段应一起确定近战距离与动作接触时刻，避免只调整动画造成玩法变化。

射箭 FBX 已有，尚需弓、箭、持弓待机/移动与发射时刻配置；小偷潜行仍待资源到位后扩展。左右手分层基础已具备，盾牌动作与装备尚未配置。庆祝、救助和专用警戒动作也仍未接入。
