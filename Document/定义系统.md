# 定义系统与作者入口

更新日期：2026-09-20。本文对应按领域拆分后的实现。旧的 `GameDefinitionAsset`、`GameCatalogAsset`、`ContentKind`、通用 `Rule` 和全局内容索引已删除，不提供兼容入口。

## 数据归属

每一类内容拥有独立的 `XxxDefinitionAsset`、`XxxCatalogAsset`、`XxxCatalogCompiler`、`XxxCatalogBaker`，以及运行时 `XxxDefinition`、`XxxId`、`XxxCatalog` 和 `XxxDefinitions`。所有领域 Baker 共用唯一 `GameContentSetAuthoring`，不再为每个目录挂独立 MonoBehaviour。资产直接声明本领域字段，编译器直接接收对应资产；没有整份定义的 `XxxDefinitionSource` 包装，也没有 `Data` 字段或兼容属性。没有共同的 Definition 基类；公共名称、图标和稳定标识组合为 Metadata 值对象。Objectives、Rewards、Prerequisites、Capabilities 等组合保留各自业务含义。相同的字段必须有相同含义，不能用 Value、Range、Duration 在不同 Kind 中解释不同业务。

正式源目录保存在 `Assets/Landsong/ECSContent/Catalogs/Source`；由它们编译的界面显示数据保存在 `Catalogs/Generated/Display`。源文件名采用下表的类型前缀，例如 `TechnologyCatalog.asset`。

## 新增或修改内容

1. 在 Unity 的 **Create → Landsong → Definitions → 领域 → 类型** 创建对应资产，例如 `Research/Technology`。填写稳定 ID、名称和该领域的中文具名字段。引用框只接受明确的目标类型。
2. 把资产加入对应 CatalogAsset 的 Definitions 数组。独立定义 Inspector 提供注册按钮；不要通过文件夹扫描自动补齐注册。相同 ID 的另一个资产不能替代已注册资产引用。
3. 在 `Assets/Landsong/ECSContent/World/GameContentSet.asset` 登记目录；世界模板通过唯一的 `GameContentSetAuthoring` 引用该内容集。各域 Baker 只读取本域目录和明确的依赖目录。例如作物只读取作物和物品目录，建筑按其功能读取物品、科技、士兵、库存槽等目录。新增跨域字段时同步增加对应 Baker 的明确依赖，不能重新引入全目录 resolver。
4. 需要实体的建筑、士兵、英雄、敌军、弹体、访客和掉落定义必须配置 Prefab。Baker 将它们写入各域的 `XxxPrefab` Buffer，Entity 不写入 Blob，以便 Entities 正确重映射。
5. 修改显示信息后执行 **Landsong → ECS → Compile domain display catalogs**。显示目录各自从所属领域编译，UI 不读取 Authoring 资产。
6. 让脚本导入和 Baking 完成，运行相应编译与行为验证。正式构建由 `ReleaseContentValidation.ValidateCommon()` 依次调用 `DomainCatalogBuild.Validate()` 编译领域及世界配置、`DisplayCatalogBuild.Validate()` 检查显示同步、`ContentAuthoringValidation.ValidateCurrent()` 检查制作结构。

中文 LabelText 是字段含义的一部分。设置非空引用用 Required，数量约束使用 Odin 约束与编译校验共同表达。Inspector 的限制不能代替 Compiler 对非法值、未注册引用、越界数量、枚举和成长溢出的拒绝。

## 运行时读取与跨域引用

运行类型位于 `Scripts/ECS/Simulation/Definitions/<领域>`，作者类型位于 `Scripts/ECS/Authoring/Definitions/<领域>`。前者命名空间是 `Landsong.ECS.Definitions`，后者是 `Landsong.ECS.Authoring.Definitions`。

```csharp
TechnologyId id = TechnologyDefinitions.Find(em, root, stableId);
if (!TechnologyDefinitions.IsValid(em, root, id)) return;
ref var definition = ref TechnologyDefinitions.Get(em, root, id);
int researchCost = definition.ResearchPointCost;
```

所有领域都提供 Count、IsValid、Get、Find。ID 包装领域内 index + 1，default/None 为无效；支持本类型比较，没有 int 隐式转换。快照 v35 写领域内的 Index，并用 ContentFingerprint 绑定目录的稳定 ID、顺序与玩法配置；读取前先比较指纹，目录重排或玩法字段变化会拒绝旧快照。Entity、ulong 个体身份和 Definition ID 是不同概念。

`Id.ToString()` 显式包含领域和值，例如 `Technology:0`、`Quest:None`，用于调试与当前目录下的 UI 条目标识。它不代替配置中的稳定内容键，也不能脱离配置指纹用于跨版本持久化。

含 BlobArray 的记录依赖相对指针，Unity 的 Entities 分析器要求使用非 readonly 的 `ref`。Get 返回 mutable ref 是工具链约束，定义仍按只读使用；不要值拷贝含 BlobArray 的结构，也不要将其改为 `in` 或 `ref readonly`。结构变更会使实体 Buffer 引用失效，必须重新获取。

ECS 没有要求统一超级定义。系统需要什么领域就读取哪个目录；生命周期清理等系统只读取状态和所有者，不需要任何定义目录。世界模板组合全部玩法资源，不能据此让每个运行服务获得一个万能查询入口。

## 公共结构的边界

- 前置条件组合六种具名数组：BuildingRequirement、TechnologyRequirement、BuffRequirement、FeatureRequirement、QuestRequirement、ExpeditionRequirement。目标字段分别是本领域 ID，不能传任意内容整数。领域编译器还校验自己的可执行前置范围与循环，例如科技路径只递归科技前置。
- 奖励只有 ItemAmount、BlueprintGrant、BuffGrant、FeatureGrant 四类具名数组。任务目标另用建造、种植、持有物品、提交物品、科技、镜头移动、镜头缩放、回合等专用记录；不嵌旧 Rule 数组。
- 任务 ItemQuantityScale 在编译时对持有/提交目标、物品奖励和失败扣罚各缩放一次，并采用 math.round。运行奖励不再次缩放同一个配置倍率。
- DefinitionEffects 按受影响的物品、建筑、士兵、英雄、人才、王国、情报和固定产出分类。EffectAuthoringBoundary 继续限制拥有者与效果能力；科技不能配置没有执行者的经济收益，岗位不能配置情报等效果。通用 Effect 枚举本身不授予任何新能力。
- TalentJobEffects 只描述被动岗位效果；TalentPeriodicIncome 只属于人才。受益 Item/Soldier/Hero 与用于计数的 SourceItem/SourceBuilding 独立配置，避免一个 Target 承担两种含义。
- 建筑功能组合在 BuildingDefinition.Capabilities 内，每个功能有自己的类型和 Enabled。禁用功能编译为空数组；启用功能继续校验等级区间、用工、产出和容量。建筑军事加成归入 Garrison/Defence 的具名数据，不通过通用 Rule 查询。
- Order 数组稳定排序，相同 Order 保留源列表顺序。奖励先结算物品再结算许可；不要因为拆成多个数组改变随机数、扣费或同批增益的生效时机。任务目标 Key 是稳定进度身份，不能用数组下标替代。

## 世界设置和初始状态

`GameContentSet.asset` 集中保存全部领域 CatalogAsset 的制作引用，世界模板只引用该内容集一次。各域 Baker 仍单独编译自己的强类型 Blob，运行时没有统一内容查询表。`GameWorldTemplateAuthoring` 创建通用模拟根；`GameWorldMapAuthoring` 保存地图、王朝名称、基础人口和种子，并编译初始建筑与网格。NightSettings、IntelligenceSettings、RoyalFamilySettings、TalentSettings、QuestGenerationSettings、ExpeditionSettings、CourtSettings、NightRules、PeacefulRules 各有独立 Authoring 与校验；货币由 CurrencyAuthoring 将明确的 ItemDefinitionAsset 编译为 CurrencySettings.Gold。它们没有合并为新的 GameSettings 大结构。

开局发放由 StartingRewardsAuthoring 编译；初始王室、肖像、夜晚事件由各自 Authoring 负责。所有地图由地图工作流自动组合唯一的 `GameWorldTemplate.prefab`，地图资产不能另选流程模板；全局昼夜流程与归营参数由该模板引用的 `GameContentSet.asset` 统一持有。新增设置应归到其真正消费者所属的领域；新增可变状态不能混进只读 Settings，也不能不断扩充 Session。

## 新增领域能力

改动应形成完整链路：资产直接声明的具名字段及语义组合与中文 Inspector → 明确类型的运行记录 → 所属领域 Compiler 和校验 → 明确消费者 → 内容指纹与存档处理 → 行为回归。嵌套组合可使用具名 Source 数据类型，但不能重新引入整份定义的包装层。跨域关系优先使用目标领域 DefinitionAsset/Id；需要多种目标时拆成数种具名记录。不要添加 Kind + Value/A/B/Target 的万能载荷。

新增领域时建立独立资产、目录、ID、Blob、索引、查询服务和 CatalogBaker，把目录登记到 `GameContentSet.asset`；世界模板不再增加目录 Authoring 组件。显示需求交给本域 DisplayCatalog。请求使用独立 `IGameRequest` 结构，队列只保存路由元数据和 payload Entity。不要让新领域依赖已删除的通用 Definition、Command 或 Sim 入口。

编译回归检查字段值、注册顺序、域类型、错误输入与禁用模块；运行回归检查行为与事务。例如新增奖励必须检查整批预检/回滚，新增周期收益必须检查可达等级区间和整数溢出，新增军事数据必须检查黄昏冻结。

## 存档与迁移证据

当前 SnapshotCodec 为 **v35**，ES3 RunArchive 封装为 **v4**。v35 编码领域内 ID 索引和独立状态，并以内容指纹绑定目录稳定 ID、顺序及玩法字段；v33/v34 设有字段迁移路径，但内容指纹不匹配时仍需新建王朝。保留定义 GUID 并不意味着旧存档可读。

定义迁移时的 185 项资产、GUID、领域内顺序及 408 个跨域引用保存在不可变历史基线，现已归档到 `Tools/RetiredMigrations/20260920/DomainDefinitionBaseline.json`，不再约束日常内容的数量或数值。日常 ContentCompilationVerification 按当前内容集编译各领域，核对当前身份、顺序和序列化，并在隔离副本中验证新增、调参与非法配置的拒绝。新增建筑、单位和科技不需要修改历史基线；新增内容仍受目录合法性、行为回归、显示同步和存档指纹规则约束。

历史验收源码与复核方式见 [迁移证据归档说明](<../Tools/RetiredMigrations/20260920/README.md>)。Library/LandsongEcs/DomainRewrite 中的 definition-schema.json、asset-migration.json、asset-static-audit.json 是本机迁移审计产物，不是运行时依赖。源码与正式资产才是后续制作入口。
