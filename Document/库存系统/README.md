# 库存

库存以来源建筑稳定 ID + 槽身份保存；建筑自定义名称只影响显示。`UI_GamePanel_库存.prefab` 提供按建筑、按资源两种模式，待存区独立显示。建筑条目展示真实槽位，支持定位和本会话置顶；改名或置顶不改变库存归属。资源条目汇总可用库存，并单列待存数量。空槽建筑也保留条目。

## 整理

白天且拥有 Inventory 许可时，建筑模式可在不同建筑槽位之间拖动整堆，也可将建筑物资拖到待存区（包括空白区域），或从待存区拖回建筑槽位。底栏提供选数量拆分、移到待存区、同物品合并、不同物品整堆交换、确认丢弃及整理。非法目标、规则不接纳、容量不足或过期请求不部分执行。夜晚只读。

建筑移出到待存区使用 `InventoryLayoutRequest` 的 `MoveInventoryToPending` 动作；数量与累计小数损耗按比例一起转移，同类待存物资合并。该操作不能抢救已荒废锁定的库存，也不能绕开待存区的用途和入夜清空规则。一键入库与其他布局命令一样核验显示时的库存指纹，容量不足的余量仍留在待存区。

`StorageSlotDefinition.AcceptedItems` 和 `AcceptedGroups` 分别以 `ItemId` / `ItemGroupId` 限定物品与物品组，两者取并集；未配置则不限。库存自动分配优先低损耗槽，同条件按稳定身份。空槽或缩容不靠 UI 排序重编号；容量变化、荒废锁定和实际支付使用同一套规则。

## 消耗与损失

- 普通建造/生产/吃饭/招工/任务从正常库存消费；内部搬运不产生经济收入或支出。
- 修复优先待存放，剩余正常库存需资源连接；提供点只决定连接与市场归因。
- 物品/槽型、维护、缺工和 Buff 共同决定损耗，保存小数余量，拆分/合并不能凭空减少损耗。
- 荒废建筑库存全部损失，不转移到其他仓库；实时锁定，黎明统一删除来源槽并结算。
- 特殊掉落与夜间收益不遗漏，黎明容量不足进入待存放池，下一夜前清空；入夜确认具名列出实际将清空物资。
- 待存放不是无限仓库，不能用于普通任务提交、吃饭和招聘。手动丢弃有确认和来源历史。

账本区分正常库存、待存放、资源收入/支出/损耗和实际来源。白天参考预测不剧透随机收益，详见 [经济与岗位](../建筑系统/经济与岗位.md)。

资源条目显示“资源名 库存量（本回合预计净增减）”，例如“石头 300（-30）”；库存量只含已入库可用物资，待存区独立显示。点击 `btn_详情` 打开“资源详情子面板”，左右两个独立滚动区分别显示本回合预计产出、消耗及来源，消耗包含自然损耗。预测按当前白天条件自动计算，库存、建筑、岗位等状态改变时失效并刷新，不修改正式库存、随机数或历史。正在计算及本回合已结算有明确状态；随机收益、白天手动操作和入夜待存区清空不纳入预测。打开详情阻止底层游戏操作，但允许只读预测刷新；Esc 优先关闭详情。

“账单记录”进入按回合分组的账单面板，五列为资源名、产出、消耗、净量、库存。产出统计实际资源流入（含税收、奖励），消耗统计实际流出（含损耗与已确认的入夜清空），转库不计收支。库存列是该回合结算后的可用已入库数量，不随后续操作改变。历史账单由 ECS `EconomyBillEntry` 保存，当前 v33 存档持久化；开发期间不读取或补算旧格式数据。

库存变更使用 InventoryTransaction 保存库存槽、待存放池及经济账本/追加资源历史的起始长度；失败恢复资源数组并截去本次追加记录。涉及许可、研究或合并消息时使用领域奖励事务扩展捕获，不把完整会话状态塞进库存事务。手动采集和士兵/英雄招募等不能只退还物品而遗留“已消耗/已获得”历史；重复失败也不得累积记录。历史的转库标记由命令种类决定，不从中文原因文字推断。

## 代码职责与请求

运行代码位于 `Assets/Landsong/Scripts/ECS/Simulation/Inventory`：

| 类型 | 职责 |
| --- | --- |
| `InventoryOps` | `Count/Add/Remove/PendingCount/RemoveWithPending`，物品参数为 `ItemId` |
| `ItemGroups` | 物品与组的从属匹配 |
| `InventoryStorage` | 接纳条件、共享损耗率、存入和消费顺序 |
| `InventoryProviders` | 按建筑仓储能力创建、调整、删除稳定槽位 |
| `InventoryLayout` | 显示指纹、槽位操作、排序与全部待存入库 |
| `InventoryDecay` | 日结自然损耗 |
| `InventoryPayments` | 对明确的 `ItemAmount` 列表支付 |
| `InventoryTransaction` | 资源与账本、历史的原子回滚 |

`InventorySlot.Item` 为 `ItemId`，`SlotType` 为 `StorageSlotId`；无物品或无限定槽型使用对应的 `None`。`InventorySelection` 仅是只读选择 DTO。界面通过 `GameplayRequests.Enqueue` 提交 `InventoryLayoutRequest`，显式携带动作、来源/目标 Provider 与槽号、ItemId、数量、ExpectedInventory；不把 UI 行号或万能命令字段当协议。
