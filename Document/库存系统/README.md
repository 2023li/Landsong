# 库存

库存以来源建筑稳定 ID + 槽身份保存；建筑自定义名称只影响显示。槽位显示来源建筑名、槽型、物品、数量和荒废锁定状态，可定位来源。改名不改变库存归属。

## 整理

白天且拥有 Inventory 许可时，可拖动整堆、选数量拆分、同物品合并、不同物品整堆交换、指定空格存放待存放物资、确认丢弃。非法目标、规则不接纳、容量不足或过期请求不部分执行。夜晚只读。

槽型可用 SlotAccept 限定物品/物品组，多条取并集；未配置则不限。库存自动分配优先低损耗槽，同条件按稳定身份。空槽或缩容不靠 UI 排序重编号；容量变化、荒废锁定和实际支付使用同一套规则。

## 消耗与损失

- 普通建造/生产/吃饭/招工/任务从正常库存消费；内部搬运不产生经济收入或支出。
- 修复优先待存放，剩余正常库存需资源连接；提供点只决定连接与市场归因。
- 物品/槽型、维护、缺工和 Buff 共同决定损耗，保存小数余量，拆分/合并不能凭空减少损耗。
- 荒废建筑库存全部损失，不转移到其他仓库；实时锁定，黎明统一删除来源槽并结算。
- 特殊掉落与夜间收益不遗漏，黎明容量不足进入待存放池，下一夜前清空；入夜确认具名列出实际将清空物资。
- 待存放不是无限仓库，不能用于普通任务提交、吃饭和招聘。手动丢弃有确认和来源历史。

账本区分正常库存、待存放、资源收入/支出/损耗和实际来源。白天参考预测不剧透随机收益，详见 [经济与岗位](../建筑系统/经济与岗位.md)。

库存变更使用 InventoryTransaction 同时保存库存槽、待存放池、经济账本、历史和相关上下文；失败恢复它们的值及原先是否存在。手动采集和士兵/英雄招募等不能只退还物品而遗留“已消耗/已获得”历史；重复失败也不得累积记录。历史的转库标记由命令种类决定，不从中文原因文字推断。
