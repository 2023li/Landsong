# 运行与存档

格式：**快照 v22 / 王朝封装 v3**。Building.SubsidyBudget 持久保存每回合补贴预算，与已付金额/回合分开；恢复校验预算非负且不超过该级岗位容量，修改未来预算不会抹去已付效果。PersonRequestEntry 保存远征愿望的创建/解决回合、待安排/在途/完成/拒绝/取消状态和队伍 ID，参与实体快照往返与失败回滚；校验状态、回合、重复待办和队长/在途队伍对应关系。每人最多保留 16 条远征请求记录，赐婚和个人委托直接读取原权威状态，不复制成第二份待办。Royal 保存性别、登基历史及赐婚请求、请求时君王、回合和冷却字段，随人物 Capture / Decode / Restore 和事务恢复。初始王室性别配置纳入内容签名，解码校验运行人物性别枚举；主动赐婚准备的候选也是持久人物。旧版快照按现有版本检查拒绝加载，原文件不修改；本轮玩法变更需要新开王朝。存档绑定地图和玩法内容签名；赐婚概率等 Court 配置纳入签名，名称/显示布局等纯表现配置不充当运行状态。

## 三类记录

| 记录 | 内容 |
| --- | --- |
| 白天开始节点 | 回合开始、当夜基础计划已锁定的状态 |
| 黄昏节点 | 白天结算与当夜军事准备完成、实时夜晚开始前的状态 |
| 手动存档槽 | 白天当前可操作状态，连同对应的原始节点 |

新王朝、白天开始和黄昏节点自动持久化。手动保存创建独立槽；快速保存覆盖当前手动槽，不替换原始白天/黄昏节点。夜晚不保存逐帧战斗，退出后继续从本夜起点进行；白天未保存的后续操作不会因此自动保存。

文件根为 `Application.persistentDataPath/ECS`，王朝主封装为 `runs/<RunId>/state.lsrun`，最近王朝由 active-run.txt 记录。主菜单可跨王朝浏览，暂停菜单管理槽名称、缩略图、覆盖/删除及备份恢复。创建新王朝不覆盖其他王朝。

## 终局与回退

PlayerHome 失守触发终局。玩家可回到当回合白天开始或黄昏；同次终局只生成一次恢复票据，新种子更新当夜编成/位置并降低当夜预算。原始回合战力、事件和 Boss 身份保持；下一回合恢复正常预算规则。不显示重试次数、种子或降难比例。

同王朝、同回合的最高已知情报保留到本回合结束，旧已读指纹不能覆盖新报告。回退清除被撤销夜晚的未提交奖励、战报和消息，费用、人口、经验随节点恢复，不保留被撤销战斗收益。

君王必须继承时完全没有在世直系后代则绝嗣。绝嗣不可用夜晚重试绕过，即使没有黄昏节点也能持久保存终局。只有确认“结束王朝”才写入覆灭记录并删除该王朝受管存档，保留历史、不影响其他王朝。

## 安全契约

- 保存先写临时文件、刷盘，再原子替换并保留备份；摘要、版本、归属、地图、内容和全部嵌入节点都要校验。
- 正式文件损坏仅接受同归属备份，后续写入前保留损坏副本。写入失败锁定阶段并提示。
- 删除/覆盖/重命名绑定 RunId、SlotId 和内容指纹。删除槽只删除自己的主文件、备份、名称、缩略图和受管损坏副本，不删除自动节点。
- 结束王朝先创建覆灭墓碑，再清理该王朝受管文件；墓碑阻止副本重新载入。未知文件不纳入删除。
- RestoreTransaction 保留原实体至候选重建与准备成功，再同步提交；失败撤销根、Buffer、临时战场和节点归属。
- 任务要求仅在稳定 Key、目标、数量和其他规则不变时允许换序映射进度，不意味着通用跨内容版本热更新。

入夜损失清单来自可回滚预演，不是保存点；确认成功才提交白天结算和黄昏节点。文件故障测试使用 Library/LandsongEcs/VerificationRuns 的独立 GUID 目录，不操作玩家正式文件。

## 肖像与士兵个人记录（v22）

人物 PortraitDNA 保存稳定部件 ID、肤色/发色/眼睛基础 RGB、随机种子、丽质是否已使用和是否已通知；士兵另存性别、年龄、寿命、换人次数、最后年龄结算回合、玩家命名标记和死亡通知标记。恢复按性别/部件类型、必需部件、颜色、年龄、标记和实体归属校验，失败仍走原事务回滚。v20 及更早快照拒绝加载，需要新开王朝，原文件不改写。

年龄和颜色遗传、士兵招募年龄与寿命配置进入玩法内容签名；像素素材和 UI Sprite/Texture 缓存不进入快照。修改相同稳定 ID 下的美术可更新表现；删除或改名已被存档使用的部件会使该存档校验失败，不能把部件 ID 当作可随意调整的数组下标。恢复不重新随机肖像，也不重新给予已用掉的捏脸机会。

任务 Quest 保存承接容器 Container 和 ContainerSlot，与原始邀约 Source / Slot 分开；主线和一般任务共用非负槽号。解码对所有进行中和待领奖任务验证容器存在、槽位配置上界及重复占位；已领奖历史记录不再绑定容器。分步任务领奖后将原容器、槽号及邀约来源交给下一步，只有任务链结束才释放；额外前置未满足的步骤以 Active、StartTurn=0、Deadline=0 保留原槽，条件满足后开始计时。完成待领奖仍占槽；容器失效引起的任务移除和处罚参与事务回滚。

本次通用任务槽调整未新增快照字段，格式仍为 v22；皇宫 QuestCapacity 从 3 调为 4 改变内容签名，因此调整前的存档需要新开王朝，不能将格式版本相同视为内容兼容。

任务追踪沿用 QuestTracking：Mode 0 为自动续接 / 价值选择、1 为手动选择、2 为明确不追踪；Target 保存当前目标。自动模式不在定期刷新时重选仍然有效的目标，成功领奖当前目标后才选择直接后续或最高价值已接受任务。本次 HUD / Toggle 调整未新增持久字段，快照仍为 v22。
