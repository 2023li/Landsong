# 运行与存档

新快照写入 **v24**，王朝封装保持 **v3**。格式版本与玩法内容签名分别校验；版本相同不代表内容兼容，UI 重构也不会把所有旧存档一律拒绝。

## 协议与兼容

| 输入 | 处理方式 |
| --- | --- |
| 快照 v24 | SnapshotBinaryV24 按固定字段顺序逐项读取、写入，使用完整玩法签名 |
| 快照 v23 | LegacySnapshotBinaryV23 使用冻结的旧布局读取并映射到当前状态，验证原 v23 签名 |
| 快照 v22 | 使用冻结布局及旧签名；旧士兵命名标记清零为未关注，其他合法记录保留 |
| v21 及更早、未知版本、错误地图或签名不符 | 明确拒绝，原文件不改写 |
| 王朝 v3 | 校验封装、摘要、归属与全部嵌入节点；每个快照按自己的版本解码 |

v24 不再拷贝当前运行结构体的原始内存。编码器明确声明基础类型、枚举、字符串、定长列表和每个结构字段的表示与顺序；ValidateFieldCoverage 检查登记类型的全部公开字段，新增字段不能静默遗漏。持久 DTO 只存在于 I/O 边界，不是第二套运行状态。持久关系使用稳定内容 ID 与个体 ID，临时 Entity 引用在保存时清空或恢复时重建。

旧读取器的字段、对齐和定长容器布局已经冻结，不能随当前组件增字段，也不能遇到错误后猜测另一种格式。旧签名只证明旧版本实际记录过的规则；旧版遗漏的全局设置无法追溯补验。读入旧文件本身不改写文件，后续正常保存生成 v24 节点。一个 v3 王朝可以同时保留旧自动节点与新手动节点，不强制重写原始白天/黄昏记录。

v24 签名覆盖完整 GameSettings、地图格数据及原点/尺度/边界、出生区域、王朝与肖像遗传设置、昼夜/宫廷/任务/远征规则，以及开局王室、建筑和发放记录。定义显示名称、初始人物/建筑名称、默认皮肤和建筑菜单顺序不进入新版玩法签名。修改表现资源仍须保留被存档引用的稳定 ID。任务要求只在 Key、目标、数量及其他规则不变时允许换序映射进度，不提供通用跨内容版本热更新。

真实旧版金样本位于 `Assets/Landsong/Scripts/Editor/Tests/Verification/Fixtures/Persistence`：两张地图的原始 v23/v3 文件由重构前已编译程序集产生，并保留原始字节与 SHA-256。它们不是把 v24 文件修改版本号得到的样本，也不是玩家存档。内容有意改变后不能重生成这些样本来消除失败，须先审查兼容策略；来源与哈希见该目录 README。

## 三类记录

| 记录 | 内容 |
| --- | --- |
| 白天开始节点 | 回合开始、当夜基础计划已锁定的状态 |
| 黄昏节点 | 白天结算与当夜军事准备完成、实时夜晚开始前的状态 |
| 手动存档槽 | 白天当前可操作状态，连同对应的原始节点 |

新王朝、白天开始和黄昏节点自动持久化。手动保存创建独立槽；快速保存覆盖当前手动槽，不替换原始白天/黄昏节点。夜晚不保存逐帧战斗，退出后继续从本夜起点进行；白天未保存的后续操作不会因此自动保存。

文件根为 `Application.persistentDataPath/ECS`，王朝主封装为 `runs/<RunId>/state.lsrun`，最近王朝由 `active-run.txt` 记录。创建新王朝不覆盖其他王朝。

## 共用存档界面与权限

Start 与 Game 打开同一套 UI_SavePanel。视图负责选择和显示，ArchiveApplicationService 负责权限、文件操作与确认失效检查，CheckpointSystem 负责当前 ECS 会话的存取事务。

- Load 模式可跨王朝浏览、载入，并管理独立槽的名称/删除；不能创建或覆盖玩法状态。
- Save 模式显式绑定当前 RunId、存储对象、会话有效性、白天写入能力及执行回调；不能读取或改写其他王朝的槽。夜晚或写入锁定时不得保存、载入或管理槽。
- 自动节点可以选择载入或备份恢复，不能作为独立槽覆盖、重命名或删除。
- 覆盖、删除、改名和载入确认均校验原对象及内容指纹；主封装与备份、独立槽内容改变，即使长度和修改时间相同，旧确认也必须失效。会话结束后旧面板请求失效。

## 终局与回退

PlayerHome 失守触发终局。玩家可回到当回合白天开始或黄昏；同次终局只生成一次恢复票据，新种子更新当夜编成/位置并降低当夜预算。原始回合战力、事件和 Boss 身份保持；下一回合恢复正常预算规则。不显示重试次数、种子或降难比例。

同王朝、同回合的最高已知情报保留到本回合结束，旧已读指纹不能覆盖新报告。回退清除被撤销夜晚的未提交奖励、战报和消息，费用、人口、经验随节点恢复，不保留被撤销战斗收益。

君王必须继承时完全没有在世直系后代则绝嗣。绝嗣不可用夜晚重试绕过，即使没有黄昏节点也能持久保存终局。只有确认“结束王朝”才写入覆灭记录并删除该王朝受管存档，保留历史、不影响其他王朝。

## 事务与文件安全

- 保存先写临时文件、刷盘，再原子替换并保留备份；摘要、版本、归属、地图、内容和全部嵌入节点都要校验。
- 正式文件损坏仅接受同归属备份，后续写入前保留损坏副本。写入失败锁定阶段并提示。
- 删除槽只删除指定王朝/槽的主文件、备份、名称、缩略图和受管损坏副本，不删除自动节点。
- 结束王朝先创建覆灭墓碑，再清理该王朝受管文件；墓碑阻止副本重新载入。未知文件不纳入删除。
- RestoreTransaction 同步执行，保留原实体至候选重建与准备成功，再提交；失败撤销根、Buffer、临时战场和节点归属。根上的 Landsong 类型必须登记为可变捕获或明确只读配置，未登记类型在候选创建前拒绝。
- InventoryTransaction 撤销库存、待存放、账本、历史及原先不存在的附加状态。手动采集、士兵/英雄招募、英雄唤醒和夜晚奖励提交失败不得留下费用、奖励或虚假历史；英雄出场准备还恢复临时战斗、导航与战术组件。

入夜损失清单来自可回滚预演，不是保存点；确认成功才提交白天结算和黄昏节点。GameEvent 自带历史类别，手动库存事务记录命令种类，分类不依赖中文原因文本。

## 持久玩法字段

Building.SubsidyBudget 保存每回合补贴预算，与已付金额/回合分开；恢复校验预算非负且不超过该级岗位容量，修改未来预算不会抹去已付效果。

PersonRequestEntry 保存远征愿望的创建/解决回合、待安排/在途/完成/拒绝/取消状态和队伍 ID；校验状态、回合、重复待办与队长/在途队伍关系。每人最多 16 条记录，赐婚和个人委托仍读取各自权威状态。Royal 保存性别、登基历史及赐婚请求、请求时君王、回合和冷却字段；主动赐婚候选也是持久人物。

PortraitDNA 保存稳定部件 ID、肤色/发色/眼睛基础 RGB、随机种子、丽质是否已使用和通知状态；SoldierPerson 保存性别、年龄、寿命、换人次数、年龄结算回合、特别关注和死亡通知标记。恢复按类型/性别、必需部件、颜色、年龄、标记与归属校验，不重新随机肖像，也不重新给予捏脸机会。更换相同稳定 ID 的像素素材可以更新表现，删除或改名已被存档使用的部件会使校验失败。v22 只清除旧命名标记，DeathNotified 保留以避免重复通知。

Quest 的承接容器 Container/ContainerSlot 与邀约 Source/Slot 分开。进行中和待领奖任务必须满足容器存在、槽号上界与唯一占位；已领奖历史不再绑定容器。分步任务领取后继承原容器、槽号和邀约来源，整条任务链结束才释放；等待额外前置时以 Active、StartTurn=0、Deadline=0 保留原槽。容器失效造成的任务移除与处罚参与事务回滚。

QuestTracking.Mode 为 0 自动选择、1 手动选择、2 明确不追踪，Target 保存目标。自动模式不在定期刷新时重选有效目标，成功领取当前任务后才选择直接后续或最高价值的已接受任务。建筑 Modules 编译后的规则、初始驻军、任务容量等属于玩法签名；格式版本不代替它们的兼容检查。

## 验证入口

ProjectVerification 统一运行 PersistenceContractVerification 与 ArchiveApplicationServiceVerification，分别输出 `persistence-contract-verification.txt` 和 `archive-application-service-verification.txt`。协议检查包含真实 v23/v3 金样本、冻结旧布局往返、v24 再保存、全部 GameSettings 字段签名、网格几何及未登记根状态；服务检查覆盖模式权限、跨王朝拒绝、失效会话和过期确认。

领域故障用例使用系统临时目录或 `Library/LandsongEcs/VerificationRuns` 下的独立 GUID 目录，不操作玩家正式文件。旧金样本是提交的固定夹具；测试日志、临时存档与截图是本机可再生结果。实际执行日期与结论见 [验证工作流](../ECS/验证工作流.md) 和 [重构执行记录](../重构执行记录.md)。
