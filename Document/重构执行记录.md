## 已实施的结构

- `Scripts/Application` 拥有启动安装、场景切换和会话装配。`ApplicationUiRoot` 在常驻 `UI_Root.prefab` 上组合 Moyo 管理器与应用服务；`GameApplicationFlow` 负责异步加载、取消、恢复、错误清理和返回菜单。
- `Scripts/UI` 按 `BootPanel`、`StartPanel`、`LoadingPanel`、`SettingPanel`、`SavePanel`、`ConfirmPanel`、`GamePanel`、`Common` 组织。根控制脚本、对应 Prefab 与 Addressables 描述资产同名；开局弹窗属于 StartPanel，科技/建筑/人才等属于 GamePanel。
- 应用根只有一个 Canvas 和 EventSystem。设置、存档、确认等应用级面板缓存后复用；Game 面板属于会话作用域，离开会话时销毁并解绑 ECS、相机、世界模型、回调和条目池。
- `ArchiveApplicationService` 统一存档操作，加载、保存和管理模式保留权限差异；确认前重新校验 RunId、SlotId 和文件指纹，不让 UI 文案承担权限判断。
- `Scripts/Presentation` 保留跨层契约、视听与世界表现。`UI_GamePanel_WorldInteraction` 是 GamePanel 使用的交互适配器，留在 UI 程序集的 `Interaction` 子目录；它通过显式会话绑定访问世界表现，没有再建一个相互引用的 Input 程序集。
- Game 主界面不再由旧 `EcsGameView` 分部类组织。领域组件各自实现展示器，9 类条目模板携带本领域控件，固定引用在 Prefab 中配置；没有运行时找组件或补建缺失控件的正常路径。
- Inspector 字段使用中文 Odin 标签。编辑示例由 Profile/Recipe 和 `UIPreviewOnly` 管理，序列化到 Prefab 后可以直接预览；运行创建前禁用示例并恢复初始文本。

### 集成阶段发现并修复的问题

- 七个根面板的 RectTransform 曾保留旧独立 Canvas 的像素尺寸、锚点或缩放，编辑预览的临时布局归一化掩盖了挂到真实 Canvas 后的错误。现由 [UiPanelLayoutAuthoring](../Assets/Landsong/Scripts/Editor/UI/UiPanelLayoutAuthoring.cs) 修正正式资产；检查同时覆盖原始 Prefab 配置（raw）、预览挂载实例（mounted）和实际应用 Canvas 内的边界（actual bounds）。预览必须接受资源配置检查，不能临时修好画面后把错误资产当作通过。
- 王室面板首帧未正确激活家谱。已在 [UI_GamePanel_Court](../Assets/Landsong/Scripts/UI/GamePanel/UI_GamePanel_Court.cs) 的真实显示路径同步 `CourtGraph` 激活状态，避免仅有数据刷新而视图仍隐藏。
- 王室相关 6 处、建筑相关 2 处零宽布局已修复为正式资产配置；普通功能区 `FeatureRoot` 通过 [FeaturePanelLayoutAuthoring](../Assets/Landsong/Scripts/Editor/UI/FeaturePanelLayoutAuthoring.cs) 为固定 HUD 底栏保留 56 个画布单位的底部空间，并由 UI 配置检查持续验证。上述资源修复的专项运行验收仍按表中分项结果记录。
- 赐婚 3 个、塑容 2 个底部按钮在真实布局中也会变成零宽：布局组即使不控制宽度，仍会驱动子节点锚点。已修为受控等宽按钮，并移除配置检查中错误的“拉伸锚点豁免”；150% 缩放编辑预览与实际专项均通过。
- 士兵详情原先只有 Image，没有肖像绑定。现由 [UI_GamePanel_SoldierDetails](../Assets/Landsong/Scripts/UI/GamePanel/UI_GamePanel_SoldierDetails.cs) 明确引用绑定组件、目标图片和同一 PortraitCache，按人物 ID 展示实际肖像；关闭和解绑时清除缓存租约、人物与世界引用。新增示例被显式标记并由所属视图清理，不能留在真实会话中。
- 任务关闭按钮的旧导航属性依赖首次内容刷新才赋值，且重复注册监听。已删除该遗留属性，直接使用预制体中由功能窗口初始化绑定的关闭按钮；实际首开后立即关闭用例通过。
