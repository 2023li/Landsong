# 建筑创建与制作流程

本页是当前建筑创建与模型维护入口。定义 `Footprint` 决定占格，完整根 Prefab 提供 Baking 与放置预览，槽位决定等级/皮肤/阶段的模型。制作工具统一读取世界模板引用的 `GameContentSet`。

## 从空白创建建筑

下面以“科研小屋”为演练示例：占地 1×1，最高二级，一级每回合产出 3 科研点，二级产出 7 科研点。这些是示例配置，不是已加入游戏的正式建筑。

### 步骤 1：创建建筑

等待 Unity 编译和导入完成，退出 Play，打开 **Landsong → 内容制作 → 创建建筑**。填写：

| 字段 | 示例 |
| --- | --- |
| 稳定 ID | `building.research_hut` |
| 显示名称 | 科研小屋 |

点击“创建并注册建筑”。创建器会选择新定义，并登记正式内容集的 Buildings 目录。后续保持 ID 稳定，不同建筑不能使用相同 ID。

### 步骤 2：确认生成的文件

创建器自动建立所需目录和文件，无须先手工创建空 Prefab。相对项目根目录，示例产物为：

```text
Assets/Landsong/ECSContent/
├── Definitions/Building/building.research_hut.asset
└── Buildings/building.research_hut/
    ├── building.research_hut.prefab
    └── Materials/Placeholder.mat
```

定义与完整根互相引用；根已包含 `SelectionAnchor`、一级运营槽、`Content`、可见占位模型、Renderer Owner 和放置预览绑定。生成后先保留这套接线，后续在槽位中替换模型。

### 步骤 3：填写建筑功能和数值

选择新定义，在 Inspector 配置以下示例字段：

| 字段 | 示例值 | 作用 |
| --- | --- | --- |
| 占地尺寸 `Footprint` | X=1，Y=1 | 权威占格尺寸 |
| 最高等级 `MaximumLevel` | 2 | 允许升级到二级 |
| 施工回合 `ConstructionTurns` | 1 | 建造后所需施工回合 |
| 耐久上限 `MaximumDurability` | 100 | 示例基础耐久 |
| 建筑功能 → 科研 `Capabilities.Research.Enabled` | 启用 | 启用每回合科研产出 |
| 科研 `Levels` 第一行 | `Level=1`，`PointsPerTurn=3` | 一级运营产出 |
| 科研 `Levels` 第二行 | `Level=2`，`PointsPerTurn=7` | 二级运营产出 |
| 升级 `Capabilities.Upgrade.Enabled` | 启用 | 配置升级模块及所需条件 |

演练可使用空的建造/升级材料配置；正式制作时再填写设计需要的费用与限制。当前有 19 个具名功能组合，按需启用并配置等级记录。岗位模块还须填写覆盖全部工人数的 `EfficiencyTiers`，区间不得重叠、留空或跨越效果门槛。复用已有科研等功能时无需修改运行代码。

### 步骤 4：制作一级、二级模型

双击生成的完整根 Prefab 进入预制体编辑模式。在 `Operational_L1/Content` 下放入一级模型，移除被替换的占位模型，保留 `SelectionAnchor` 和槽位组件。

本例需要二级外观：复制一级槽，命名为 `Operational_L2`，把槽位 `Level` 改为 2，`Purpose` 保持 Operational，再在其 `Content` 下替换为二级模型。默认皮肤通常为空；两级的 `SkinId` 须与定义的默认皮肤一致。真实模型完成后关闭对应槽的 `Placeholder`；仍用占位模型时保留此标记。

所有槽位保持启用。选中完整根，在 Inspector 点击“补齐所有模型的 Baking 接线”，再点“检查建筑根与槽位结构”，然后保存 Prefab。接线按钮同时更新 Renderer Owner 和放置预览引用。定义的 `Prefab` 始终指向完整根。

普通静态建筑不需要另建 Animator 或动画控制器；动态动画、粒子或灯光按后文的动态表现说明接入。

### 步骤 5：让玩家获得建筑

选择一种明确的获得途径：世界初始奖励、科技或任务的 `Rewards.Blueprints`。例如按 [科技创建流程](../科技系统/README.md) 新建研究节点，在蓝图奖励中把 `Building` 指向新定义，`GrantedLevel` 设为 2。本例完成科技后，玩家可建造一级并获得升到二级的蓝图许可；奖励不会直接创建建筑。

玩家还须已获得全局 `feature.Building` 建造许可。仅注册目录不会自动授予蓝图、功能许可或资源。只授予一级蓝图时，即使 `MaximumLevel=2`，也不能升到二级。

### 步骤 6：保存、编译和校验

保存定义、奖励来源和 Prefab，执行 **Landsong → ECS → Compile domain display catalogs**，再执行 **Landsong → 内容制作 → 校验正式制作内容**。出现错误时根据控制台定位具体资产，修正后重跑。

新定义经 Entities Baking 生效；地图制作参数或初始摆放变化时，另按地图手册重新烘焙。正式内容编译与地图烘焙是各自的操作。

### 步骤 7：在游戏中完成验收

用新测试会话获得相应蓝图和建造许可，然后依次检查：放置预览可见、合法位置可建造、施工完成可选中、一级结算增加 3 科研点、升级到二级后切换外观、二级结算增加 7 科研点、保存再读取后等级和功能保留。核对科研点净增量时暂不排研究队列，避免产出在同回合被研究消耗；同时计入其他建筑的产出，或在隔离配置中只保留本例产出。

该建筑设计包含修复/荒废等行为时也要验证。运行 **Landsong → ECS → Verification → Content authoring workflow** 检查工具链，再按 [验证工作流](验证工作流.md) 跑相关领域回归。

重复“创建”同一 ID 只检查并打开同路径的已注册产物，保留 GUID、数值、模型和控制器等手工内容；不会将配方重新覆盖到资产。若 ID 被其他路径占用或存在未登记的同名文件，工具报错，须先明确资产归属。失败的首次创建会撤回本次新建资产，目录保持原样。

```text
<建筑根> BuildingVisualAuthoring + BuildingPlacementPreviewBinding
├── SelectionAnchor
├── Operational_L1 [BuildingVisualSlotAuthoring]
│   └── Content
│       └── 模型 [MeshRenderer + EntityVisualAuthoring.Owner → 根]
└── 可选的其他用途/等级/皮肤槽
```

已有建筑可保留跨等级共用的底座模型；它仍必须有正确 Owner，且明确登记为预览 Parts 中 `Slot=null` 的共享部件。新增模型或删除旧模型后必须更新接线，不能保留过期预览引用。

## 常见问题

| 现象 | 检查位置 |
| --- | --- |
| 已创建却不能建造 | 蓝图是否已实际发放、`feature.Building` 是否已解锁，以及费用、占地和建造条件 |
| 放置预览为空或残留旧模型 | 根的预览引用是否已在增删模型后补齐；对应槽是否有 MeshRenderer |
| 升级后还是旧模型 | 二级槽的 Level、Purpose、SkinId，以及是否有实际模型；缺模型时会回退到低等级外观 |
| 科研没有产出 | Research 是否启用、等级记录是否匹配、建筑是否完成施工并参与正常白天结算 |
| 修改名称或图标后界面没更新 | 是否保存并重新编译显示目录 |
| 创建按钮提示 ID 或文件已存在 | 确认是否为同路径的已注册产物；不删除 `.meta` 或重写旧资产来绕过冲突 |

## 配置不同建筑与等级模型

1. 在 `Assets/Landsong/ECSContent/Definitions/Building` 编辑各建筑定义。资产上的 `Prefab` 始终指向该建筑的完整根 Prefab，不要指向某个单等级模型。
2. 打开相应 `Assets/Landsong/ECSContent/Buildings/<稳定 ID>/<稳定 ID>.prefab`。根上是 `BuildingVisualAuthoring`，`ViewRoot` 下的每个外观分支挂 `BuildingVisualSlotAuthoring`；`Anchors/SelectionAnchor` 用于运行选择定位。
3. 槽位配置 Purpose、Level、Step、SkinId，把模型放到槽位的 Content 下。运营用 Operational；施工用 Construction；也可单独配置 Preview、Ruined、Repairing。Step=0 为通用，其他值对应施工期数。
4. 所有槽位保持启用，交给 Baking 和 ECS 选择可见模型。根 Inspector 的“预览”按钮只改变编辑器 Scene 可见性，不改对象启用状态；“显示全部编辑节点”恢复编辑可见性。
5. 在根 Inspector 点“补齐所有模型的 Baking 接线”，再点“检查建筑根与槽位结构”。新加 MeshRenderer 会挂 `EntityVisualAuthoring` 并把 Owner 指向建筑根，放置预览的 Parts/Slots 也会重建；美术导出会执行同一预览接线操作。保存 Prefab，等待 Baking 完成后运行。

模型选择先匹配皮肤和用途，再选不高于当前等级/进度的最新配置。空槽不遮掉已有低等级模型；修复可回退施工模型，荒废/施工缺专属模型可回退运营模型并呈废墟色。不自动使用另一皮肤。缺少精细模型时仍明确标记 Placeholder，不表示该等级美术已完成。

仓库提供 LV1/LV2/LV3 模型；部分建筑或皮肤仍用明确标记的 Cube 占位。静态模型和 LOD 通过 Baking 使用；动画、粒子和灯光通过可选动态表现接入。

### 美术导出

使用 `LS_BuildingViewOptimizer` 导出。命名配置中的同步开关表示“同步对应等级/施工槽位”，覆盖对应槽位，不把整个建筑根替换成单等级 Prefab。每次覆盖槽位前备份到 `Backups/BuildingVisualExport_*`。静态 LOD 保留；动画、粒子、灯光使用 [动态表现绑定](../音频与本地化/表现与语言制作.md)。

### 农田与有限资源堆

农田保留可编辑的空种植点和单株作物阶段配置。在 `BuildingCropVisualController` Inspector 点击“同步点位与生长阶段到 ECS 建筑表现”，会生成同级 `_ECS_Crop_Renderers` 节点，再由正常 Baking 转为实体。编辑点位/作物阶段后需再次同步并保存 Prefab。生成节点可重建，不手工编辑。

运行时依据 Crop ID、CropProgress 和持续保存的建筑状态切换阶段；未种植、清除、收获重置、荒废会相应隐藏/切换。当前固定选取前 N 个点，不做每次播种随机换点。小土堆/小石堆以 `BuildingVisualPartAuthoring.HarvestRemaining` 控制剩余阶段外观；通用阶段值为 0。

## 验证

保存前检查所有槽位用途、等级、皮肤、根引用和 Renderer 接线。使用建筑根 Inspector 预览；进入 Map_Map01 检查放置、升级、施工、修复、荒废和实际选择范围。占位模型的尺寸按占地调整，不用模型包围盒反算权威占地。建筑玩法见 [建筑](../建筑系统/README.md)。

功能配置使用 `Capabilities` 的 19 个具名组合：Construction、Upgrade、Maintenance、Production、Quests、Placement、Connection、Storage、Workforce、Housing、Research、Farming、Gathering、Garrison、Sanctum、Market、Effects、Defence、Expeditions。各自使用中文字段和明确领域引用；禁用后不生成可执行模块数据。新增能力按 [新增建筑能力开发流程](新增建筑能力开发流程.md) 修改对应层，不增加按建筑 ID 判断的专用分支。
