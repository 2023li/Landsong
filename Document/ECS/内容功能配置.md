# 内容功能配置

在 `Assets/Landsong/ECSContent/Definitions` 选择内容资产，通过 Odin 中文检查器编辑。建筑的配置入口为“建筑功能模块”；其它内容使用“功能配置”。模块独立保存数据，关闭模块会保留内容并停止生效。

## 模块与使用场景

| 模块 | 配置内容 | 主要适用内容 |
| --- | --- | --- |
| 解锁与显示条件 | 已完成科技/任务、显示所需内容及数量 | 科技、任务、远征、人物特性 |
| 任务目标 | 建筑数量/最低等级/仅完工、已种植建筑、持有/提交物品、镜头操作、研究科技、回合数 | 任务 |
| 奖励与失败惩罚 | 物品数量、蓝图最高等级、增益/功能许可、失败物品扣除、特殊掉落稀有度 | 科技、任务、远征、敌人、访客、掉落物；具体条目有类型限制 |
| 招募、唤醒与供奉 | 独立的募兵费用、英雄唤醒费用、英雄供奉费用 | 士兵、英雄 |
| 作物种植与收获 | 种植材料、自动收获费用、每种产物最少/最多数量 | 作物 |
| 物品分组与库存规则 | 额外物品组、允许收纳的物品/物品组、指定损耗倍率 | 物品、库存槽类型 |
| 远征补给 | 物品、最低携带、额外上限、每份额外补给的成功率/奖励加成 | 远征 |
| 属性与经济效果 | 各项独立属性加成、生产/收获/损耗/风险、固定物品产出、情报 | 增益、政策、人才、职位、王室特性；科技可提供军事修正和情报 |
| 人物与任职 | 基础/每级工资、特性、基因冲突/依赖、人物委托、每回合产物、任职效果 | 人才、职位、王室特性 |

例如募兵费用直接填写“物品、数量、适用等级”，远征补给直接填写“最低数量、额外数量上限、成功率加成、奖励加成”。不再通过某个规则种类改变 B/C 等参数的含义。

## 编辑步骤

1. 启用适用的模块，展开对应列表并添加条目。
2. 在内容引用字段选择已注册资产，也可拖入。选择器按类型过滤；Baking 再检查引用、类型和适用场景，不接受同 ID 的未注册替代资产。
3. 填写具名数值。任务目标保留已有“目标进度标识”；新目标可在任务窗口补齐缺失标识。
4. 需要控制奖励或效果先后时填写“执行顺序”。小值先执行，同值保持模块及列表顺序。定义奖励在运行时仍分为“物品入库 → 许可生效”两遍，各遍保留编译顺序；开局和夜间批次保留原有混合顺序。仅拖动列表不会越过不同的显式顺序值，配置顺序也不改变领域既定的结算阶段。
5. 保存资产，执行 `Landsong → ECS → Validate native content`；修改玩法后运行相关编辑器验证。

不同模块的条目有明确的适用类型。不支持的组合、未注册引用、重复科技前置、循环依赖、非法目标标识、错误补给上限等会被拒绝，不能靠勾选模块产生无效配置。

## 奖励与内容许可约束

开局、科技、任务、远征、敌人、访客和掉落来源共用 `RewardAuthoringValidation`；运行发放与存档导入复用 `EntitlementRules` 的许可边界。错误包含来源、条目和目标信息，不再将零或负等级自动补成一级。

| 内容 | 可配置范围 | 含义 |
| --- | --- | --- |
| 物品奖励、失败扣除、特殊掉落 | 对应物品，数量为正整数 | 失败扣除仅任务/远征；特殊掉落仅敌人 |
| 建筑蓝图 | `1..建筑最高等级` | 取已持有与本次许可的较高值，高等级覆盖低等级 |
| 永久 Buff | 正整数许可等级 | 不套用建筑最高等级；同定义取最高，不表示叠加次数 |
| 功能许可 | 一级且目标为 Feature | `limit.*` 是建筑限建组，不能发放为功能开关 |
| 科技、任务、远征完成状态 | 不接受普通奖励配置直接授予 | 由研究结算、任务领奖、远征成功分别记录 |

完整奖励放不下时整批拒绝，不先留下蓝图或完成标记。夜间奖励允许溢出至待存放，重复提交不重复入库。人才回合物品收入继续只存能够容纳的数量，不能把它与完整奖励的失败策略混用。

人才自身的“内容许可”任职效果仅支持每回合发放，目标必填且只能是 Building/Buff/Feature；只允许固定或人才等级缩放。编译按人才初始至最高等级范围检查计算结果，包括等级缩放的内部极值，所有可达结果都必须满足目标许可约束。不支持岗位回合许可、被动许可或按库存/人口/建筑数量缩放许可。人才每回合产物允许零数量作为无收益，拒绝负数和整数溢出。

## 人才与岗位的任职效果

“人物与任职 → 任职效果”使用单独的来源/时机支持表，不等同于下方通用 Modifiers 模块。`EffectRules.SupportsTalentEffect` 与编译器 `ValidateTalentEffectScope` 共同校验：

| 来源 | 被动 | 每回合 |
| --- | --- | --- |
| 人才 Talent | 生产百分比、攻击百分比、民意 | 物品、科研点、内容许可 |
| 岗位 TalentSlot | 生产百分比、攻击百分比、民意 | 全部拒绝，无岗位回合发奖入口 |

同一条目的“指定作用对象”同时承担效果目标和缩放来源，不能分别选择两个对象。配置必须同时满足两者的类型约束：

- 每百份物品缩放必须指定 Item；运营建筑数缩放可指定 Building，或留空统计全部运营建筑。
- 被动生产的作用对象可为 Item 或空；被动攻击可为 Soldier/Hero 或空；民意必须为空。因此“攻击按物品库存缩放”“生产按指定建筑数量缩放”等冲突组合拒绝；留空的全局生产按全部运营建筑数缩放可以使用。
- 每回合物品必须指定 Item；按每百份物品缩放时，统计的是这个同一物品。不能用该字段另选建筑作为计数来源。
- 每回合科研点是全局收入。固定、人才等级、王国人口缩放时必须留空；仅物品计数或建筑计数缩放可以指定对应来源对象。
- 内容许可仍遵循前节更严格的目标、时机和等级范围约束，不因通用计数缩放可选而开放许可计数缩放。

每回合物品与科研效果允许零收益，拒绝负收益。固定/人才等级缩放按成长范围检查最终取整结果及整数上限，等级二次缩放还检查内部极值；按库存、人口或建筑数缩放时，成长范围内的系数必须非负且有限，运行时再用 checked 检查实际数量的转换和累加溢出。此限制不作用于被动效果，被动负修正仍可配置。

上述被动效果仍受雇佣、任职资格、岗位适配和付薪状态控制。没有消费路径的来源/时机/效果组合会在编译时拒绝，不静默忽略。

## 通用效果支持边界

`EffectRules` 同时约束通用“属性与经济效果”模块和运行查询。建筑本体/范围模块保持独立配置与叠加规则，不因这张表变成永久授权。以下是已落盘的支持范围，定向验证状态见 [执行记录](../非UI重构执行记录.md)。

| 来源 | 通用模块支持 | 生效条件 |
| --- | --- | --- |
| 永久 Buff | 经济、军事、科研、风险、行动力、固定产出和情报 | 已获得许可；普通修正不按许可等级自动倍乘 |
| 政策 | 上述通用效果 | 已采用且政策条件满足；不是永久获得 |
| 人才、人才岗位 | 经济、军事、科研、风险、行动力和固定产出 | 已雇佣、任职资格/岗位要求满足、已付薪；当前不支持情报模块 |
| 王室特性 | 经济、军事、科研、风险、行动力和固定产出 | 君王激活特性参与全局；个人自然死亡风险读取本人特性 |
| 科技 | 军事修正和情报 | `ResearchEntry` 已完成；其它通用经济修正拒绝配置 |

固定产出必须指定物品，指定建筑可留空表示全部建筑；物品与建筑是两个独立匹配条件。负固定修正可用于减产，先与基础产出相加再乘比例，最终取整数量最低为零，不把负产量误报为库存不足。产出/收获/损耗可留空表示全体物品，或指定物品。科研、民意、阴谋风险为全局值，目标字段必须留空；行动力可指定建筑，自然死亡风险可指定人才。军事目标通常为士兵/英雄，士兵专用修正只接受士兵；建筑目标仅接受实际防御结算使用的护甲和减伤，不能配置没有消费路径的建筑攻击/速度/生命修正。

情报的科技引用表示前置条件。等级零为通用条目，非零匹配当前等级：建筑用建筑等级，Buff 用持有等级，科技用完成次数；政策和不可重复科技只允许通用或一级情报，重复科技可按完成次数配置多级情报。军事查询保留“通用或不高于当前等级”的既有累积条件，黄昏冻结当夜数值；其它通用模块没有逐级字段时，不把 Buff 等级解释为效果层数。

`EffectOps.Query` 返回总值、固定/比例单位、来源贡献和排除原因，与实际数值计算共用匹配规则。它不改变任职、政策、许可或 RNG；查看解释不负责启用效果。

## 开局发放与夜间条件

目录资产的“开局发放”使用 `StartingRewards`，仅接受正数量的物品、蓝图、增益和功能许可。开局驻军仍配置在建筑驻军模块，二者职责不同。

每个夜间事件的 `Conditions` 使用独立的夜间触发条件配置，可填写回合、建筑、物品、科技和完成前置。它没有任务进度标识，不和任务目标共用可编辑数据。

## 代码与持久化边界

- 建筑配置：`Authoring/BuildingModules.cs`，编译器为 `BuildingModuleCompiler`。
- 非建筑模块：`Authoring/*ContentModule.cs`；每个模块的编译实现位于 `ContentModuleCompiler.*.cs`。
- `ContentReferenceResolver` 只解析实际注册的内容资产；`ContentCompilation` 统一缓存本次编译的运行记录、开局发放与夜间条件，供领域校验和 Blob 写入复用。
- 奖励编译共用 `RewardAuthoringValidation`，许可规则共用 `EntitlementRules`；人才许可和回合产物另由 `TalentGrantAuthoringValidation` 检查增长范围。普通效果模块通过 `EffectRules.SupportsOwner/SupportsTarget` 拒绝无执行意义的来源或目标；人才任职效果另检查 `SupportsTalentEffect` 及目标与缩放是否兼容。
- 运行层继续使用紧凑 `Rule` 和 Blob。通用编辑类、原始 Rules 字段、EffectiveRules 和旧转换/反向迁移工具均已删除。
- 任务标识、内容 ID、资产 GUID 和执行顺序保持稳定。当前快照写入 v24，王朝封装为 v3；配置编译对照与持久协议兼容分别验证，详见 [运行与存档](../运行时与存档/README.md)。

`ContentCompilationBaseline.json` 记录迁移前 185 个定义及开局奖励的执行结果，验证数值、引用索引、顺序和任务标识。日后有意调整玩法配置，须审阅并更新对应基准，不能批量覆盖来消除失败。资产往返检查同时覆盖 Unity 序列化后的实际引用和值。

本轮许可/效果重构没有改写正式内容或更新基准。正式目录校验、内容编译基准和新增奖励/效果边界验证已通过最终编辑器回归；四场景和研究 HUD 实际 Play 检查均通过，结果统一记入 [非 UI 重构执行记录](../非UI重构执行记录.md)。
