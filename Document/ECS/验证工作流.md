# 验证工作流

本页维护当前验证入口；实际结果以 [当前修复与验收记录](../ECS/问题修复记录20260917.md) 及对应时间的报告为准。

## 日常内容回归与历史迁移

`ProjectVerification.RunAll` / `ValidateBatch` 中的 ContentCompilationVerification 只按当前内容集检查领域编译、数量与身份对应、注册顺序、序列化和任务数量缩放，不再要求正式资产等于历史 185 项迁移快照。可单独运行 **Landsong → ECS → Verification → Current content compilation**，或使用本机自动化 `VerifyCompilation`；报告仍为 `Library/LandsongEcs/content-compilation-verification.txt`。

该套件用内存中的隔离副本新增建筑、士兵和科技，调整既有耐久、生命和科研费用，并重排科技目录，确认当前编译检查接受合法变更；另检查重复 ID、未注册同名引用、非法费用和循环前置仍被拒绝。测试不保存正式资产。目录重排合法不代表旧存档可读，内容指纹与版本门禁保持不变。BuildingModuleVerification 也只核对当前建筑配置的编译与序列化，不再读取历史基线；特定玩法场景的行为断言仍须满足各自条件。

历史基线和原验收源码归档在 `Tools/RetiredMigrations/20260920/`，基线字节保持不变。需要复核迁移时，使用归档说明指定的独立历史检出；不要为日常新增内容改写历史基线。参见 [归档说明](<../../Tools/RetiredMigrations/20260920/README.md>)。

## 本轮新增检查

内容制作使用 **Landsong → ECS → Verification → Content authoring workflow**，自动化动作为 `VerifyContentAuthoring`，报告为 `content-authoring-workflow-verification.txt`。该套件使用独立 GUID 目录和内容集副本，从空白生成建筑及科技，验证注册、显示编译、实际研究与蓝图奖励、建造/施工、选择、二级升级/外观切换、按等级科研产出和存档恢复；生成基础动作、剑与火把两种士兵以及英雄、敌人，验证独立控制器、重复执行保留 GUID/手工修改、失败清理和出勤/归营/死亡生命周期。结束后删除临时产物，不登记到正式内容集，并检查工具保留原活动场景及其修改状态。它证明制作流程及报告所列行为，不替代新素材的画面、实际获得入口和完整战斗验收。

文档使用 **Landsong → ECS → Verification → Current authoring documentation**，自动化动作为 `VerifyDocumentation`，报告为 `documentation-verification.txt`。检查 Document 内本地链接、当前主要手册的存档版本，以及建筑/单位/科技 SOP 的实际字段和菜单。内容制作与文档检查均已纳入 Run all；不能仅用字词检查证明整份说明语义正确。

正式内容结构可运行 **Landsong → 内容制作 → 校验正式制作内容**，串联当前世界模板的领域内容、派生显示目录及建筑/单位结构检查。结构检查也进入正式构建前的内容门禁。涉及共享单位动画适配时，再运行 **Landsong → 动画 → 验证按需创建与释放 (Play)**（`VerifySoldierAnimationLifecyclePlay`）；等待 `soldier-animation-lifecycle-play.txt` 的本次完成结果，自动化的“已启动”响应不等于 Play 通过。

SceneRequestVerification 覆盖延迟失败、取消、同步拒绝、重复请求和失败后的再次进入。ArchitectureVerification 检查运行内容边界、迁移器缺席、作物当前 schema、场景 GUID 与生成显示目录。PortraitVerification 验证 Release 对占位肖像的拒绝；普通构建通过 IPreprocessBuildWithReport 执行同一门禁。当前 PortraitConfig 只有程序占位，正式构建应失败，不能为得到绿色构建而绕过门禁。

修改图标、说明或科技树位置后执行 **Landsong → ECS → Compile domain display catalogs**。一次性迁移动作已经退役，自动化不再提供 Migrate / FinalizeGameUi 等旧入口；保留当前预览配方刷新和只读检查。

实际图形 Play 可用 Unity 的 -executeMethod Landsong.ECS.Editor.EcsSceneFlowVerification.RunCommandLine，不加 -batchmode 或 -quit，结束后自动退出并返回结果；需要真实 Game 视图渲染，不能用无图形流程代替截图和交互检查。

场景请求定向回归使用 `EcsSceneFlowVerification.RequestsCommandLine`，报告为 `scene-requests-play-verification.txt`，覆盖重复进入/返回、忙碌拒绝、无效地图、损坏快照、取消和失败后重试。它不替代完整 UI 流程。UI 框架可通过 `-batchmode -executeMethod Moyo.Unity.Editor.UIFrameworkVerification.Batch` 运行，不加 `-quit`，等待异步验证自行退出；报告为 `ui-framework-verification.txt`，包括正常 shutdown 和根强制销毁时的取消/释放。

## 领域拆分后的检查

`WorldInitialization.Initialize` 是世界初始化入口，`GameRequestExecution.Execute<T>` 执行明确类型的请求，`GameplayRequests.Enqueue<T>` 创建待执行 payload；旧 GameLoopSystem.Initialize/Execute 和通用 Command 已删除。测试应构造各域 Catalog 与独立组件，不建立万能 Definition 夹具。目录克隆必须保持显式跨域引用；手造建筑岗位定义也必须填写完整的 EfficiencyTiers 区间。

`DomainArchitectureVerification` 检查旧通用定义、规则与状态入口已移除及领域契约；`GameplayRequestVerification` 检查队列 payload 所有权、请求顺序、失败清理和恢复事务中的队列处理。保存回归检查 v33 的分域快照与当前版本拒绝策略，不能用旧存档或之前的 PASS 日志证明本轮通过。

出现大片“模拟根不存在”前先检查烘焙异常、目录引用与资源反序列化；这类共同前置失败不应通过放宽领域规则或跳过断言处理。仓储、经济和岗位的独立夹具用于在地图导入失败时继续定位局部规则。

## 日常怎么确认通过

1. 保存要保留的场景修改并退出 Play，等待脚本编译与资源导入完成。验证期间不要并行修改源码或启动第二个 Unity 实例。
2. 执行 Unity 菜单 **Landsong → ECS → Verification → Run all**。
3. 打开 `Library/LandsongEcs/regressions.txt`。最后一行必须为 PASS，failures=0，且完成时间属于本次执行。文件不存在、只写 Started、出现 FAIL 或编译失败，都不能算通过。
4. 涉及真实界面/场景/战斗时，再执行 **Landsong → ECS → Verify four-scene flow (Play)**。结束后查看 `Library/LandsongEcs/scene-flow-verification.txt` 的本次 PASS。测试自动退出自己的 Play 并恢复原场景。
5. 涉及打包或运行差异时，执行 **Landsong → ECS → Build Windows baseline**，查看 build.txt 并运行新的独立程序。

这些领域回归是项目自定义断言，与 Visual Studio / Unity Test Runner 里的绿色勾选列表不是同一个入口。GridMapDefinitionTests 是保留的 NUnit 测试；不要用它的绿色勾选代替整个项目验证。

建筑详情 / 研究 HUD / 功能面板调整可运行 **Landsong → ECS → Verify research HUD and panels (Play)**，本次结果写入 hud-panels-verification.txt（带完成时间）。该定向测试包含新版建筑详情的默认展开、输入改名、异常悬浮、补贴预算/黄色即时预览/实际已付效果保留/比例岗位/空基础产出隐藏/工人档位悬浮侧栏、作物选择/进度/铲除、缺蓝图升级原因、升级材料确认/取消/执行、MAX、坐标与默认范围；同时覆盖默认隐藏、各功能关闭、驻军双视图、情报退出、科技队列进度/效果/空态、完整科技树交互，以及王室分代/家庭/登基连线/死亡/皇冠、右侧人物详情/父母/操作门禁/王朝事务切换、赐婚事件及双方详情弹窗、同意/拒绝/稍后处理、主动候选选择与确认、人物多请求列表/搁置后重开/请求数量标记/导航不结单/逐项处理/空态/关闭门禁，以及肖像缓存共享/丽质 RGB 与部件预览/取消和一次确认/读档重新绑定/程序衰老/幼儿襁褓/士兵列表；测试结束恢复原场景。截图输出 building-details.png、royal-family.png、marriage-request.png、arrange-marriage.png、person-requests.png 与 royal-requests-details.png。Court 领域回归额外验证生育资格、女性继位、父母性别映射、主动赐婚、候选稳定、换君、拒婚风险、请求去重/过期/阶段限制和快照往返。它不等于完整四场景/战斗验收。仅调整 UI 时优先编辑器验证，涉及独立运行差异才额外构建。

地图制作与目录调整可单独运行 **Landsong → ECS → Verification → Map authoring workflow**，报告为 `Library/LandsongEcs/map-authoring-verification.txt`。测试创建独立临时地图并恢复菜单、Game 场景和原有编辑场景；该套件也纳入 Run all。地图目录/引用调整还可执行 **Landsong → ECS → Verify map loading (Play)**，检查菜单地图和重复进入后的加载、身份及释放；报告为 `map-loading-play-verification.txt`，此定向检查不替代完整四场景 UI/音频验收。

## 代码与输出

- Scripts/Editor/Tests/Verification：领域套件、ProjectVerification 总入口、真实 Play 调度；套件数量以当前总入口为准。
- Scripts/Verification/Tests：编辑器和 Development Player 共用完整流程，正式 Release 不包含 smoke 行为。
- Scripts/Editor/Tests/GridMapDefinitionTests.cs：独立 NUnit 网格检查。
- 每个领域写自己的 `<领域>-verification.txt`；总报告为 regressions.txt，不嵌套重复调用其他套件。
- 只跑 UI 快速复现输出 interface-ui-verification.txt，不能代替完整场景报告。
- 测试使用独立 GUID 临时目录及非持久会话，不操作玩家王朝；借用的设置、设备、字体/资源测试对象在 finally 归还。
- Library/LandsongEcs 是可再生本机证据，不提交版本库。先检查本次时间与结果，不能仅凭旧文件存在判定。

PersistenceContractVerification 检查当前显式字段覆盖、快照精确往返、非当前版本提前拒绝、10 个独立 Settings 的逐字段签名与网格签名、未登记根组件拒绝和采集失败回滚。ArchiveApplicationServiceVerification 使用现场生成的当前格式测试存档，检查 Load/Save 权限、跨王朝拒绝、自动节点保护、失效会话和相同长度/修改时间下的内容变更。它们已并入总入口，输出分别为 persistence-contract-verification.txt 和 archive-application-service-verification.txt。旧协议夹具及兼容验证已移除。

ArchitectureVerification 校验九个项目程序集分区、脚本归属及依赖方向，包括 Authoring 与第三方 AI 适配从运行核心分离；UiConfigurationVerification 校验实际根画布、注册表、显式引用、脚本/资源目录、中文标签与预览配置。GamePanelNavigationVerification 检查类型化面板标识、迁移后九个原有静态导航事件的目标和参数、配置权限与显示身份分离。上述静态检查不代替真实 Play 中的输入、异步加载、失效会话与清理检查。

完整场景 smoke 会记录常驻 Canvas、UIManager、EventSystem 的初始实例，在 Start 与 Game 实际打开设置和存档后比较共享面板实例，并在退出 Game 后检查旧面板销毁、会话释放、示例内容清理。下拉框关闭后才统计实际活动 Canvas，避免把 TMP 临时展开画布当成第二套应用画布。这些检查是否实际通过仍以本次 Play 报告为准。

历史/库存验证通过正式 `HistoryOps.ForRequest`（带 `QueuedGameplayRequest` 元数据）或 `GameRequestExecution.Execute<T>` 建立命令上下文。StorePending 与 StorePendingSlot 的待存放扣减、仓库增加必须标记为转库且数量平衡；中文原因改写不改变经济统计，其他命令也不能仅因文案包含“待存放转库”而获得转库标记。

## 命令行

Unity 已关闭时，可用对应版本的 Unity.exe：

```powershell
& 'C:/Program Files/Unity/Hub/Editor/6000.3.24f1/Editor/Unity.exe' -batchmode -quit -projectPath 'D:/UnityProject/Landsong' -executeMethod Landsong.ECS.Editor.ProjectVerification.Batch -logFile 'D:/UnityProject/Landsong/Library/LandsongEcs/batch.log'
```

Batch 先打开 Boot，运行全回归，再分别构建 Development（Builds/ECSBaseline）和 Release（Builds/ECSRelease）。只做逻辑回归可改用 ProjectVerification.ValidateBatch。构建必须 Succeeded 且错误数为 0；退出码不能替代报告检查。不与同项目已打开的 Unity 并发启动。

独立程序：

```powershell
& 'D:/UnityProject/Landsong/Builds/ECSBaseline/Landsong.exe' -landsong-ecs-smoke -screen-width 1600 -screen-height 900 -screen-fullscreen 0 -logFile 'D:/UnityProject/Landsong/Library/LandsongEcs/player.log'
```

需要 Development Build 和显式 -landsong-ecs-smoke。完整成功会输出 [ECS PLAYER SMOKE] PASS 并返回 0；异常、超时和流程未跑完不算通过。输入/画面测试不要使用 -nographics。

独立程序追加 `-landsong-scene-requests-only` 可只运行场景请求回归，成功后通过原生退出事件检验应用清理和退出。完整 smoke 失败时由应用根等待清理后保留退出码 1。以当前日志中的具体范围和进程退出码判断，定向 PASS 不代表完整业务流程通过。

## 本机编辑器自动化

EcsEditorAutomation 读取 Library/LandsongEcs/request.json，每个唯一 Id 只处理一次，结果写 response.json。只在非编译/非更新状态执行；Refresh 返回不代表编译已完成。

常用请求包括 InspectEditor、InspectScenes、Refresh、Validate、VerifyAll、VerifyPersistenceContracts、VerifyGameplayRequests、VerifyUiConfiguration、VerifyPeaceful、VerifyCompilation、VerifyIntelligence、VerifyUiFramework、VerifyContentInspector、VerifyPortraitImport、OpenPortraitImport、VerifyArchitecture、SceneFlowPlay、SceneFlowInterfacePlay、SceneFlowHudPanelsPlay、SceneFlowGarrisonPlay、StopSceneFlowTest、Build、BuildRelease、SyncPresentationText。具体可用操作以 EcsEditorAutomation 的 switch 为准，一次性资源迁移/安装动作不是日常验证入口，完成重构后不要为解决普通配置问题重复执行。

VerifyContentInspector 用临时资产打开实际 Odin 检查器，绘制结果写 content-inspector-gui.txt；只写 Started 或 INCOMPLETE 不算通过，窗口画面还需可视核对。VerifyPortraitImport 单独验证肖像导入服务和窗口门禁；其错误报告保留 Validate 的真实拒绝原因。如果临时资产操作触发待处理源码编译，必须待编译稳定后重新执行，不能移除导入器的 Play/编译保护来使测试通过。OpenPortraitImport 打开导入窗口。Stop 只允许停止调度器拥有的测试，不停止用户 Play。完成后移除请求文件。
