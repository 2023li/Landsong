# 验证工作流

## 日常怎么确认通过

1. 保存要保留的场景修改并退出 Play。
2. 执行 Unity 菜单 **Landsong → ECS → Verification → Run all**。
3. 打开 `Library/LandsongEcs/regressions.txt`。最后一行必须为 PASS，failures=0，且完成时间属于本次执行。文件不存在、只写 Started、出现 FAIL 或编译失败，都不能算通过。
4. 涉及真实界面/场景/战斗时，再执行 **Landsong → ECS → Verify four-scene flow (Play)**。结束后查看 `Library/LandsongEcs/scene-flow-verification.txt` 的本次 PASS。测试自动退出自己的 Play 并恢复原场景。
5. 涉及打包或运行差异时，执行 **Landsong → ECS → Build Windows baseline**，查看 build.txt 并运行新的独立程序。

这些领域回归是项目自定义断言，与 Visual Studio / Unity Test Runner 里的绿色勾选列表不是同一个入口。GridMapDefinitionTests 是保留的 NUnit 测试；不要用它的绿色勾选代替整个项目验证。

建筑详情 / 研究 HUD / 功能面板调整可运行 **Landsong → ECS → Verify research HUD and panels (Play)**，本次结果写入 hud-panels-verification.txt（带完成时间）。该定向测试包含新版建筑详情的默认展开、输入改名、异常悬浮、补贴预算/已付吸引力/比例岗位、作物选择/进度/铲除、缺蓝图升级原因、升级材料确认/取消/执行、MAX、坐标与默认范围；同时覆盖默认隐藏、各功能关闭、驻军双视图、情报退出、科技队列进度/效果/空态、完整科技树交互，以及王室分代/家庭/登基连线/死亡/皇冠、右侧人物详情/父母/操作门禁/王朝事务切换、赐婚事件及双方详情弹窗、同意/拒绝/稍后处理、主动候选选择与确认、人物多请求列表/搁置后重开/请求数量标记/导航不结单/逐项处理/空态/关闭门禁，以及肖像缓存共享/丽质 RGB 与部件预览/取消和一次确认/读档重新绑定/程序衰老/幼儿襁褓/士兵列表；测试结束恢复原场景。截图输出 building-details.png、royal-family.png、marriage-request.png、arrange-marriage.png、person-requests.png 与 royal-requests-details.png。Court 领域回归额外验证生育资格、女性继位、父母性别映射、主动赐婚、候选稳定、换君、拒婚风险、请求去重/过期/阶段限制和快照往返。它不等于完整四场景/战斗验收。仅调整 UI 时优先编辑器验证，涉及独立运行差异才额外构建。

## 代码与输出

- Scripts/Editor/Tests/Verification：24 个领域套件、ProjectVerification 总入口、真实 Play 调度。
- Scripts/ECS/Presentation/Tests：编辑器和 Development Player 共用完整流程，正式 Release 不包含。
- Scripts/Editor/Tests/GridMapDefinitionTests.cs：独立 NUnit 网格检查。
- 每个领域写自己的 `<领域>-verification.txt`；总报告为 regressions.txt，不嵌套重复调用其他套件。
- 只跑 UI 快速复现输出 interface-ui-verification.txt，不能代替完整场景报告。
- 测试使用独立 GUID 临时目录及非持久会话，不操作玩家王朝；借用的设置、设备、字体/资源测试对象在 finally 归还。
- Library/LandsongEcs 是可再生本机证据，不提交版本库。先检查本次时间与结果，不能仅凭旧文件存在判定。

## 命令行

Unity 已关闭时，可用对应版本的 Unity.exe：

```powershell
& 'C:/Program Files/Unity/Hub/Editor/6000.3.5f2/Editor/Unity.exe' -batchmode -quit -projectPath 'D:/UnityProject/Landsong' -executeMethod Landsong.ECS.Editor.ProjectVerification.Batch -logFile 'D:/UnityProject/Landsong/Library/LandsongEcs/batch.log'
```

Batch 先打开 Boot，运行全回归，再分别构建 Development（Builds/ECSBaseline）和 Release（Builds/ECSRelease）。只做逻辑回归可改用 ProjectVerification.ValidateBatch。构建必须 Succeeded 且错误数为 0；退出码不能替代报告检查。不与同项目已打开的 Unity 并发启动。

独立程序：

```powershell
& 'D:/UnityProject/Landsong/Builds/ECSBaseline/Landsong.exe' -landsong-ecs-smoke -screen-width 1600 -screen-height 900 -screen-fullscreen 0 -logFile 'D:/UnityProject/Landsong/Library/LandsongEcs/player.log'
```

需要 Development Build 和显式 -landsong-ecs-smoke。完整成功会输出 [ECS PLAYER SMOKE] PASS 并返回 0；异常、超时和流程未跑完不算通过。输入/画面测试不要使用 -nographics。

## 本机编辑器自动化

EcsEditorAutomation 读取 Library/LandsongEcs/request.json，每个唯一 Id 只处理一次，结果写 response.json。只在非编译/非更新状态执行；Refresh 返回不代表编译已完成。

支持 InspectEditor、InspectScenes、Refresh、Validate、VerifyAll、VerifyPortraitImport、OpenPortraitImport、VerifyArchitecture、SceneFlowPlay、SceneFlowInterfacePlay、SceneFlowHudPanelsPlay、StopSceneFlowTest、Build、SyncPresentationText。VerifyPortraitImport 单独验证肖像导入服务和窗口门禁，OpenPortraitImport 打开导入窗口。Stop 只允许停止调度器拥有的测试，不停止用户 Play；没有安装、迁移或恢复旧资源的动作。完成后移除请求文件。
