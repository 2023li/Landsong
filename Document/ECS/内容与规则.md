# 内容与规则

> 历史资料：本文保留旧配置模型的说明，通用 Rule/旧字段不再是当前制作 API。当前入口为 [定义系统](../定义系统.md)、[建筑制作](建筑玩法与制作工作流.md)、[单位制作](../昼夜与战斗系统/单位制作流程.md) 和 [科技制作](../科技系统/README.md)。

编辑数据与运行数据分离。正式内容位于 `Assets/Landsong/ECSContent/Definitions`，按 22 个领域分别使用具体的 DefinitionAsset、CatalogAsset、编译器和只读 Blob。完整类型及依赖见[定义系统](../定义系统.md)。ECS 没有要求所有系统共享一个定义；项目已移除通用定义、通用 Rule 和全目录查找入口。

## 定义层

| 字段 | 含义 |
| --- | --- |
| Metadata.Id / Name / Description | 领域内稳定内容键、显示名、编辑说明 |
| Item.MaximumStack | 物品单格堆叠上限 |
| Building.Footprint / MaximumLevel | 建筑占格与最高等级 |
| Technology.ResearchPointCost | 科技研究点消耗 |
| Quest.Objectives / Rewards / Penalties | 任务目标、奖励与惩罚 |
| Soldier / Hero 的招募、人口和战斗字段 | 各自单位定义中的专用配置 |
| Expedition 的供应、队伍和历时字段 | 远征定义中的专用配置 |

系统显式使用 `ItemDefinitions.Get(ItemId)`、`QuestDefinitions.Get(QuestId)` 等领域 API（实际参数还包括 EntityManager 和 root）。ID 默认值为空，不能隐式转成整数或另一领域 ID。Baking 仅在指定的领域目录中解析引用，运行时不再通过 Kind 判断字段含义。

## 强类型功能配置

建筑定义组合建造、储存、生产、居民等具名能力配置；其他领域各自声明需要的配置，不继承一个包含全部系统字段的基类。开局奖励、夜晚计划、王室、人才、货币等设置由独立 Authoring 组件保存和烘焙。

编辑和运行时均已删除通用 `Rules`、`RuleSource`、`Rule.Kind / Target / Amount / B / C`。编译器直接生成具有明确字段与目标类型的运行记录。奖励、前置与效果可组合复用，但它们的物品、建筑、科技等接收者仍使用不同类型的引用。

模块“启用”控制是否编译；禁用保留字段但不产生效果。建筑与非建筑的活动模块不能混用，非建筑条目有明确的内容类型限制。引用必须是当前目录实际注册的资产，不能用另一个同 ID 资产代替。任务目标的稳定进度标识和条目的执行顺序属于玩法身份，修改时需审阅存档影响。

## 专用配置

- Building：移动、外观、目录排序等建筑参数。修复回合与募兵额度分别归入 Maintenance / Garrison 模块。
- SoldierGrowth / HeroGrowth：个人累计经验曲线、等级上限、生命/攻击成长与经验来源。
- Combat：感知、追击、体积、防御/穿透、弹体、范围、预警、寿命和遮挡。
- Court：政治、自然死亡概率、交际和出访；Night / NightEvents：回合初夜晚计划及 Boss 后续。
- QuestGeneration：来源强度档与抽签权重；任务 QuestIntensity / QuestWeight / ItemQuantityScale 控制模板。
- Peaceful / Opportunity / Theft：平安互动、访客与物品偷盗规则。
- Settings 的情报档位/提前量，建筑防御模块或非建筑属性效果模块中的情报来源条件。

具体字段见对应[系统手册](../README.md)，当前资产与各专用 ContentValidation 为可用配置的最终依据。不认识的字段/枚举不能自行假设执行语义；新增规则须同时实现执行器和拒绝非法配置的测试。

## 注册和烘焙

新增定义后在 Inspector 注册到对应领域的 CatalogAsset.Definitions，保存并执行 Landsong/ECS/Validate native content。SubScene 上的领域 Authoring 显式引用自身目录和所需目录，Unity 会重新 Baking。修改行为数值通常改变配置指纹，需要新开王朝；纯模型、语言和布局不应改玩法身份。

当前存档为 v30：保存类型化领域索引，并使用完整配置指纹校验对应关系，不读取旧版存档。任务进度另以稳定目标键保存，合法的目标显示顺序调整不会把进度对应到其他目标。

工作流：配置 → 校验 → 保存 → Baking → Map_Map01 实玩 / 领域回归。禁止运行中改模板代替修改 ECS 状态，也不要用安装脚本重新生成并覆盖正式内容。

肖像部件由独立肖像 Authoring 引用 PortraitConfig，烘焙为只读 PortraitLibraryBlob。正式原生校验同时检查肖像尺寸、色盘、部件及适用性别。gene.beauty 是第六项可遗传基因；详细参数和美术导入见 [当前肖像说明](../玩法系统/README.md)。
