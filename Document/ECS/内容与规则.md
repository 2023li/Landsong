# 内容与规则

编辑数据与运行数据分离。正式内容入口为 `Assets/Landsong/ECSContent/Definitions`，每项一个 GameDefinitionAsset；GameCatalog.asset 注册定义并配置全局参数。运行时只读 ContentBlob，引用在 Baking 时解析为索引；索引不能替代持久内容 ID。

## 定义层

| 字段 | 含义 |
| --- | --- |
| Id / Name / Description | 稳定内容键、显示名、编辑说明 |
| Kind | 建筑、物品、兵种、英雄、敌人、科技、任务、远征等 |
| Prefab | Baker 引用的视觉/DBP 编辑源，不是运行状态 |
| Size | 建筑 X/Z 占格，旋转交换 X/Z |
| Level | 建筑最高等级 / 人才初始等级 / 远征要求等级，依内容类型解释 |
| Duration | 建造回合数 / 作物生长 / 远征时长 / 英雄死亡冷却 |
| Capacity | 物品单格堆叠上限 / 作物全周期工人阈值 / 人才等级上限 |
| Population / Cost | 单位人口与招募金币；科技 Cost 是研究点数 |
| Health / Damage / Range / Interval / Speed / ProjectileSpeed | 战斗基础数值；建筑 Speed 是格子通行成本，0 表示阻挡 |
| Value | 物品基础价值 / 敌人基础威胁值 / 建筑资源连接行动力，依类型解释 |
| Group / Limit | 建筑限建组 / 上限，0 表示无限；物品组有父组 |

只读运行目录是 `ContentBlob`。内容资产引用和分组等稳定 ID 在 Baking 时解析为索引；索引不是可持久化 ID。

## 强类型功能配置

建筑使用 `ContentSource.Modules` 的 18 个模块，见 [建筑模块配置](建筑模块配置.md)。非建筑内容使用 `ContentSource.Configuration`，见 [内容功能配置](内容功能配置.md)。开局发放为 `GameCatalogAsset.StartingRewards`，夜间事件条件为 `NightEventSource.Conditions`；全部由独立配置类保存具名字段，内容引用直接选择已注册资产。

编辑配置中已删除通用 `Rules` 和 `RuleSource`，没有兼容字段或反向转换路径。`ContentCompilation` 为一次烘焙解析引用并缓存执行记录；建筑编译器和各功能模块编译器直接生成运行时 `Rule`，随后复制进 Blob。`Rule.Kind / Target / Amount / B / C` 仅属于紧凑执行格式，策划不需要填写它们。

模块“启用”控制是否编译；禁用保留字段但不产生效果。建筑与非建筑的活动模块不能混用，非建筑条目有明确的内容类型限制。引用必须是当前目录实际注册的资产，不能用另一个同 ID 资产代替。任务目标的稳定进度标识和条目的执行顺序属于玩法身份，修改时需审阅存档影响。

## 专用配置

- Building：移动、外观、目录排序等建筑参数。修复回合与募兵额度分别归入 Maintenance / Garrison 模块。
- SoldierGrowth / HeroGrowth：个人累计经验曲线、等级上限、生命/攻击成长与经验来源。
- Combat：感知、追击、体积、防御/穿透、弹体、范围、预警、寿命和遮挡。
- Court：政治、自然死亡概率、交际和出访；Night / NightEvents：回合初夜晚计划及 Boss 后续。
- QuestGeneration：来源强度档与抽签权重；任务 QuestIntensity / QuestWeight / ItemQuantityScale 控制模板。
- Peaceful / Opportunity / Theft：平安互动、访客与物品偷盗规则。
- Settings 的情报档位/提前量，建筑防御模块或非建筑属性效果模块中的情报来源条件。

具体字段见对应[系统手册](../README.md)，当前资产与各专用 ContentValidation 为可用配置的最终依据。不认识的字段/枚举不能自行假设执行语义；新增规则须同时实现执行器和拒绝非法配置的测试。

## 注册和烘焙

新增定义后在 Inspector 注册到 GameCatalog.Definitions，保存并执行 Landsong/ECS/Validate native content。SubScene 引用目录和 Prefab，Unity 会重新 Baking。修改行为数值通常改变内容签名，需要新开王朝；纯模型、语言和布局不应改玩法身份。

工作流：配置 → 校验 → 保存 → Baking → Map_Test2 实玩 / 领域回归。禁止运行中改模板代替修改 ECS 状态，也不要用安装脚本重新生成并覆盖正式内容。

肖像部件单独由 GameCatalog.Portraits → PortraitConfig 配置并烘焙为只读 PortraitLibraryBlob，正式原生校验同时检查肖像尺寸、色盘、部件及适用性别。gene.beauty 是第六项可遗传基因；详细参数和美术导入见 [肖像规格](../肖像系统初稿.md)。
