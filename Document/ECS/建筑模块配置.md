# 建筑模块配置

正式入口为 `Assets/Landsong/ECSContent/Definitions/Building` 中的建筑资产。建筑不再编辑通用 Rules；每个功能由独立的配置类保存。`ContentInspector` 使用 OdinEditor，字段、模块、条目及嵌套战斗/移动等设置由 Odin `LabelText` 显示中文；`ShowIf` 隐藏不适用的配置，关闭模块保留已填写内容。内容引用选择器使用 Odin 绘制链，按类型筛选已注册资产，修改支持 Unity 撤销。

数值下限使用 Odin `MinValue`，避免 Unity 原生 `Min` 绘制器覆盖中文标签。建筑模块校验也读取同一下限，脚本或资产文件写入的非法值仍会在烘焙前被拒绝。

## 配置步骤

1. 选择建筑资产，填写名称、最高等级、施工回合、占地、耐久等基本信息。
2. 在“功能模块”勾选需要的功能。关闭模块会停止编译该模块的配置，已有输入仍保留，重新启用可以恢复。
3. 展开模块中的列表添加条目。折叠标题会显示等级、物品和主要数量，不需要记忆 B、C 的含义。
4. 物品、兵种、英雄、库存类型、作物和科技直接从当前目录中选择对应类型的资产，也可以拖入；箭头按钮可定位资产。引用以稳定内容 ID 解析，不以显示名称匹配。
5. 留意 Inspector 的错误提示和等级能力摘要。保存后运行原生内容校验，再在编辑器开始新王朝检查实际效果。

## 等级和时间

- “适用等级”：0 表示所有等级，正数表示只在该等级生效。升级不会隐式继承上一等级的配置。
- 放置材料和地形是整座建筑的放置条件，不提供无效的等级选项。种植作物和最终采集奖励会按建筑当前等级筛选，通用奖励与该等级奖励相加。
- “施工阶段”：0 表示每一期，正数表示第几期；不能超过建筑基本信息中的施工回合数。
- “升级目标等级”：例如 2 表示从一级升级到二级时的要求和材料；0 表示每次升级都适用。
- 岗位容量、驻军容量、基础生产周期等单值能力不能同时配置重叠的通用项与指定等级项；校验会拒绝，避免先后顺序决定结果。
- 多条材料可以相加；生产产出档位仍按实际工人范围匹配，多个匹配产出均执行。配置不同档位时应确认边界，0 的“最多工人”表示不限。

## 示例：皇宫开局两名民兵

打开 `b王宫.asset`，启用“驻军”：

1. 在“驻军容量”添加 LV1 条目：驻军容量 3、每批出勤 1。
2. 在“开局驻军”添加 LV1 条目：兵种民兵、人数 2。需要混合兵种时添加更多条目，总人数不能超过容量。
3. “每回合募兵上限”填写 0 表示使用当前驻军容量；这是后续募兵额度，开局赠兵不消耗它。

初始化完成时创建两名普通持久士兵，分配到真实槽位 1、2，保留人口成本、姓名、年龄和战斗属性。它仅用于地图开局已有建筑；运行中建造、升级和读档不会重复赠兵。

## 数据及迁移约束

`ContentSource.Modules` 是建筑功能的唯一可编辑来源。18 个模块类和具名条目位于 `Authoring/BuildingModules.cs`；运行中的人数、库存、经验仍只存在于 ECS 组件及缓冲区。

`BuildingModuleCompiler` 接收建筑模块和内容引用解析器，直接生成模拟系统使用的 `Rule[]`。这些紧凑运行记录随即写入 Blob，不保存回资产，也不经过其它通用编辑数据类。

29 个建筑和所有非建筑资产均已采用强类型配置。`RuleSource`、`EffectiveRules`、`ConvertRule` 及旧反向迁移器已删除；不保留原始 Rules 字段或回退来源。非建筑配置见 [内容功能配置](内容功能配置.md)。每次 `ContentCompilation` 统一解析目录引用，内容校验和 Blob 写入共用同一份执行记录，包括开局奖励和夜间条件。

`BuildingModuleBaseline.json` 保存迁移前的有效规则基准，用于防止遗漏材料、容量和条件。以后有意调整建筑数值时，应同步审阅并更新对应建筑的基准；不要直接批量覆盖基准来消除失败。

初始驻军从原 Garrison.C 拆分为独立的 InitialGarrison 执行记录，Garrison 的兵种引用随之移入初始兵种条目。旧 Provider.Amount 和 ExpeditionSite.C 没有运行读取点，迁移时移除，不再向策划显示无效参数。其它实际材料、等级、容量、条件和产出有迁移前基准对照检查。

模块编译保留既有运行记录的数值、索引、顺序和目标标识，不能用配置结构整理改变建筑身份。当前快照写入 v24，玩法内容签名覆盖完整全局设置、规则与开局状态；旧 v22/v23 使用各自的历史签名。实际改变玩法数值时仍执行兼容检查，不匹配的存档明确拒绝载入并保留原文件。资产移动保留 meta GUID 和稳定内容 ID；完整格式规则见 [运行与存档](../运行时与存档/README.md)。


## 工作效率档位

在建筑资产的“岗位与补贴 → 工作效率档位”中逐条设置建筑等级（0 为通用）、最少工人和最多工人（含上限，0 表示确切的零人，不表示不限）。例如农田当前显式配置 0、1、2、3 人四档。13 个启用岗位模块的现有建筑已补齐各等级配置。

分档不再由 UI 按容量枚举或反推阈值。等级的档位必须连续覆盖 0～岗位容量，不能缺项、交叠、倒置或越界；实际效果发生变化的工人门槛不能被包在一个区间中。相同效果人数可明确合并成区间，例如农田 0～1 人。内容校验只检查错误，不代写或自动修复配置。修改产出、种植门槛等玩法规则时需同步调整档位边界。

实际效果数值继续由生产、作物、仓储、神殿等具名玩法模块配置；档位不是另一套重复的结算参数。GameWorldAuthoring 将明确的人数区间烘焙到 ContentBlob.WorkerTiers；WorkerEfficiencyOps 查询这些档位并统一解释模块规则，UI 直接展示查询结果。缺少档位时提示未配置，不回退到推导逻辑。

WorkerTiers 是只读展示分组数据，不参与玩法内容签名。只改分档范围不改变实际结算或快照格式，也不会导致存档因内容签名变化而失效；修改真正的玩法参数仍遵循原有内容签名校验。
