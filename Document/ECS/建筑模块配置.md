# 建筑模块配置

> 历史资料：本文保留旧配置模型的说明，通用 Rule/旧字段不再是当前制作 API。当前入口为 [定义系统](../定义系统.md)、[建筑制作](建筑玩法与制作工作流.md)、[单位制作](../昼夜与战斗系统/单位制作流程.md) 和 [科技制作](../科技系统/README.md)。

正式入口为 `Assets/Landsong/ECSContent/Definitions/Building` 中的建筑资产。建筑不再编辑通用 Rules；每个功能由独立的配置类保存。`BuildingDefinitionInspector` 使用 OdinEditor，字段、模块、条目及嵌套战斗/移动等设置由 Odin `LabelText` 显示中文；`ShowIf` 隐藏不适用的配置，关闭模块保留已填写内容。内容字段直接使用 ItemDefinitionAsset、SoldierDefinitionAsset 等具体资产类型，修改支持 Unity 撤销；编译再检查是否已注册到显式依赖目录。

数值下限使用 Odin `MinValue`，避免 Unity 原生 `Min` 绘制器覆盖中文标签。建筑模块校验也读取同一下限，脚本或资产文件写入的非法值仍会在烘焙前被拒绝。

## 配置步骤

1. 选择建筑资产，填写名称、最高等级、施工回合、占地、耐久等基本信息。
2. 在“功能模块”勾选需要的功能。关闭模块会停止编译该模块的配置，已有输入仍保留，重新启用可以恢复。
3. 展开模块中的列表添加条目。折叠标题会显示等级、物品和主要数量，不需要记忆 B、C 的含义。
4. 物品、兵种、英雄、库存类型、作物和科技直接从当前目录中选择对应类型的资产，也可以拖入；箭头按钮可定位资产。编译通过显式领域目录将已注册资产转换为本域 ID；未注册的同 ID 替代资产也会被拒绝。
5. 留意 Inspector 的错误提示和等级能力摘要。保存后运行原生内容校验，再在编辑器开始新王朝检查实际效果。

## 等级和时间

- “适用等级”：0 表示所有等级，正数表示只在该等级生效。升级不会隐式继承上一等级的配置。
- 放置材料和地形是整座建筑的放置条件，不提供无效的等级选项。种植作物和最终采集奖励会按建筑当前等级筛选，通用奖励与该等级奖励相加。
- “施工阶段”：0 表示每一期，正数表示第几期；不能超过建筑基本信息中的施工回合数。
- “升级目标等级”：例如 2 表示从一级升级到二级时的要求和材料；0 表示每次升级都适用。
- 岗位容量、驻军容量、基础生产周期等单值能力不能同时配置重叠的通用项与指定等级项；校验会拒绝，避免先后顺序决定结果。
- 多条材料可以相加；生产产出档位仍按实际工人范围匹配，多个匹配产出均执行。配置不同档位时应确认边界，0 的“最多工人”表示不限。

## 示例：皇宫开局两名民兵

打开 `b王宫.asset`，启用“驻军”：

1. 在“驻军容量”添加 LV1 条目：驻军容量 3、每批出勤 1。
2. 在“开局驻军”添加 LV1 条目：兵种民兵、人数 2。需要混合兵种时添加更多条目，总人数不能超过容量。
3. “每回合募兵上限”填写 0 表示使用当前驻军容量；这是后续募兵额度，开局赠兵不消耗它。

初始化完成时创建两名普通持久士兵，分配到真实槽位 1、2，保留人口成本、姓名、年龄和战斗属性。它仅用于地图开局已有建筑；运行中建造、升级和读档不会重复赠兵。

## 数据及迁移约束

`BuildingDefinitionAsset.Capabilities` 是建筑功能的作者入口。资产直接声明建筑字段，`Authoring/Definitions/Buildings` 下的嵌套功能 Source 与 Compiler 对应 `Simulation/Definitions/Buildings` 下的运行记录。BuildingCatalogCompiler 直接接收 BuildingDefinitionAsset 和所需领域索引，写入 BuildingCatalogBlob，不再输出 Rule[] 或共享全局内容编号。

29 个建筑保留原 GUID、数值和领域内注册顺序；功能关闭时保留作者输入，但烘焙为空能力数据。DomainDefinitionBaseline.json 覆盖 185 个正式资产的序列化字段和值，BuildingModuleVerification 另检查能力边界、禁用功能、等级结算及显示档位。调整玩法值时审阅对应基线与行为断言，不能批量覆盖基线消除失败。

初始驻军使用 InitialGarrison 的 SoldierDefinitionAsset、等级与人数；Baker 转为 SoldierId，初始化时由建筑领域创建持久士兵。旧的无消费者占位参数不进入新契约。非建筑领域、独立 Settings、强类型引用与新增能力流程见 [定义系统](../定义系统.md)。

当前快照为 v33，ES3 王朝封装为 v4。快照编码领域内索引并用内容指纹绑定稳定 ID、目录顺序、设置和玩法数据；不兼容旧版本，需新建王朝。资产移动保留 meta GUID 和稳定 ID，详见 [运行与存档](../运行时与存档/README.md)。

## 工作效率档位

在建筑资产的“岗位与补贴 → 工作效率档位”中逐条设置建筑等级（0 为通用）、最少工人和最多工人（含上限，0 表示确切的零人，不表示不限）。例如农田当前显式配置 0、1、2、3 人四档。13 个启用岗位模块的现有建筑已补齐各等级配置。

分档不再由 UI 按容量枚举或反推阈值。等级的档位必须连续覆盖 0～岗位容量，不能缺项、交叠、倒置或越界；实际效果发生变化的工人门槛不能被包在一个区间中。相同效果人数可明确合并成区间，例如农田 0～1 人。内容校验只检查错误，不代写或自动修复配置。修改产出、种植门槛等玩法规则时需同步调整档位边界。

实际效果数值继续由生产、作物、仓储、神殿等具名玩法模块配置；档位不是另一套重复的结算参数。BuildingCatalogCompiler 将人数区间烘焙到 Capabilities.Workforce.EfficiencyTiers；WorkerEfficiencyDescriptions 查询这些档位并解释各功能数值，UI 直接展示查询结果。缺少档位时提示未配置，不回退到推导逻辑。

EfficiencyTiers 是只读展示分组数据，不参与玩法内容签名。只改分档范围不改变实际结算或快照格式，也不会导致存档因内容签名变化而失效；修改真正的玩法参数仍遵循原有内容签名校验。
