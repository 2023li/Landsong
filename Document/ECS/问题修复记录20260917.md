# 问题报告修复与验收（2026-09-18）

依据当时的问题报告（原报告未保留于当前仓库）核对完整仓库，而非仅按压缩包中的源码推断。当前工程版本为 Unity 6000.3.24f1、Entities 1.4.8、Entities Graphics 1.4.21、Addressables 2.9.1；精确依赖以 ProjectVersion、manifest 和 packages-lock 为准。

## 修复对照

| 报告问题 | 当前实现与处理 |
| --- | --- |
| 场景异步异常锁死、忙碌请求静默丢失 | 路由接收 `Func<Request, Task>`，提供 `BeginAsync`、`CurrentTransition`、`TryBegin` 和 `LastFailure`。异步失败清除 Busy / Pending；同步拒绝保留原会话。加载面板创建失败仍清理并返回菜单；面板不可用时清理重试有应急入口。 |
| 场景诊断丢失 | 切换异常包含 operation / map / run / slot；存档最新记录读取失败的回退记录来源与异常。菜单进入保留尚未消费的错误消息。 |
| 平行 Moyo 场景轨、强制 GC、隐式单例 | 已扫描代码和资产 GUID，删除无消费者的 SceneTransitionManager / SceneLoadingPipeline、MonoSingleton、Singleton、MoyoConfig 及其资产与 Addressables 条目；删除 AppConstant。没有仅按低引用删除其他组件。 |
| WorldPresentation 每帧分配和重复解析 | 会话持有有类型限制的 EntityQuery；复用删除列表；按实体的 definition / stage / level / FixedString skin 缓存匹配结果（包括无匹配），定义字符串按会话缓存。仅 Transform 改变时写位置/旋转/坡路缩放，仅可见性改变时 SetActive。解绑清理查询与缓存。 |
| TacticalOps 托管 List、平方级预约检查 | 使用 NativeParallelMultiHashMap 空间索引，邻域范围包含双方半径；继续按稳定 ID 分配，保持确定顺序。独立 TacticalSlotSystem 在感知之后、行为树之前执行，不在感知系统内部强制 Complete。 |
| UI / Presentation / Application → Authoring | 新增 Landsong.Content.Runtime；运行时仅读取生成的 ContentDisplay 目录。建筑槽与选择器移出 Authoring，保留脚本 GUID。编译器与过期检查属于 Editor。架构验证禁止反向引用。 |
| 8 份 BindFeature 重复 | GameFeatureViewBase 统一服务验证与绑定；现有功能视图继承同一基类。 |
| UIManager 异步销毁 | ApplicationUiRoot 正常退出等待场景与 UI shutdown；OnDestroy 同步取消操作、释放实例与 Addressables lease。UILoader 原有 lease 所有权保留，迟到异常观察器命名为 ForgetAndObserve。 |

## 保留边界

世界表现仍需遍历可表现实体，以处理单位运动、死亡倒计时和动画；这次消除了重复模型解析和静态 Transform 写入，没有声称已实现完整 ECS changed-filter / 事件管线。接战位仍是按顺序执行的主线程工作，读取感知结果时仍需等待对应 Job；原生临时分配与稳定排序仍存在。性能改善需结合规模基准解读，不能由源码直接推断整帧帧率。

超大文件列表属于重构候选，不能按行数认定缺陷。本轮拆分具有明确维护风险的快照序列化并合并重复 UI 注入，没有为了减少行数重写地图烘焙、建筑美术流水线或 UI 业务规则。

原报告的“UILoader ownership 正向”“AI 边界正向”等项目保留；LINQ / catch / Assets 路径出现次数不是待消灭的缺陷数量。当前没有接入 Ultimate Inventory System，本次不添加 UIS 适配层。
