# 表现层统一

状态：基础架构已实施。民兵已迁移；敌人、英雄和访客等待正式动画资源后按本文逐类迁移。

## 决策

表现资源统一遵循“内容定义 → ECS Prefab → 该 Prefab 自己声明表现”的归属关系。不再为新角色向 `LandsongWorldVisuals.asset` 添加按字符串 ID 查找模型的映射。

建筑和动画角色采用相同的资源归属原则，但保留符合各自生命周期的运行方式：

- 建筑长期存在。`BuildingDefinitionAsset` 引用完整建筑 ECS Prefab，模型、Renderer、选择锚点和 `BuildingVisualSlot` 随 Prefab 一起 Baking。
- 士兵、敌人、英雄及需要骨骼动画的访客保留长期逻辑实体。它们的 ECS Prefab 声明动画表现配置，出勤或需要显示时创建 Rukhanka View，归营或展示结束后释放 View。
- 隐藏 Renderer 不视为卸载动画表现。未显示角色不得继续承担骨骼动画和蒙皮变形开销。

目标关系如下：

```text
BuildingDefinitionAsset
└─ Building ECS Prefab
   ├─ ECS Authoring
   └─ 常驻建筑模型与表现槽

ActorDefinitionAsset
└─ Actor ECS Prefab
   ├─ 长期玩法逻辑
   └─ AnimatedActorAuthoring
      └─ Rukhanka View Prefab（按需创建与释放）
```

其中 `AnimatedActorAuthoring` 是计划中的通用角色表现入口。现有 `SoldierAnimationAuthoring` 先作为士兵实现保留，迁移时再抽取公共生命周期；火把、拔剑、收剑等士兵专属规则继续放在士兵扩展中，不进入所有角色的公共配置。

## 当前状态

- 建筑已经采用定义直接引用完整 ECS Prefab 的方式。
- 正式民兵由 `militia` Definition 直接引用逻辑 Prefab，再由 `SoldierAnimationAuthoring` 直接引用 View，运行时按需创建 Rukhanka 表现；文件夹名称不参与查找。
- `WorldPresentationView` 会跳过带有 `AnimatedUnitVisual` 的实体，避免给正式 Rukhanka 士兵再创建一套 GameObject 模型。
- `LandsongWorldVisuals.asset` 中的 `militia` 映射已移除，编辑器验证会拒绝同一正式动画士兵同时存在全局模型映射。
- 敌人和部分英雄尚未具备正式动画表现，暂时继续走旧路径，不允许新角色继续扩展这条路径。

## 新内容制作规则

1. 新建筑继续使用现有建筑 Prefab 与 `BuildingVisualSlot` 工作流。
2. 新动画角色必须由自己的定义资源引用 ECS Prefab。
3. 角色 ECS Prefab 必须显式引用自己的 Rukhanka View Prefab。
4. View Prefab 负责骨骼、蒙皮、动画控制器、动画层、装备挂点和 Renderer。
5. 不为新士兵、敌人、英雄或动画访客增加 `LandsongWorldVisuals.asset` 模型条目。
6. 表现创建与释放不得改变角色的稳定 ID、等级、经验、装备、所属建筑或存档身份。

## 迁移步骤

### 1. 固化现有士兵路径（已完成）

- 验证出勤创建 View、归营释放 View、死亡延迟释放和存档恢复。
- 已核验并移除 `LandsongWorldVisuals.asset` 的 `militia` 条目。
- 保留防重复表现检查，确保同一实体只能拥有一种活动表现。

### 2. 抽取通用动画角色入口

- 从 `SoldierAnimationAuthoring` 和对应系统中抽取 View 创建、绑定、显示、暂停和释放的公共生命周期。
- 公共部分命名为通用角色概念，例如 `AnimatedActorAuthoring`、`AnimatedActorState` 和 `AnimatedActorViewOwner`。
- 士兵装备切换、火把、持剑和士兵庆祝继续由士兵专用组件或系统处理。

### 3. 分批迁移其他角色

- 有正式动画资源时，依次迁移敌人、英雄和访客。
- 每类角色迁移完成并通过编辑器验证后，删除它在 `LandsongWorldVisuals.asset` 中的对应映射。
- 不要求一次性迁移全部角色；未迁移内容可临时使用旧表现路径，但不得新增对旧路径的依赖。

### 4. 收口旧表现目录

- 角色迁移完成后，移除 `WorldPresentationView` 中按角色稳定 ID 生成模型的职责。
- 根据剩余用途决定将 `WorldVisualCatalog` 缩减为非角色临时表现目录，或完整删除。
- 建筑继续使用自身 Baking 表现，不迁入这个目录。

## 验收条件

- 每个正式内容定义都能从定义资源追踪到唯一 ECS Prefab，再追踪到唯一表现来源。
- 新角色无需编辑 `LandsongWorldVisuals.asset` 即可正确显示。
- 未出勤角色不存在活动的 Rukhanka View、骨骼动画和蒙皮变形负担。
- 出勤、归营、死亡、暂停、存档恢复和场景重载后不会出现重复模型或残留 View。
- 建筑的施工、等级、皮肤、废墟和作物表现不受角色表现迁移影响。
- 编辑器验证覆盖表现唯一性、View 生命周期、Rukhanka 注册和存档恢复；验证阶段不执行 Player Build。

## 不在本次范围

- 不修改战斗、导航、出勤、归营或访客玩法规则。
- 不把未出勤士兵的长期玩法数据移出 ECS 实体。
- 不要求静态建筑与骨骼角色采用完全相同的运行时生命周期。
- 不在缺少正式模型和动画资源时强制迁移占位敌人、英雄或访客。
