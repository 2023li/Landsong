# 肖像系统现行实现规格

本文已按 2026-09-09 确认结果和现有 ECS 项目更新，取代初稿中的示例类名、阶段计划和未落地假设。实现使用项目原有角色、UGUI、存档和事件流程，不建立第二套人物状态。

## 已确认玩法

- 王室、交际人物/人才、士兵和战斗英雄接入统一肖像生成与展示。肖像只影响外观，不改战斗数值。
- 默认 16 岁切换为青年，可在项目配置中修改；婚姻成年年龄仍由 Court 配置控制。幼儿不需要脸部美术，使用带不同基础颜色的程序摇篮/襁褓。
- 青年基础 DNA 在人物生成时就固定。中老年发色逐步变灰，面部皱纹由程序生成，不要求每个部件另画年龄版本。衰老不改写可遗传的基础颜色。
- 每种基础颜色独立选择父亲或母亲，默认 5% 从项目色盘独立抽取。父母有同色也可能抽到相同色，独立抽取不保证视觉上不同。五官、发型和饰物随机，不做部件遗传。
- gene.beauty（丽质）沿用既有特性遗传概率，无额外属性效果。有该特性且达到青年年龄、仍在世、未使用机会的人物可捏脸一次；可以稍后处理，完成后不能再捏脸，但仍自然衰老。子女可继承父母修改后的三种基础颜色。
- 捏脸只切换当前库中性别兼容的已有部件与 RGB 颜色，不上传图片、不自由变形、不生成新美术。窗口草稿不写 ECS，确认通过命令一次提交。
- 每名士兵首次生成姓名、年龄、性别、寿命和肖像。每回合黎明年龄结算一次，仅自然死亡原位换人；属性、经验、驻军槽和人口成本保留。战死依旧减员。
- 玩家改名的士兵持久标记；自然死亡或战死生成一次纪念消息，重要历史冻结原名。换人清除该个体的命名和通知标记。回退存档同时回退这些故事事件。
- 历史家谱保留，死亡人物仍展示原 DNA 与死亡年龄，整张肖像置灰。

## 项目配置

配置资产：`Assets/Landsong/ECSContent/PortraitConfig.asset`，由 `GameCatalog.asset.Portraits` 引用。

| 字段 | 当前默认 | 用途 |
| --- | --- | --- |
| Resolution | 64 | 项目统一采用 32×32 或 64×64，不自动缩放素材 |
| Placeholders | true | 程序占位与正式部件共同加载，便于逐步导入；正式素材齐备后可关闭 |
| Settings.YouthAge | 16 | 摇篮/襁褓切换为青年，也决定丽质解锁 |
| Settings.GreyAge / ElderAge | 50 / 75 | 渐灰和皱纹的起止年龄，分为十档缓存 |
| Settings.ColorMutation | 0.05 | 每种颜色独立抽色盘的概率，其余等概率取双亲 |
| SoldierRecruitMinAge / MaxAge | 18 / 30 | 士兵出生身份和自然补员年龄范围 |
| SoldierLifeMin / Max | 65 / 85 | 士兵自然死亡年龄范围 |
| SkinColors / HairColors / EyeColors | 不透明 RGB 色盘 | 随机出生和独立遗传颜色，捏脸可使用色盘外 RGB |
| Parts | 正式素材列表 | 稳定 ID、类别、适用性别、随机权重及渲染层 |

当前配置由 Authoring 烘焙进只读 Blob；修改资产后重新进入游戏生效。运行时捏脸修改人物 DNA，不直接修改项目配置或 Blob。英雄沿用现有无年龄/性别玩法，默认成年男性占位，不因本系统新增自然死亡或婚姻。

## 美术制作与覆盖

美术成品统一存放在 **`Assets/Landsong/Art/Portraits/Parts/`**。优先使用 Unity 菜单 **`Landsong → ECS → Portraits → Import parts`**（窗口标题“肖像部件导入”），从任意源目录选择 PNG，或把 Project / 文件系统中的 PNG 拖入对应文件栏。窗口复制原文件并自动登记当前 `GameCatalog.Portraits`，不移动源文件。仅把 PNG 拖进文件夹不会自动登记到部件库。

导入步骤：

1. 确认窗口顶部项目尺寸。当前默认 64×64；若项目改成 32×32，只能导入原始 32×32 PNG。必须使用完整统一画布，不允许导入器缩放、裁切或 Sprite 切片凑尺寸。
2. 选择类别，填写唯一稳定标识，例如 `hair.short_01`。标识以英文字母开头，最多 64 字符，只允许英文、数字、点、下划线、短横线；禁用路径字符、系统保留名、`placeholder.` 前缀。重名、哈希冲突及已存在目标目录均拒绝覆盖。
3. 勾选“男用”“女用”，至少一项；两项都选表示通用。同一个逻辑部件的性别和随机权重共用，多层会作为一个部件一起选择。Weight 非负，0 只供丽质选择、不参与随机。
4. 从“可添加图层”选择需要的程序层，点击“添加图层”后填写 PNG；可用“移除图层”删除不需要的层。**任何特定程序层都不是必填项**，一个逻辑部件至少提供一张有效 PNG 即可；未提供 PNG 的行不参与导入。例如发型可仅前发、仅后发或前后发一起导入，服装也可仅前层或仅后层，不需要补全透明图片。逻辑部件拆成多层时继续添加，每个程序层最多一次，多层不能重复选择同一源文件；列表只提供与当前类别匹配的图层。
5. 需要染色的图层以灰度保留明暗，选择 Skin / Hair / Eyes；固定颜色选择 None。发型前后层固定使用发色通道，以保证统一换色和程序衰老。右侧棋盘预览展示原图透明叠层。
6. 点击“导入并登记部件”。自动创建 `Parts/<类别>/<稳定标识>/<渲染层>.png`，例如 `Parts/Hair/hair.short_01/HairBack.png` 和 `HairFront.png`。自动设置 Sprite Single、完整矩形、中心 Pivot、Point、Clamp、可读写、无压缩、无 Mipmap；原始 PNG 字节保持不变。
7. 导入时重新校验文件真实内容及尺寸，最多每张 4 MB；不信任已有 Unity 缩放后的预览尺寸。全部文件导入和候选部件库烘焙成功后才登记配置；中途失败恢复原 Parts 并清理本次部件目录。成功后可点击“填写下一个部件”。导入不提供覆盖已有部件的操作，也不自动删改已有美术。

逐步替换：`Placeholders=true` 时两类部件一起进入随机池和丽质选择；已有占位 DNA 仍有效。不要导入第一套发型后就关闭占位，正式库仍需为男/女各提供可随机的 Face、Eyes、Body、Clothes。关闭占位会移除占位 ID，因此不能继续加载使用这些 ID 的旧人物快照。窗口“校验当前肖像库”可检查当前库。

导入窗口与 Baker 共用部件规则，都允许单层或多层逻辑部件。手动编辑 Parts 也不能绕过非空部件、类别/图层匹配、重复层、性别范围、尺寸/Pivot/Point/Mipmap/可读 Sprite 校验。项目尺寸改变后，已有不匹配素材会导致校验失败，不会静默缩放。

稳定 ID 写入 DNA 后不能当作数组下标随意改名或删除；替换同 ID 的像素前应保持类别、性别与层结构兼容。本轮窗口接入 13 类现有单选部件；SkinDetail 多选与独立 Effect 流程仍属于后续扩展。

固定整图覆盖仍使用 `Resources/LandsongPresentation.asset.Portraits`：先匹配非零 Person，再匹配 Definition，最后 DefaultPortrait。完整覆盖图保持原样，且由原资源所有者管理，不由生成缓存销毁；程序衰老作用于模块化肖像。完成丽质后使用模块化结果，遗传始终读取 DNA 基础颜色。

## 数据和渲染

- `PortraitDNA`：13 个单选槽（Face、Ear、Eyes、Eyebrows、Nose、Mouth、Hair、FacialHair、Body、Clothes、HeadAccessory、FaceAccessory、Accessory），最多 8 个 SkinDetail ID，三种 Color32、Seed、Customized、InvitationAnnounced。
- `SoldierPerson`：年龄、寿命、最后年龄结算回合、性别、换人次数、玩家命名/死亡通知标记。军事实体和 Soldier 数值独立保留。
- `PortraitConfig` → `PortraitLibraryBuilder` → `PortraitLibraryBlob`：只读部件、渲染层、像素、色盘和设置。当前程序占位提供多种脸型、眼睛、嘴型、发型、服装及可选胡须/帽子，不生成外部图片文件。
- 图层顺序为 BackAccessory、HairBack、NeckBack、Body、ClothesBack、Neck、FaceBase、Ear、Eyes、EyeOverlay、Eyebrows、Nose、Mouth、SkinDetail、FacialHair、HairFront、ClothesFront、HeadAccessoryBack、HeadAccessoryFront、FaceAccessory、FrontAccessory、Effect。同层按 DNA 槽与部件渲染顺序稳定合成。
- 皱纹只绘制在 FaceBase 已有非透明像素上，再覆盖后续五官层。发色变化只影响 Hair 染色层，不把老年灰色写回可遗传颜色。
- SkinDetail 的多选数据、排序、保存和合成已预留，当前占位不生成该类素材，捏脸入口只处理 13 个单选槽和颜色。Effect 可作为部件渲染层，当前没有独立临时光效玩法或特效 DNA 流程。
- `PortraitComposeSystem` 在 PresentationSystemGroup 调度 Burst IJobEntity，只处理未完成任务。任务在像素 Buffer 中输出；Sprite/Texture 创建与 UI 发布留在主线程。
- `PortraitCache` 归 Game Canvas 所有，同 DNA/年龄档/性别/库像素版本共用 Sprite；每次最多 8 个合成任务。128 项为缓存保留目标，正在显示的项不会为淘汰而中断；超出视口的绑定释放引用，优先淘汰无引用旧项。隐藏/重开、读档换实体和切图均重新绑定或清理。
- UI 定期读状态判断是否换 Key，但不每帧重新合成全部人物。相同成年年龄档共用纹理，RGB 预览改动会换 Key。

## UI 接入

`PortraitImageBinding` 统一连接家谱、右侧人物详情、人才卡片、赐婚左右详情、驻军列表/士兵详情与英雄 HUD。已有点击和请求操作继续使用人物稳定 ID。

丽质初成时记录事件，在 HUD 提示和个人“处理请求”中保留待办，并计入家谱请求标记。捏脸窗口左侧预览，右侧滚动切换部件和设置 RGB，底部固定确认/稍后按钮。确认仅白天未暂停时合法；未持有丽质、未到青年、死亡、机会已用、种子过期、部件不合法都由 ECS 拒绝。关闭或 Esc 不消耗机会。

## 存档与验证

格式升级为快照 v22，王朝封装仍为 v3。保存 DNA、一次性状态与士兵个人状态，不保存生成贴图和缓存。恢复不重新随机；严格校验稳定部件 ID、性别、颜色、年龄和标记；恢复失败事务回滚。年龄/遗传/士兵寿命设置进入内容签名，旧版快照拒绝加载，需要新开王朝。

编辑器验证入口：`Landsong/ECS/Verification/Run all` 的 PortraitVerification，覆盖 32/64 合成、Alpha、颜色/年龄缓存、性别兼容、丽质门禁与一次性确认、颜色遗传、快照往返/回滚、士兵自然补员/战死纪念。四场景 HUD Play 流程另覆盖缓存共享、关闭重开、实时 RGB 草稿、取消/确认、恢复和程序化衰老。测试输出在 `Library/LandsongEcs/`。本轮遵守仅编辑器验证，不构建应用。

导入工具代码：`Scripts/ECS/Editor/PortraitImportWindow.cs`、`PortraitPartImporter.cs`；共享规则：`Scripts/ECS/Authoring/PortraitPartRules.cs`。编辑器领域测试 `PortraitImportVerification` 使用临时 PNG/配置验证 32/64、单前发/单后发导入与合成、身体多层、单层服装、按需增删层、空部件/性别/重复拦截、无缩放复制、实际导入设置、失败清理、窗口提交门禁与原项目配置不变。
