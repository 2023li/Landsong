# 开发规范

## 代码与状态

1. 手写代码统一放在 Assets/Landsong/Scripts。遵守 ECS、Presentation、Editor 三个程序集边界；编辑器工具置于 Editor，完整流程测试置于 Presentation/Tests。
2. 移动资产和脚本时一起保留 .meta GUID，不创建重复脚本根或重复启动场景。
3. Component / Buffer 只保存运行数据；不以 Transform、GameObject、ScriptableObject 作为第二套玩法状态。Authoring → Baking → 只读 Blob → 运行实体。
4. UI 读取状态、显示共享 Quote、提交 Command；合法性、阶段门禁和扣费由 ECS 校验。不得在 UI 中直接修改库存、单位、等级或发奖。
5. 配置 ID、个体 ID、来源建筑 ID 和真实驻军槽号保持稳定，不以数组排序、名称或 Entity 句柄替代身份。
6. Gameplay RNG 使用受控随机状态；禁止 UnityEngine.Random 决定结算、命中或奖励。

## 事务与生命周期

- Entity 结构变更后重新获取失效的 Buffer / 引用；明确 Job 依赖，处理 Native 容器、BlobAsset 和临时 World 的所有权与释放。
- 所有动态实体登记 SimulationOwner；切图或根失效必须清理。表现模型、粒子和音源不写入玩法快照。
- 白天按稳定 ID 逐栋结算。普通生产、招聘、吃饭不使用待存放池；修复可优先消耗待存放，正常库存部分仍需资源连接。
- 经济记录只在实际成功变更时写入，内部转库不算收入。库存事务同时撤销资源、账本和历史，避免重复日志。
- 预测和入夜预演不得修改正式资源、历史、节点、随机状态或授权。状态变更使旧确认失效。
- 快照新增持久状态时同步实现 Capture / Decode / Restore、内容签名、合法性验证、事务回滚和往返测试。
- RestoreTransaction 同步完成，不跨帧；保留原实体直到候选数据、出勤准备和发布均成功。可变根组件和 Buffer 必须纳入 RootState。
- 文件先写临时内容再原子替换并保留备份。槽操作使用 RunId / SlotId / 内容指纹；不能误伤其他王朝或自动节点。结束王朝先写覆灭记录，禁止副本复活。

## 昼夜和军事

- 一回合为白天 N + 夜晚 N，黎明才进入 N+1。敌军事件和基础预算按回合开始战力锁定，黄昏冻结当夜军事数值。
- 核心失守重试生成一次恢复票据；白天/黄昏选择共用票据，重抽编成/位置并只降低当夜预算。不向玩家显示次数、种子或援助比例。
- 生成与情报共用合法入口/目标规则。出生区内无合法点应取消并提示，不跨区强行找点掩盖失败。
- 所有攻击经 Projectile → DamageRequest → CombatOps。发射时冻结载荷；先校验阵营、保护、遮挡和减伤，再发布有效伤害/死亡/经验事件。
- 持久士兵与工人分开，驻军槽从 1 起算。未分配士兵和待存放物资在下一夜前通过真实损失预演确认清空。
- 英雄不同于人才；供奉、唤醒成本与实际参战经验分开。只在真实生效的效果后记录贡献，不把空放、待命或平安抓捕当成战斗。
- 战斗为 1×，平安夜可 2×，战斗收尾固定 10 秒。暂停、情报模式、终局和收尾均在命令层限制操作。
- 小偷与精灵独立配置；小偷生成不预留赃物，逃离时才从绑定来源当前合格库存扣除。实时消息不得泄漏被盗明细。
- 特殊掉落不遗漏，无法生成时直接记账，收尾自动收集。夜间奖励暂存，黎明先提交损失再入库，溢出进入待存放。
- 战报和通用历史保存来源名称/位置快照，不能从已经销毁的实体或当前改名结果重算历史。

## UI、文本与表现

- 四场景及动态 UI 全部使用 TMP。编辑输入框保持原文；选择、滚动和输入焦点不因定期刷新丢失。
- 暂停记录打开前的暂停状态，Esc 负责暂停/子页返回；UI 起拖不穿透到地图，TMP 焦点阻断玩法快捷键。
- 建筑分类按已拥有蓝图过滤，不按当前能否支付过滤。所有破坏性操作需要明确对象与失效确认检查。
- 应用设置独立于王朝，草稿须应用；显示变更超时恢复。
- 文本使用语义 Key，外部语言包仅加载校验后的文本；不加载外部代码、字体或任意路径。共享字体/图集，不为每个控件或切图复制字体。
- 纯表现 Prefab 按白名单接入，禁用 Root Motion。模型/动画只消费 ECS 状态，不能回写移动、伤害和奖励。
- 声音使用统一有界音源，不增加重复 Listener。暂停冻结世界动画、粒子和世界短音效；UI 声音保持可用。

## 验证与交付

改动按风险运行内容校验、领域回归、真实 Play 和独立构建。编译通过不等于玩法通过。测试不读写玩家正式存档，不覆盖未保存场景；临时设备、设置和测试文件必须在 finally 中归还或清理。

完整验证只有一个总入口 ProjectVerification；领域套件不互相递归调用。EcsPlayerSmoke 仅编译到编辑器 / Development Build，独立程序还需显式启动参数。保留可复用断言，不把迁移安装器当日常制作工具。

文档只维护当前实现、工作流和限制，不追加互相冲突的历史版本说明。测试输出位于 Library/LandsongEcs，不提交生成文件。
