# Layer 与 Blueprint 地形规则

一个 Blueprint Layer 只代表一种逻辑用途、一种地形。Blueprint 整数格定义各地形的覆盖范围；去掉规范的 `L数字_` 前缀后，通过 `分层地形规则.asset` 的共用规则名称映射单一 `TerrainType` 枚举、建造和通行权限。同层覆盖顺序由独立的 `地形覆盖排序.asset` 决定。两个 SO 都位于 `Assets/Landsong/GameMaps/`。TilePreset、FBX、碰撞体、TileType、Dual Grid、Build 显隐、视觉缩放和高度偏移均不参与逻辑计算。

## 制图

- Blueprint 文件夹命名为 `Layer0`、`Layer1` 等，编号非负且唯一。组内启用 Blueprint 的 Default Layer Height 必须等于编号，逻辑高度单位固定为 1；不一致时校验报错，不静默修改画稿。
- Build 文件夹可叫 `LayerView_0` 等；用 `assignedBlueprintLayerGuid` 关联 Blueprint，Build 文件夹的名字不参与逻辑。
- 每个启用的地形 Blueprint 去掉 `L数字_` 前缀后，必须精确匹配一条 SO 共用规则。例如 `L0_陆地`、`L3_陆地` 都匹配 SO 中的 `陆地 → 陆地枚举`，SO 不再填写 `L0_陆地`。不带前缀的 Blueprint 名称也可直接匹配。规则区分大小写，不做包含匹配或模糊匹配。
- 前缀编号必须与所在文件夹一致：`L3_陆地` 只能放在 `Layer3` 中；`L03_陆地`、空名称等不规范输入报错。高度只读取文件夹编号，名称编号用于校验。新增 `Layer3`、`Layer12` 无需复制任何已有地形规则；新层中各 Blueprint 的 Default Layer Height 仍须填写对应层号。
- Blueprint 不需要任何 Build Layer 或 TilePreset 就能生成逻辑地表；同一个 Blueprint 的视觉预设可以自由替换和混用。
- 同层同格取覆盖排序 SO 中最靠上的地形，拖动顺序即可调整；TWC 图层顺序不影响结果。排序不能重复、包含组合值或遗漏映射中的地形。同种地形重叠时权限必须一致，否则报错。主地形替换后不保留被覆盖地形标签或权限。
- 同 XZ 最高 Layer 作为主地表，建造仍使用这一主地表且所有高度共用一份 XZ 建筑占用。低层允许通行的格自动成为额外导航地表，因此高处建筑不自动封闭桥下整列路线。
- 不同层相同规则名称共用地形和权限，不能按层重复声明不同权限。改变 Blueprint 的地形名称时需确保新名称在 SO 中有规则；仅改变层号时不需要改 SO。Layer 连接绑定文件夹 GUID，每层由编号分配稳定 Surface ID（编号 + 1）；重新命名编号意味着改变逻辑高度，需同步 Blueprint 前缀和 Default Layer Height，重建文件夹后已有连接必须重新绑定。
- 地图范围来自 TWC Settings 宽高，边缘宽度在 `MapContentAuthoring` 设置，见下节，不再绘制“边缘区” Blueprint。

## 地图宽高与边缘

地图范围直接采用 TWC **Settings → 宽度、高度**，坐标为 `0 ≤ X < width`、`0 ≤ Z < height`。`MapContentAuthoring` 显示只读宽高，并设置 **边缘（格）＝5**；不再选择 base 层。所有逻辑地形与斜坡必须位于矩形范围内，越界时校验报错，不静默裁剪。

边缘按矩形四边向内取指定格数。例如 128×128 地图内收 5 格，中间为 118×118，边缘共 2460 格。0 表示不预留边缘；过大的宽度覆盖整个地图。孔洞、岛屿岸线和外部连通缺口都不会改变这条矩形边缘。

范围内没有 Blueprint 地形的格子保持空白，不能建造、通行或刷怪。运行地图保留完整 Settings 宽高，不再收缩至有地形格子的外包框；删除或禁用原来的水域层不会影响其他地形或地图范围。旧测试地图的基础层名称仅作为旧地形输入保存在隐藏兼容字段中，不再决定边界。

整个边缘范围都不可建造，包括桥梁跨度与斜坡道路；其中原本可通行、且能到达城市的格子才可作为刷怪入场候选。地形和通行权限不变，水域不会因为落在边缘就强制变成可通行。边缘作用于最高主地表，Layer 高度规则保持不变。

组件上的 **检查地图范围与边缘** 按钮可在未配置核心建筑、尚未完整烘焙时检查范围，报告有效格数、边缘格数及可通行格数。完整烘焙仍要求合法的入场路线和初始建筑。调整宽度后按正常流程重新烘焙，运行输出不会被检查按钮改写。

默认覆盖顺序为 `障碍 > 石地 > 泥地 > 沼泽 > 陆地 > 水域`。障碍保留给旧地图或今后明确配置的障碍 Blueprint；当前地图没有自动添加障碍图层。陆地、石地、泥地默认可建、可通行；水域默认不可建、不可通行。

当前映射包含共用的陆地、水域、石地、泥地、斜坡规则。例如 `L3_石地` 会直接匹配石地规则。首次新增沼泽时，只需在 SO 增加一次 `沼泽 → 沼泽枚举`，此后所有层的 `L数字_沼泽` 共用它；如果新增的是已有枚举地形，不需要修改代码。新增全新枚举类型时，使用新的独立位值，更新 `All` 并把它加入覆盖排序，不能重排现有枚举数值。

## 建筑允许与排除地形

建筑定义的“放置地形”只有两个枚举多选字段：

- **允许地形**：占地的每一个格子都必须属于选中的地形之一；“全部地形”允许所有已定义地形，“无”禁止放置。
- **排除地形**：占地任一格属于排除集合就拒绝；与允许集合重叠时，排除优先。

例如沼泽专属建筑设置“允许地形＝沼泽、排除地形＝无”；允许跨石地与泥地的建筑同时勾选石地和泥地。地形筛选通过后仍需满足可建权限、平整、边缘区、占用及斜坡限制。桥梁/阶梯建筑的地形筛选检查支撑端点，不把桥下地形当作桥面地形。

已有 29 个建筑定义已迁移：采石场从“陆地＋石矿标签”改为只允许石地，其余保留原先只允许陆地的限制。想允许其他建筑放在石地或泥地上，需要在该建筑的允许地形中勾选；地图的“可建”不会绕过建筑自己的地形限制。

编辑地图时可运行 `Landsong/地图/检查当前 Blueprint 地形映射`，检查未映射图层、覆盖规则和高度，并在 Console 查看每层覆盖后的地形格数。结果同时写入 `Library/LandsongEcs/current-terrain-report.txt`，不保存场景或改动绘图。

纯修饰和连接视觉的 Blueprint 可在 SO 中按名称声明对应用途，不生成逻辑地表。连接视觉不会自动创建连接；逻辑连接另行绘制。

## 台阶与桥梁连接

选中地图根下的“导航地表与连接”对象：

1. 添加逻辑连接，选择入口和出口 Layer。
2. 点击“在 Scene 点选入口/出口”，在对应高度的数学网格平面点选逻辑格。此操作不向模型或碰撞体发射射线。Esc 取消。
3. 设置宽度及是否双向。端点表示通道第一条车道的入口和出口格。
4. 点击“校验全部连接”。编辑器检查端点整排通行地表、跨度、重复连接 ID、逻辑地形相交及通道净空。
5. 执行正常地图烘焙，连接与额外地表写入 MapAsset。

第一版沿用矩形直通道：端点须沿 X/Z 轴，长度（含端点）3～128 格，宽度 1～32 格；入口选择低层，出口选择同层或高层，高差最多 32。单向连接由入口通向出口。固定连接沿用运行系统 1.5 世界单位的逻辑净空。地形不能占据通道内部的同高度或更高位置；应在对应地表掩码中留出通道空间。转折楼梯由多个连接和平台组成。

连接保存 Layer 文件夹 GUID 和逻辑坐标，不保存独立高度；编译时从 Layer 得到端点高度和高差。单位在连接上的连续移动高度由端点插值。逻辑地表 Height 为 Layer 高度，既有单位中心的 0.5 偏移仅是单位锚点约定，不来自模型、不写入地表 Height。

## 突出式斜坡

菜单 `Landsong/地图/配置突出式斜坡 My斜坡` 给当前已有 Layer1 及更高层添加空的 `L<n>_斜坡` Blueprint 和对应 `Landsong Slope` Build，绑定 `My斜坡.asset`。新增 Layer 后可重复执行，只复用 SO 中唯一的 `斜坡 → ProtrudingSlope` 规则，不增加按层重复的规则。TilePreset 不决定逻辑。`Layer3/L3_斜坡` 自动连接 Layer3 和 Layer2。

斜坡在高地平台外侧占一排，至少 `左+中+右` 三格，深一格、高差一。高地直边必须至少六格，两端各避开一个角格；斜坡占地与下口必须是 n−1 层可通行地表，上口必须是 n 层可通行平台。编译从 Layer 自动生成双向连接，45° 模型要求 Cell Size=1。平台逻辑范围不变，不再手动重复添加该连接。

斜坡格只允许 `BuildingCategory.Road` 的 1×1 普通道路，禁止其他建筑和跨格道路；保留道路原有地形限制、XZ 占用与正的移动代价。导航与逻辑射线使用连接的单格高度曲线，端点高度只读取 Layer，忽略模型。道路视觉自动倾斜。

绘制或修改平台后使用顶部绿色按钮完整构建所有 Build Layers，再正常烘焙。专用构建层选择左/中/右模型，在生成网格副本上接平平台草沿、避开岩壁穿插，不修改原陆地 FBX。详见 `ArtSource/MyTileSlope/README.md`；验证菜单 `Landsong/ECS/Verification/Protruding slopes`。

`Landsong Slope` 构建层也提供 **Global Offsets → Layer Y Offset**。该偏移只平移生成的斜坡及其左右衔接修整，逻辑端点仍为 n−1 和 n；改变偏移后重新执行 Build Layers。多层斜坡可分别设置偏移，所有衔接修整会读取各自构建层的偏移，重复生成从原网格计算，不累积变形。

当前 `My斜坡` 的模型上口为局部 Y=0.5、下口为 Y=−0.5，构建根在 Layer n：偏移 −0.5 时上口在 n、下口在 n−1。当前陆地中心模型顶面也是局部 Y=0.5；普通 Tiles 层没有其他高度/缩放时，两者使用相同偏移即可衔接。若都设为 −1，虽彼此衔接，但视觉地表低于逻辑面 0.5。不要通过修改 Blueprint Default Layer Height 来补偿模型。
