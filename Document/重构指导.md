审查日期：2026-09-11。以下第 1–11 节保留实施前工作区的审查基准，不只看 Git 已提交版本。用户随后授权全部批次实施，实际修改及验收结果见 [重构执行记录](重构执行记录.md)。文中原路径、行号和数量用于定位审查时状态，迁移后的制作入口以执行记录及各专题现行文档为准。

初次审查阶段只新增本文，未修改业务代码、场景、预制体或配置资产。该阶段采用文档阅读、代码调用链检查、程序集检查及 Unity YAML 静态核查，未启动 Play、重新编译、构建或进行实际 Inspector/分辨率可视验收。下文区分“已确认实现”“静态发现的缺陷”和“需要运行验证的风险”，不以历史验证报告代替实施后的验收。

## 1. 结论与评分

**实施前评分：项目整体架构 56 / 100；UI 架构 35 / 100；非 UI 架构 70 / 100。**

当前 UI 需要一次覆盖生命周期、职责、资源组织和制作流程的系统重构。仅移动脚本、改名前缀、把现有整套 UI 放进常驻 Canvas，无法解决核心问题。

非 UI 部分已有值得保留的设计：ECS 权威状态、Command 校验、稳定身份、受控随机数、内容单向编译、事务恢复和领域验证。建议保留这些基础，修复已经发现的一致性缺口，并逐步收紧模块边界。没有依据要求把整个游戏推倒重写。

## 2. 首先澄清：设置和存档到底有没有重复

### 2.1 设置：资源已经复用，实例与宿主生命周期尚未统一

Start 和 Game 使用的是**同一份设置 Prefab 的两个场景归属实例**，不是两套独立设置控件。两个实例只覆盖根布局、名称和激活状态，没有发现分别复制内部设置控件的情况。

证据：

- 共用资源：[ECS_UI_Settings.prefab](D:/UnityProject/Landsong/Assets/Landsong/Objects/Prefabs/UI/Common/ECS_UI_Settings.prefab)。
- [Start.unity:7354](D:/UnityProject/Landsong/Assets/Landsong/Scenes/Start.unity:7354) 与 [ECS_UI_Game.prefab:85213](D:/UnityProject/Landsong/Assets/Landsong/Objects/Prefabs/UI/UIGamePanel/ECS_UI_Game.prefab:85213) 引用相同 Prefab GUID。
- 打开入口分别位于 [EcsMainMenu.Management.cs:46](D:/UnityProject/Landsong/Assets/Landsong/Scripts/ECS/Presentation/EcsMainMenu.Management.cs:46) 和 [GamePauseMenu.cs:42](D:/UnityProject/Landsong/Assets/Landsong/Scripts/ECS/Presentation/GamePauseMenu.cs:42)。

剩余问题是 Start 的设置遮罩、Game 的暂停分页、返回路径和实例生存期仍由各自宿主维护。应把现有设置资源迁移为唯一的 `UI_SettingPanel.prefab`，由持久 UIManager 按需创建、缓存一个实例；两处入口只传打开上下文。保留现有设置草稿、应用保存、改键和显示回滚逻辑，不重做一套。

“共享实例”指同一应用 UI 管理器在需要时复用同一个面板，不要求设置界面从启动起一直创建、显示或刷新。

### 2.2 存档：确实有两条展示和操作链路，但功能权限不同

| 当前入口 | 展示代码 / 模板 | 当前职责 |
| --- | --- | --- |
| Start 加载游戏 | `ArchiveBrowser` / `ArchiveRowView` | 跨王朝浏览、自动节点和独立槽、备份、重命名、删除、覆灭记录 |

证据：[ArchiveBrowser.cs:30](D:/UnityProject/Landsong/Assets/Landsong/Scripts/ECS/Presentation/ArchiveBrowser.cs:30)、[GamePauseMenu.Slots.cs:17](D:/UnityProject/Landsong/Assets/Landsong/Scripts/ECS/Presentation/GamePauseMenu.Slots.cs:17)、[Start.unity:5403](D:/UnityProject/Landsong/Assets/Landsong/Scenes/Start.unity:5403)、[Game 存档模板引用:29851](D:/UnityProject/Landsong/Assets/Landsong/Objects/Prefabs/UI/UIGamePanel/ECS_UI_Game.prefab:29851)。

目标为一个 `UI_SavePanel`，接收明确的 `Load / Save / Manage` 模式和上下文。上下文包含当前 RunId、选中 SlotId、允许的操作、来源导航和应用服务；实际能力由服务查询，UI 显隐不构成权限校验。存档 IO、指纹校验和载入流程不放进面板。

主菜单进入时可以浏览其他王朝；游戏中保存仍只能写当前王朝。不得因共用面板而把“覆写当前槽”“载入其他王朝”“恢复备份”混成同一种操作，也不得让共享面板长期保留已卸载会话的回调。

## 4. 目标 UI 结构

### 4.1 唯一应用 UI 根

Boot 的显式启动配置创建或持有 `UIRoot.prefab`。UIManager 挂在根 Canvas 上，整个 UIRoot 使用 DontDestroyOnLoad。根负责唯一的 CanvasScaler、GraphicRaycaster 和 EventSystem；业务场景不各自创建 UI 根。

```text
UIRoot  [Canvas + CanvasScaler + GraphicRaycaster + UIManager]
├─ EventSystem  [明确配置输入模块]
├─ BackgroundLayer
├─ HUDLayer
│  └─ UI_GamePanel                  按游戏会话创建/释放
├─ NormalLayer
│  └─ UI_StartPanel                 菜单流程打开
├─ PopupLayer
│  ├─ UI_SettingPanel               全应用共享，首次打开才创建
│  ├─ UI_SavePanel                  全应用共享，明确打开模式
│  └─ UI_ConfirmPanel               通用确认，可带失效条件
├─ ToastLayer
│  └─ UI_ToastPanel                 轻量提示
├─ GuideLayer
└─ BlockerLayer
   ├─ UI_BootPanel                  开幕展示，可选根面板
   └─ UI_LoadingPanel               过渡时遮罩和进度
```

以上层首先使用普通 RectTransform。采用一个持久根 Canvas 满足当前目标；默认不增加多个子 Canvas。后续只有明确的刷新隔离/排序需求并经测量后，才增加归属于此根的局部 Canvas。

Start、LoadingTransition 场景可以继续保留为轻量流程/背景场景，不要求为了改 UI 同时删除场景。Game 保留相机、灯光、地图 SubScene 和会话宿主。其可用状态通过明确的会话上下文交给应用流程，再绑定 GamePanel，不扫描场景取引用。

开发时从 Start/Game 点 Play 也必须经过同一启动配置。可由 Editor 启动入口指定 Boot 并携带“跳过开幕/返回菜单”等意图，不用 `UIManager.Instance` 自动搜索或创建一个缺配置的 Manager。

```text
   └─ 建筑专属操作弹窗
```

只有具有独立应用生命周期的根面板继承 `UIPanelBase`、登记到 UIManager。子窗口和列表条目采用 `UIViewBase` 或简单 MonoBehaviour，由所属根或所属子面板明确管理；它们不都登记成全局单例。

GamePanel 只组合子面板和管理游戏 UI 的局部导航，不接收所有业务实现。科技查询/命令由科技 Presenter 负责；建筑详情由建筑详情 Presenter 负责。需要调用同级窗口时，经窄导航接口发出请求，禁止持有整个 GamePanel 作为万能服务对象。

跨场景共用的 Settings、Save、通用 Confirm 位于全局根层。只在游戏中有意义的 Pause、科技、人才等属于 GamePanel 子层；共用输入路由仍能知道当前最上层子弹窗，不需要把子弹窗移到别的根下才能获得模态能力。

### 4.3 生命周期必须写成明确契约

| 阶段 | 必须完成的工作 |
| --- | --- |
| Create | 校验序列化引用、注入服务、一次性绑定控件事件；先准备后显示 |
| Open(context) | 接收本次上下文，刷新展示和来源导航，建立本次订阅；禁止沿用失效会话 |
| Focus / Blur | 输入所有权、选中对象和交互状态同步；与实际层级一致 |
| Close | 清理本次上下文/回调、解绑会话订阅、停止刷新和动画；按策略进入缓存 |
| Release | 唯一路径注销长期事件、释放条目池/图片/Addressables 句柄；可重复调用而不重复释放 |

常驻的是 UI 根，不是所有 GamePanel 和所有 ECS 引用。退出 Game 前先停止游戏 UI 输入，关闭模态、撤销显示设置临时更改，解绑会话上下文，再释放 GamePanel 和地图；旧的异步加载结果不得重新打开旧会话面板。加载过程中 LoadingPanel 必须保持可见，最后在恢复和 HUD 初次绑定成功后关闭。

## 7. 引用、Inspector、预览与输入规范

### 7.1 引用规则

1. 固定 UI 对象、文字、按钮、滚动区、模板、布局容器和 CanvasGroup，全部由 Inspector 序列化引用配置。
2. 子视图引用由拥有它的 Prefab 保存；共用根面板之间通过类型化导航访问，不在场景里互相查找。
3. 跨场景的 Camera、World/会话访问和存档/设置服务，由显式组合入口注入。GameHost 的 Awake/OnDestroy 可向已注入的生命周期服务登记/注销自身，不用 Find 获取宿主。
4. 动态列表只从已配置的强类型模板复制；条目自带全部控件引用。实例化对象是正常行为；实例化之后再按名称或组件搜索补绑定不合规。
5. 必需引用为空、指向错误父对象、类型不符、重复根控制器等必须在编辑器预检/构建前报告具体资源、对象、字段。运行入口保留校验；禁止 catch 后自动造控件继续运行。
6. ECS 按稳定 ID 查询业务状态不是查找 UI 配置；已登记的面板字典/条目池取值也不是场景搜索。允许这些明确的数据访问，但不允许把全局 Find 包进一个 Service 后称为“注入”。

为同时满足“按需加载”和“运行时不找组件”，可让每个根面板对应一个 Addressable `UIPanelAsset` 描述资产，其中序列化保存强类型 `UIPanelBase` 预制体根引用。UIConfig 只登记描述资产的地址引用；首次打开才加载该描述及其依赖，再通过 `Instantiate(descriptor.PrefabRoot)` 直接取得类型化实例。这样不需要实例化后 GetComponent，也不必让启动配置直接强引用全部面板、使它们一起加载。描述与实例的资源句柄由 UIManager 管理，编辑器预检类型和唯一根组件。

### 7.2 Odin 中文检查器

所有项目脚本中实际暴露在 Inspector 的字段都要有中文 `[LabelText]`，包括 UI、启动配置、UIConfig、预览配置、嵌套类和可编辑枚举。公开运行时属性若通过 Odin 显示，也要有中文标签。纯内部运行数据不必为了加标签而暴露给 Inspector。

```csharp

[SerializeField, LabelText("地图下拉框"), Required]
```

每个字段单独声明、单独命名和标注；不用 `public Text A, B, C` 配一个模糊标签。Header、Tooltip 的中文不能代替 LabelText。自定义 Drawer 必须尊重 Odin 属性树；验证要检查实际 Inspector 渲染、嵌套字段和枚举，而不只是源码存在属性。

### 7.3 编辑器预览应成为交付要求

每个根面板/重要子面板在 Prefab Mode 中可以显示一个完整的代表性状态，不必先开局、刷资源或进入特定玩法阶段。

| 面板 | 至少提供的预览状态 |
| --- | --- |
| Start / GameStartPop | 菜单、地图缩略图、说明长文本、王朝名和难度草稿 |
| Setting | 音量、分辨率、语言和按键的可读样例；显示确认状态 |

| BuildingDetails | 名称、图标、产出、驻军、岗位、工人档位、作物和异常提示 |
| Technology / Talent / Royal | 节点/卡片、长描述、锁定/选中、头像/家谱关系 |

推荐做法：固定标题、按钮、默认图标直接保存在正式 Prefab；动态数据使用明确的 `UIPreviewProfile`，通过 Editor 预览入口调用与运行时相同的 `Render(viewData)`。普通状态/空态/错误态都使用已配置模板。样例应可在打开 Prefab 时直接看到或通过统一中文“预览状态”选择器切换，不再依赖手工逐层启用对象。

### 7.4 输入和模态

一个 InputRouter 负责指针认领、文本输入焦点和当前最上层模态；一个导航规则处理 Back/Esc。相机控制器、建筑放置和世界点击从 EcsGameView 移出，消费明确的输入许可。

保留现有产品语义：输入框不触发玩法快捷键；UI 起拖不转成地图拖动；设置子页返回来源；显示更改关闭/超时回滚；暂停关闭恢复打开前状态；终局不能普通关闭；破坏性确认执行前校验目标与指纹。用可撤销的输入/暂停占用记录和会话身份管理这些规则，避免各弹窗复制一串布尔判断，也避免旧弹窗关闭后错误恢复新会话。

## 11. 重构完成的统一判定

以下应作为后续实施的完成标准，而不是仅用“代码编译通过”结束重构：

- [ ] UIManager 挂在唯一持久 Canvas 上；四场景往返保持同一个 UI 根和唯一有效 EventSystem。
- [ ] Start/Loading/Setting/Save/Game 等根面板按需加载；设置和存档不再在宿主各维护一套展示逻辑。
- [ ] GameStartPop 属于 StartPanel；科技、建筑详情、人才等属于 GamePanel，子视图拥有自己的职责和局部状态。
- [ ] 脚本、Prefab、挂载对象和命名层级能直接对应；移动后 GUID、字段和事件引用完整。
- [ ] 正式运行路径没有动态查找/补建固定引用；跨场景对象和服务通过显式上下文绑定、解绑。
- [ ] Inspector 可编辑字段、嵌套类型、枚举和自定义绘制全部以 Odin 中文标签正确显示。
- [ ] 每个主要面板有代表性编辑预览；无需启动玩法即可大致看到效果；样例不进入真实会话。
- [ ] Open/Close/Back/并发/取消/失败/清缓存行为一致；Addressables 与事件订阅有可验证的所有权。
- [ ] 暂停、设置回滚、存档权限、模态输入、稳定选择/滚动和终局流程均保留原有产品语义。
